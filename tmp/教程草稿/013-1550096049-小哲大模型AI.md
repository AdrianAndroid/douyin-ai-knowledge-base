### 大模型/LLM

- [2026-09] 所以面试的标准答法是：先讲默认独立推理下各自计算、各自存储，再讲开启前缀缓存后共享公共前缀，最后点出判断本质是看前缀是否对齐、框架有没有开前缀缓存、语义缓存有没有命中
- [2026-06] 采用召回加重排策略，先用Embedding或关键词检索召回Top10，再交给大模型做最终判断
- [2026-06] 大模型如何记住上下文的三种核心策略：滑动窗口、摘要式记忆和基于向量数据库的长期记忆召回
- [2026-09] 搭建人工智能Agent时，应关注模型、指令、工具和状态这四个核心部件，而非仅纠结于框架
- [2026-09] Router+Skill：作者最推荐的一种，核心理念是 “不要让模型想，让模型选”—— 用户输入先经 IntentRouter 做意图识别，直接路由到对应 Skill 执行
- [2026-10] 这条视频是博主小哲讲大模型上下文窗口的科普，核心结论是：上下文窗口够用即可，不是越大越好，关键在于 “精准投喂”
- [2026-06] 比如 “调搜索接口→解析数据→丢给大模型生成回答”，第一步、第二步全在代码里写死
- [2026-07] 大模型微调的7个核心步骤包括明确目标、准备高质量样本、数据清洗和格式化、选择微调路线、开始训练、评估和迭代

- [2026-08] 面试回答需确认问题时间范围，给资料打标签，逐条核验关键断言，能确认的写进结论，冲突和缺口保留

### Agent/智能体

- [2026-06] 严格来说，业界对 Agent 的界定还常涉及自主规划、记忆、多轮工具调用等特征，“决策权归属” 是其中最关键的一条，但并非唯一维度
- [2026-07] Agent 一旦能调工具，就可能真的发邮件、改数据、下订单，所以关键是分清 “哪些能自动化、哪些必须被人拦住”
- [2026-09] 为实现多Agent协作的最终一致性，需要考虑任务语义重叠、部分失败重跑、通信延迟等场景，采用全局任务状态机、子任务幂等和补偿机制等核心逻辑
- [2026-10] 这个视频是博主小哲讲多 Agent 辩论的工程原理，核心结论是：三个 Agent 辩论后投票，默认并不能保证答对，关键要看论点是否独立、是否引入新证据、收敛依据是票数还是证据强度
- [2026-06] 如何提高Agent技能命中率的四个方法：1. 优化技能描述，写清触发场景
- [2026-09] 最后用二次校验 Agent 加规则引擎拦截错误
- [2026-10] 他最后强调的一句话挺关键：与其给整个系统贴一个 “Agent” 或 “Workflow” 的标签，不如想清楚每一部分的决策权该放在哪里—— 确定性流程牢牢管住，需要探索的范围划清楚
- [2026-10] 运行特性与取舍 本地 Tools 链路短、无网络开销、响应最快，但和 Agent 强耦合，加工具要改代码重启，第三方程序用不了，适合功能简单、改动极少的小工具

### 其他要点

- [2026-07] 面试答题的推荐结构是：先点明 “相关性≠事实支持”，再讲文档解析按条款保留上下文，接着讲重排、极性识别与引用校验，最后讲证据不足必须拒答或转人工
- [2026-08] 为避免这些问题，应采用滑动窗口和关键信息摘要，将最相关的上下文放在最前面和最后面
- [2026-09] 想继续聊的话，这套方案里最容易踩坑的其实是第三层的 chunk 上下文注入 —— 具体怎么写那段说明文字、多长合适，作者只给了例子没展开，可以顺着这个往下拆
- [2026-10] 如果两个 Agent 的初始错误来自同一份脏检索结果，它们会在辩论中互相引用对方的错误论据，形成错误证据的闭环强化，越辩越自信，最后把少数正确的一方压垮
- [2026-10] 想再往下聊的话，EWC 里那个 Fisher 信息矩阵具体怎么算、为什么它近似 “参数重要性”，是这套方法最容易被追问的点
- [2026-11] 四层各自的落地要点 状态区把关键事实抽成结构化 JSON（如 “零停机、副本延迟小于 5 秒”“第 12 轮否决了哈希分区”），不经模型加工，所以零语义损失，是百轮后不矛盾的底牌
- [2026-11] 500 的状态表不能省，因为摘要本质是另一个模型做的有损压缩，轮次越多语义损耗和幻觉继承越严重，只有结构化状态表能做到零损失
- [2026-06] 核心答案是建立立体指标体系，结合代码断言、环境状态比对与模型裁判进行自动化评估，同时规避错误传递、结果不确定性和裁判幻觉
- [2026-06] SFT、RLHF和DPO是三种不同的训练方法，用于使模型更符合人类期望
- [2026-06] 问题本质是考察Embedding模型如何学会拉近正例、推远负例，关键在于负样本的梯度信息量和标签真实性
