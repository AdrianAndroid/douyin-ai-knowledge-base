## 1. 核心认知（先看这一节）

- **核心结论是：光调大最大轮次没用，得把 “规划” 和 “执行” 拆成两个循环，再加漂移诊断**（2026-10）
- **严格来说，业界对 Agent 的界定还常涉及自主规划、记忆、多轮工具调用等特征，“决策权归属” 是其中最关键的一条，但并非唯一维度**（2026-06）
- **大模型如何记住上下文的三种核心策略：滑动窗口、摘要式记忆和基于向量数据库的长期记忆召回**（2026-06）
- **Agent 一旦能调工具，就可能真的发邮件、改数据、下订单，所以关键是分清 “哪些能自动化、哪些必须被人拦住”**（2026-07）
- **这条视频是博主小哲讲大模型上下文窗口的科普，核心结论是：上下文窗口够用即可，不是越大越好，关键在于 “精准投喂”**（2026-10）
- **核心设计：分层加载 第一层只存技能简介和适用场景，几乎不占内存**（2026-11）
- **四层各自的落地要点 状态区把关键事实抽成结构化 JSON（如 “零停机、副本延迟小于 5 秒”“第 12 轮否决了哈希分区”），不经模型加工，所以零语义损失，是百轮后不矛盾的底牌**（2026-11）
- **问题本质是考察Embedding模型如何学会拉近正例、推远负例，关键在于负样本的梯度信息量和标签真实性**（2026-06）
- **作者的核心答案是：Transformer 同时解决了长距离依赖、并行计算和规模化训练三个关键问题**（2026-06）
- **扩展性好：结构统一，文本切成词元、图片切成图像块、音频切成声学片段，都能交给注意力机制处理，所以多模态模型也都在往这个方向靠，它像一个通用计算框架**（2026-06）
- **面试回答需解释不用RAG原因、agentic search方法、短板和兜底策略，展示对落地逻辑的理解**（2026-07）
- **幂等键需绑定用户、会话、任务、工具名和关键参数，形成唯一标识**（2026-07）

## 2. 实操方法（照着做）

1. 面试的标准答法是：先讲默认独立推理下各自计算、各自存储，再讲开启前缀缓存后共享公共前缀，最后点出判断本质是看前缀是否对齐、框架有没有开前缀缓存、语义缓存有没有命中（2026-09）
2. 建议记录结构化事件、父子步骤和输入输出断言，沿依赖图找到第一处偏差（2026-08）
3. 作者先抛出的面试式追问 用户第一轮说 “查上海周三高铁票”，第二轮 “顺便订当天酒店”，第三轮 “到了后约客户会议”（2026-09）
4. 采用召回加重排策略，先用Embedding或关键词检索召回Top10，再交给大模型做最终判断（2026-06）
5. 1. 匹配习惯：贴合工程师查代码的真实流程，先搜索关键词、再找对应目录、最后读取目标文件（2026-06）
6. PDF RAG处理图片和表格的五个关键步骤：文本解析、版面还原、表格结构化、图片理解和证据引用（2026-07）
7. 详细讲解了表格解析、计算边界、答案引用和兜底策略四个关键步骤，以及面试回答模板和验收指标（2026-08）
8. 搭建人工智能Agent时，应关注模型、指令、工具和状态这四个核心部件，而非仅纠结于框架（2026-09）
9. 为实现多Agent协作的最终一致性，需要考虑任务语义重叠、部分失败重跑、通信延迟等场景，采用全局任务状态机、子任务幂等和补偿机制等核心逻辑（2026-09）
10. 比如 “调搜索接口→解析数据→丢给大模型生成回答”，第一步、第二步全在代码里写死（2026-06）
11. 大模型微调的7个核心步骤包括明确目标、准备高质量样本、数据清洗和格式化、选择微调路线、开始训练、评估和迭代（2026-07）
12. 他最后留了个互动问题：AI 回答 “最近一周” 时，你希望它直接给结论，还是先说明具体日期范围（2026-07）
13. 面试答题的推荐结构是：先点明 “相关性≠事实支持”，再讲文档解析按条款保留上下文，接着讲重排、极性识别与引用校验，最后讲证据不足必须拒答或转人工（2026-07）
14. 应对结果互相依赖的追问，先串共享前置步骤，再并行独立分支，最后统一合并（2026-08）

## 3. 常见误区与坑

- ✗ 题目考察Trace和步骤依赖，第三步错误导致后面九步在错误前提上执行（2026-08）
- ✗ Router+Skill：作者最推荐的一种，核心理念是 “不要让模型想，让模型选”—— 用户输入先经 IntentRouter 做意图识别，直接路由到对应 Skill 执行（2026-09）
- ✗ 这个视频是博主小哲讲多 Agent 辩论的工程原理，核心结论是：三个 Agent 辩论后投票，默认并不能保证答对，关键要看论点是否独立、是否引入新证据、收敛依据是票数还是证据强度（2026-10）
- ✗ 视频最后留了个思考题：如果有个几乎每次对话都会用到的高频基础技能，还要不要严格走完整套按需加载流程（2026-06）
- ✗ 为避免这些问题，应采用滑动窗口和关键信息摘要，将最相关的上下文放在最前面和最后面（2026-08）
- ✗ 想继续聊的话，这套方案里最容易踩坑的其实是第三层的 chunk 上下文注入 —— 具体怎么写那段说明文字、多长合适，作者只给了例子没展开，可以顺着这个往下拆（2026-09）
- ✗ 最后用二次校验 Agent 加规则引擎拦截错误（2026-09）
- ✗ 如果两个 Agent 的初始错误来自同一份脏检索结果，它们会在辩论中互相引用对方的错误论据，形成错误证据的闭环强化，越辩越自信，最后把少数正确的一方压垮（2026-10）
- ✗ 500 的状态表不能省，因为摘要本质是另一个模型做的有损压缩，轮次越多语义损耗和幻觉继承越严重，只有结构化状态表能做到零损失（2026-11）
- ✗ 核心答案是建立立体指标体系，结合代码断言、环境状态比对与模型裁判进行自动化评估，同时规避错误传递、结果不确定性和裁判幻觉（2026-06）

## 4. 关键零散结论

- 最终产出不是平均分，而是退化清单、不可接受差异、可接受变化和建议路由，最好能落到 “允许上线、限制场景上线、改 prompt、改解析、回滚工具 schema” 这类可执行结论
- 如何提高Agent技能命中率的四个方法：1. 优化技能描述，写清触发场景
- 作者强调的重点是40 多个代码版本：不给最终成品，而是每节课对应一个版本，逐步迭代，能看清每一步为什么这样处理、加了什么能力、改了哪些代码
- 运行特性与取舍 本地 Tools 链路短、无网络开销、响应最快，但和 Agent 强耦合，加工具要改代码重启，第三方程序用不了，适合功能简单、改动极少的小工具
- 想再往下聊的话，EWC 里那个 Fisher 信息矩阵具体怎么算、为什么它近似 “参数重要性”，是这套方法最容易被追问的点

- 智能体意图识别的面试问题解答，强调传统方法的局限性，提出并行化意图识别方案，通过规则、上下文、工具和安全四个维度的专家同时评估，提高准确率、速度和安全性
- 用户说 “最近” 时，系统最好追问或明确说明范围，而不是默默替用户决定
