这是一个介绍 nufhus-mcp 开源项目的短视频，作者是「AI 实战实验室」。核心讲的是：怎么让 AI 直接控制电脑桌面和浏览器，替人操作鼠标键盘、截图、跑本地任务。

它做了什么

项目用 Rust 写成，提供 38 个自动化工具，通过 MCP（Model Context Protocol，模型上下文协议）把电脑操作能力交给 AI 代理。视频里演示了用单行 JSON 指令获取窗口并截图。识别屏幕位置有两条路：内置本地 OCR，或外接视觉模型来读屏幕坐标。作者认为它适合需要让 AI 代理执行本地日常任务的开发者。

作者提到的限制

Linux 用户：桌面控制功能会受限；
最新版谷歌浏览器：调试端口无法直接读取默认配置；
从画面里的 Prerequisites 看，需要 Rust 工具链（stable）和 Cargo 从源码构建，浏览器工具还要求 Chrome 或 Edge。

评论区在聊什么

讨论集中在和 Computer Use 类方案的对比上。有评论指出，Computer Use 遇到 APIKey 这类敏感操作会停下来让用户自己处理；另一条高赞评论则把差异概括成 “能不能让 AI 少要 APIKey”，也就是自动化到底能深入到哪一步。这属于网友经验补充，不是作者原话。

一个容易误解的点

“无守护进程” 不等于 “无风险”。它省掉的是常驻后台服务，但 AI 一旦拿到鼠标键盘和截图的权限，误操作的影响是实打实的。作者说 “安全”，更多指架构上不常驻、本地运行；实际用起来，敏感操作还是建议加人工确认。
