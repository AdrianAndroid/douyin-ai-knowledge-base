这条视频来自 AI 产品千媚，用 “做一个智能客服” 的案例，把大模型（LLM）一步步进化成智能体（Agent）的路径讲清楚了：Prompt → RAG → Context → Tool → Orchestration → Memory，每加一层，就补上一个具体短板。

第一层：Prompt 解决 “人格漂移” 纯大模型套上去做客服，客户问 “我的订单为什么还没发货”，它可能讲物流发展史、安抚情绪，甚至编个 “当地信号不好” 的理由，每次回答都像开盲盒。作者把这种状态叫人格漂移，原因是模型默认目标是生成通用、合理的自然语言，而不是业务上正确的答案。提示词相当于一份岗位说明书：告诉它你是电商客服、公司做什么、政策是什么、回答要守什么规则。

第二层：RAG 解决知识固定 提示词长度有限、内容固定，产品多、政策又常变，不可能天天改。于是外挂一个知识库，把产品说明、退换货政策、QA 都放进去，回答前先检索再作答。作者认为这样知识能随时更新、可无限扩展，也能缓解幻觉。

第三层：Context 解决 “断片” 客户刚问完 iPhone，接着问 “最便宜多少钱”，客服却不知道在说哪款 —— 因为大模型本身没有记忆，每次对话都是独立的。把上下文一起喂进去，它才能接着聊。

第四层：Tool 解决 “只会说不会做” 查订单状态、查物流，光靠语言模型做不到。通过 Function Calling 给它接上工具，作者形容为 “给大模型安上手和脚”，它才从会答题变成能干活。

第五层：Orchestration 与 Memory 有了 “大脑” 和 “手”，还要协调，业内主流编排模式包括顺序路由、并行 planning 和多智能体编排；再加上短期与长期记忆，塞进上下文，服务才能个性化、连贯。

作者的核心判断：从大模型到智能体，本质是 “从只会说到能做事” 的跨越，是从玩具到工具再到生产力的质变。作为产品经理不必卷底层算法，真正的战场在智能体的编排与设计。

一个值得留意的边界：RAG 能显著降低幻觉，但并不能完全消除 —— 检索到错误或过时资料时，模型仍会照着错的内容回答，所以知识库的维护和答案溯源同样关键。
