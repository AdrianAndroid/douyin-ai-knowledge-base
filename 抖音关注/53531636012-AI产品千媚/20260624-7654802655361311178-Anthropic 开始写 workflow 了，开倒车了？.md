这条视频是 AI 产品博主「AI 产品千媚」对 Anthropic 推出 dynamic workflow 的解读：她认为这并非 “开倒车”，而是用代码替代模型 “一个脑子扛全队” 的瓶颈，专门解决长任务翻车的问题。

核心问题：长任务三种翻车方式 作者归纳了 Claude 做长任务时的三类失败：一是 “白烂”，让读 50 篇报告，读到 30 多篇就说 “干完了”；二是 “跑偏”，多轮拉扯中不断做摘要腾上下文，最初需求被磨没；三是 “自我感觉良好”，让它自查会偏袒自己，又当裁判又当运动员。她认为病根是只有一个脑子，所有资料和活都堆在同一上下文里，一长一多就装不下。

四种 “找帮手” 方式的差别

Subagent：跑腿的，10 个小弟各读 5 篇，只回摘要，原文不刷爆主对话。
Skill：操作手册，提前把 SOP 写死，但干活时信息照样堆回 Agent 上下文。
Agent team：真正的项目组，一个组长加几个长期在线平级队友，共享任务清单、能互发消息，但统筹仍由组长一回合一回合判断。
Workflow：计划攥在代码里，循环、分支、先后顺序全写死在脚本；中间结果存进变量，一个字不塞进模型脑子。

前三种本质是给那个会爆的脑子换几种使唤帮手的姿势，脑子本身没变；workflow 则把脑子换成不会累、不会忘的代码，所以能一口气调度几十上百个 agent。作者也点出静态流程的局限：流程是在干的过程中长出来的，调研要读几篇、会不会中途掉头，事先定不了。Coze、Dify 是静态的，dynamic 让 AI 边干边画。

怎么用、什么时候别用 在 Claude Code 里说人话，或用 /ultracode，让它 “用 workflow 帮我把这赛道调研透”，它会自己写脚本自己跑；也内置了现成的 /deepresearch。作者强调难点在 “什么时候千万别用”：它烧的 token 是平时好几倍，上百个 agent 同时跑每个都在烧。Anthropic 也建议能上静态流程就先上，更稳、更可控、更便宜、可追查；只有提前画不出图的活，比如扫整个代码库、大重构、会中途掉头的深度调研，才是 dynamic 的主场。

结尾她的判断是：Anthropic 不是退回旧世界，而是把 “画流程图” 这件原本只能人干的事接了过去 —— 过去图是人画的，现在图是它自己画的。评论区里有人问动画怎么做，作者回复用的是 Claude design；也有评论留下 “Stability is first”，呼应了 “稳定优先” 的取舍。
