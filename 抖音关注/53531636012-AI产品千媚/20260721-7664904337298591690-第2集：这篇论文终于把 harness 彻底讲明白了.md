七层分类法

论文把 harness 从 “模型之外的一切” 这种排除式定义，升级为独立系统层，并拆成七层：

前四层（让 agent 能干活）：执行环境（沙盒隔离，别让 agent 直接在生产服务器上运行）、工具接口（告诉 agent 有哪些工具、怎么调）、上下文管理（工作记忆，决定每一步看什么、怎么压缩历史）、生命周期与编排（控制流、多 agent 谁先谁后）。
后三层（安全可控的控制平面）：观察层（耗时、调用、花费、哪步出错）、可验证层（做完了对不对、错在哪、怎么防复发）、治理层（权限、授权、数据访问、责任归属）。

博主特别强调，论文把可观察性和治理单独拎出来，而 LangChain 类框架里这两块原本塞在生命周期中，很不起眼。她引用 LangChain 2026 年调查数据：89% 的团队用了可观察性工具，但只有 52.4% 跑了离线评估 ——“看得到” 和 “能判断对错” 之间的裂缝，正是很多 agent 在生产环境悄悄翻车的原因。

实验数据

论文用三组独立实验支撑 harness 的增益：只改工具调用格式、模型不动，15 个模型平均涨 10 分；对 GPT-5.2 只做提示词重构、中间件上下文、加验证钩子三件事，分数从 52.8 升到 66.5；自动化搜索最优 harness 配置跑到 76.4%，超过所有人工调优方案。对比模型自身迭代通常只带来 2—4 个百分点提升，harness 层面的增益是模型进步的三到五倍。

生态图谱与选型建议

论文把 170 个开源项目映射到七层上，是目前最大规模的 harness 生态图谱。结论是前四层开源方案密集、可直接选用；可观察性、治理、上下文记忆开源项目少，多集中在商业平台。因此博主给出两条判断：做产品选型时前四层挑开源、后几层自建或付费；找创新方向时，生态最薄但生产最痛的可观察性和治理就是机会所在。

评论区高赞把 harness 理解为 “一种实用优化思想”，并认为模型正逐渐把许多原本靠 harness 实现的能力内化。这属于网友观点，不是论文结论，也和视频 “harness 增益显著” 的判断形成对照，值得留意。
