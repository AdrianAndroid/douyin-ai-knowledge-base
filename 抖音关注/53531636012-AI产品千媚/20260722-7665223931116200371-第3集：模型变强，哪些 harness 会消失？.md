核心观点：模型越强，Agent 越需要 Harness。 作者（AI 产品千媚）针对 “模型变强后，Harness 迟早被吞掉” 的说法，提出自己的判断：模型变强不会让问题消失，只会让问题升级。

为什么需求反而变多 2023 年的 Agent 只做单轮回答、简单工具调用，Harness 很薄 —— 一个 while 循环、一个提示词模板、一张工具分发表就够。到 2026 年，Agent 要跑几小时长任务、操作真实文件系统、调用几十个外部 API 与其他 Agent 协作，在生产环境端到端干活。这些任务恰恰是因为模型变强才敢交给它，也随之带来上下文腐烂、状态漂移、权限越界、成本失控等新问题。作者用类比说明：CPU 变强后，浮点运算、手动内存分页等补偿性工作被硬件吞掉，但操作系统没消失，反而演化出进程隔离、权限管理、容器化、安全沙盒，今天的 Linux 内核比 30 年前复杂得多。

三类 Harness 的不同命运

类别	具体组件	理由
会消失	上下文压缩与窗口管理、单 Agent 循环里的 “保姆逻辑”（退出 / 强制继续）、工具描述精细打磨、Web 搜索作知识补丁	本质是补偿模型架构局限、不知何时该停、结构化理解弱、训练数据有截止日期；模型进步后变多余。作者举 Anthropic 案例：某模型有用的上下文重置机制在更强模型上完全多余，移除后成本降、质量不变
会变形	沙盒与执行环境、验证与评估、记忆、多 Agent 编排	存在理由混合。沙盒从 “铁笼子” 变 “分级门禁”，低风险自动放行；验证从全检变抽检、实时拦截变事后审计；短期记忆被更大窗口解决，长期记忆因存储架构刚需永存；单 Agent 越强，多 Agent 协作规模越大，编排问题反而加剧
永久存在	可观察性、治理、文件系统与持久化存储	与模型能力无关，是生产系统的刚性需求：花了多少钱、走了哪条路、谁授权、出事怎么追溯。作者强调 “一个没有治理的 agent 系统不是技术问题，是法律问题了”

结论：未来 Harness 是更薄的数据平面，更厚的控制平面—— 让 Agent 干活的部分持续变薄，让它安全可控干活的部分持续变厚。Harness 要当活系统运营，定期审计、移除不再产生价值的干预，否则会背上越来越重的技术债。
