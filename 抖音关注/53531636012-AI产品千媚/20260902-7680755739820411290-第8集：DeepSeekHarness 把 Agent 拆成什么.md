介绍 DeepSeek Harness
Agent 的本质是 “Model + Harness”，如果把模型看作负责思考的员工，Harness 就是员工所在的办公室，决定了工具使用、权限控制和办事流程。市面上成熟的 Agent 产品通常提供一间 “装好的办公室”，内部的系统分配和模块替换往往由产品提前定死。 而 DeepSeek Harness 则提供了一套完全不同的机制，它不给你现成的办公室，而是让你自己 “盖一间”。在这套体系下，模型接入、工具、会话、存储甚至最基础的 Agent Loop 都可以被灵活拆换。这种极致的解耦设计，构成了它与传统 Harness 最核心的区别。

理解一切皆为插件
DeepSeek Harness 提出了 “everything is a plugin” 的口号。在普通的插件体系中，通常会有一个固定不变的核心，只能在上面增加功能；但在 DeepSeek Harness 里，连核心的运行方式本身都是由插件提供的。 从模型适配器、工具、会话记录，到沙盘调度、UI 界面以及 Agent Loop，全部都被抽象为插件。这种设计使得整个运行环境具备了极高的可塑性，真正实现了底层架构的模块化与插拔式替换。

装配 Host 运行环境
DeepSeek Harness 的装配分为两层，第一层是装配 Host，即搭建整个进程共享的公共运行环境，包含会话、模型、工具、授权、存储等基础服务。这一过程主要依靠 Profile、Bundle、Patch 三者配合，并最终由 Cordis 拼接运行：

Profile：相当于一套 Host 的组合方案或装修清单，决定系统以何种形态启动（如带浏览器界面的 web 模式或适合自动化脚本的 headless 模式），并定义可用的模型、工具和安全规则。
Bundle：一组可复用的能力包，将经常一起使用的插件和配置打包（如查资料或代码审查的成套设备），避免每次新建 Agent 时重复对接十几个插件。
Patch：相当于配置变更单，用于记录临时的小改动（如换个模型或关掉某个工具），无需重新组装整个 Bundle。 这些配置层层叠加形成一棵完整的插件树，再由 Cordis 负责处理插件间的依赖关系与生命周期，将其真正启动并运行起来。

03:51
解析 Cordis 组合机制
Cordis 背后的核心理念是 “时空的可组合性”，它解决了插件如何配合启动，以及如何干净地卸载和替换的问题。

空间可组合性：解决插件树中谁依赖谁的问题。插件通过 provide 将服务登记到当前的上下文中（Context），而 Agent Loop 则通过 inject 提前声明所需的服务。Cordis 会检查上下文，只有当所有依赖的服务齐全后才会允许插件行动，从而实现了类似 “标准插座” 的接口依赖，插件无需关心服务具体由谁提供。
时间可组合性：解决插件如何干净退出的问题。Cordis 为每个插件建立了名为 Fiber 的生命周期记录，并将插件对外部环境的改变（如注册工具、启动监听）记录为 Effect。当插件被卸载时，Cordis 会自动执行对应 Dispose 操作，彻底清除旧插件留下的痕迹，确保新插件能干净地替换进来。

装配 Agent 专属能力
在公共的 Host 环境搭建完成后，系统进入第二层装配，即为具体的 Agent 分配专属能力。这相当于给员工安排具体的岗位，决定其拥有的工具和职责。 官方目前提供了四种不同的 Agent Preset 模式供选择：

Standard：标准模式，提供全面的文件编辑、Shell 搜索、技能规划、子 Agent 等工作流能力。
PTC：拥有 Standard 的大部分能力，但工具会通过代码模型提供给大模型，允许模型将多次工具调用编排成一段程序，从而减少一问一答的来回交互，适合批量操作任务。
Minimal：极简模式，仅保留最基础的持久化能力和文件编辑器，提示词也更加简单，适合用来纯粹观察大模型在极少外部辅助下的原生能力边界。
Creator：相当于办公室的设计师岗，除了 Standard 的能力外，还可以检查当前的运行环境、试验插件，甚至制作新的 Agent Preset。

运行真实 Agent 任务
当 Host 和 Agent 能力都装配完毕后，系统便可以开始处理真实的任务流转。 用户的消息首先进入 Agent 的 Inbox（收件箱），唤起 Agent Loop 并开启一个 Turn（代表从任务交付到完成或停止的完整生命周期）。在一个 Turn 中，包含了多个 Step（每次模型请求及其触发的工具执行即为一个 Step）。 由于插件和权限可能动态变化，Agent 会在每次请求模型前重新组装最新的 System Prompt 和工具列表。输入经过插件的前置检查后，系统将历史消息写入 Session Log，并向大模型发起请求。大模型通过流式返回内容并决定是否调用工具，执行结果会被写回日志并再次送入模型。这个循环不断迭代，直到模型不再调用工具且 Inbox 没有新输入时，系统经过最终检查后将该 Turn 标记为结束。

总结产品视角与建议
随着大模型能力的同质化，未来 Agent 的核心竞争力差距将逐渐转移到 Harness 层面。DeepSeek Harness 试图通过开放的插件框架构建一个完整的生态，降低开发者对单一平台的锁定，甚至探索让 Agent 参与改造自身的可能性。 然而，从产品视角客观来看，它目前仍处于非常早期的初级阶段，官方也提示后续可能会存在不兼容旧版本的重构。虽然其架构设计极具前瞻性，但目前多数插件的改造还停留在较浅的层面。因此，建议开发者可以将其用于研究、学习和快速搭建原型，但在直接应用于生产环境时仍需保持谨慎。
