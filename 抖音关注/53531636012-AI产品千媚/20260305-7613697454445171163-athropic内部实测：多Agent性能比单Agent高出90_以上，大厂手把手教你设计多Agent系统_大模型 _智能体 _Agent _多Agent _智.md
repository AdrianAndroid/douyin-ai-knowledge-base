这条视频讲的是 Anthropic 多智能体（Multi-Agent）研究系统的设计思路：作者引用 Anthropic 的实测结论 —— 多 Agent 比单 Agent 性能高出 90.2%，并用 “老板带团队” 的比喻拆解架构，最后给出五条工程避坑清单。

为什么单 Agent 不够用 作者用 “调研 2025 年全球 AI 芯片市场份额” 举例：单 Agent 要读 200 份财报、50 篇研报，会碰到三个问题 —— 注意力稀释（读到第 150 份就忘了前面数据）、串行效率低（一次只能搜一个、读一个）、路径漂移（边干活边做计划，容易钻进细节忘了目标）。所以作者认为单纯堆模型能力没用，解法是 “把一个人变成一个团队”。

Orchestrator–Subagent 架构

Lead Agent（老板）：只做战略决策，不亲自读网页，负责制定计划、统筹全局、分配任务，并把计划写进 memory 防止遗忘。
Subagent（员工）：每人只专注一个具体任务（提财务数据、查政策、比产品），不操心全局，只求把自己那块做快做准。
运行方式不是固定流程，而是循环：观察已有数据和反馈 → 定位问题 → 决策（继续深挖还是换路子）→ 下发指令给 Subagent，直到资料足够出报告。

LeadResearcher 案例 用户提需求 → 主 Agent 生成初始研究大纲并存入 memory → 按大纲创建多个子 Agent 全网搜索 → 每个 Subagent 返回前先自我反思 “搜到的东西好不好、对老板有用吗” → 老板汇总后交给 Citation Agent，它不写内容，只核查报告里每句话能否在原文找到证据。

五条避坑指南（跨越最后一公里）

上下文截断导致 “失忆”：子 Agent 信息汇总易撑爆 token，解法是把核心计划存进外部 memory。
工具调用失败：Anthropic 发现多半不是模型问题，而是人手写的工具说明书有歧义；解法是用 Tool Testing Agent 反复试错、重写说明书，这一项让整体耗时降低约 40%；另外在提示词里强制 “交错思考”，调用前说明理由和预期，调用后评估是否符合预期。
路径随机性导致评估失灵：同样查询跑两次路径不同，传统准确率失效；解法是引入高阶模型当裁判打分，加上 “小样本快跑”—— 早期用 20 个代表性真实案例就能揪出约 80% 的问题。
任务规模失控：简单问题可能盲目开几十个 Subagent 让 token 指数级增长；解法是在提示词里嵌入规模自适应规则，简单事实类 3–10 次工具调用，复杂研究才启用 10 个以上 Subagent。
信息归因与可信度：信息碎片化会让结论对不上原始来源，靠 Citation Agent 专门做引用核查。
