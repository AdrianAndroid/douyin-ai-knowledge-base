这是一期信息源筛选与阅读方法的分享，作者是「AI 产品千媚」。她的核心观点是：学 AI 时，选对一手信息源会慢慢拉开判断力差距，而如果只挑一个重点跟进，她推荐 Anthropic 官网。

她为什么选 Anthropic 作者认为，Anthropic 不只发布模型，更愿意把一线团队的实践拆开讲：agent 怎么搭、为什么这样设计、遇到什么问题、怎么解决。多看这些，能帮人建立 “AI native” 的思维方式。

官网分两个梯队，三个重点看

Claude Platform：她每天都会打开。内容分四类 ——agents（智能体构建与应用）、Claude Code（开发方法与最佳实践）、企业应用案例、产品公告。产品经理尤其该多看 agents 和企业应用，因为 “看过足够多的前沿案例，脑子里才会有更多选择”。
Anthropic Engineering：在 research 导航下，偏工程方法论。她点名了几篇必读：
《Building effective agents》：讲清 workflow 与 Agent 的区别、常见架构模式，以及什么任务适合固定流程、什么时候该让模型自主决策；
《How we built our multi-agent research system》：拆解 Claude Research 从原型到生产的架构、评测与工程经验，客观评估多 Agent 的收益和风险；
《Effective context engineering for AI agents》：从 prompt engineering 推进到上下文组织方式；
长任务 harness 设计与 Agent 评测（Evals）两篇，串起来就是一条完整的 Agent 架构设计线。
她也提到遗憾：这个栏目从 5 月起就没再更新。
Claude Academy：有系统课程（如 Claude Code 101）、操作教程和按岗位整理的应用案例，适合 “已经在用 AI 但不知道还能怎么用” 的人。

第二梯队是 Newsroom（公司动向、模型发布、政策立场）和 Toolbook（工具调用、评测、代码示例，开发者可提到第一梯队）。

她的英文阅读方法 先筛选再精读：用 Chrome 里已有的 Gemini 入口直接辅助阅读，不用复制粘贴。常用提示词是四个问题 —— 这篇文章解决了什么问题？核心观点和方法是什么？哪些地方值得重点阅读？对产品设计有什么启发？判断值得深入后，再让 Gemini 翻译，对照原文重点看架构图、具体案例，以及作者讲失败和限制的部分。
