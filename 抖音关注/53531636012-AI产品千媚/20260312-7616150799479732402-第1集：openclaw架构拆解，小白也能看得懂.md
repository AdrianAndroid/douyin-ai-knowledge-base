这条视频是 AI 产品千媚 对 OpenClaw 的架构拆解，全程只讲原理、不讲安装。作者的核心结论是：OpenClaw 并没有发明新技术，它的爆火来自把已有能力组装成一套本地化、高度解耦的 Agent 平台。

整体架构：以 Gateway 为中心

OpenClaw 本质是围绕一个跑在电脑本地的网关程序 Gateway 搭建的智能体平台。Gateway 相当于调度中心，作者用公交调度打比方：人多车多，需要有人管 “谁去哪个方向、坐哪趟车”。它负责路由规划、状态管理和消息分发，一头接微信、飞书、Telegram 等聊天工具，把各渠道消息统一格式；另一头接 Agent Runtime。消息量大时先入消息队列排队，再逐条处理。

一条指令的完整链路

用户发消息，Gateway 承接并识别需求，分发给对应的 Agent Runtime。
Context Builder 先去记忆系统检索历史，再和当前消息拼成上下文，生成 prompt 交给大模型。
记忆文件包括内置的 Agent Soul 的 MD 文件、日志，以及向量数据库里的内容。
大模型理解意图、推理；纯聊天解决不了就调用工具和技能，工具结果回传给模型，由模型生成最终回复。
回复返回用户前，这一轮对话细节会被写回记忆，下次遇到同类问题更高效。
最后由 Gateway 封装返回。

作者把这条链路概括为典型的 ReAct 模式：思考推理 → 制定计划 → 判断是否需要外部数据 → 发起工具调用 → 根据结果决定继续还是终止。

三个优势

多渠道接入：不用守在电脑或某个 App 前，发条消息就能干活。
定时任务：通过 Cron 和 Heartbeat 机制实现定时触发，AI 能在没人盯着时主动做事，而不只是被动响应。
记忆本地化持久化：普通智能体的记忆存在云端，看不见也改不了，容易反复提旧事；本地存储可以随意增删改查，也不怕丢。
