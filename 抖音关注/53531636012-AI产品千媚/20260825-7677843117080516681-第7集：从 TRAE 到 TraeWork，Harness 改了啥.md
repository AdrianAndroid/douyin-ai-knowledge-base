核心结论：agent loop 本身没变，仍是 “理解任务→选工具→执行→接收结果→再判断”；变的是 loop 外围的 Harness，TraeWork 补了四层秩序。

演示任务：把需求文档、用户反馈表、竞品分析 PDF、历史周报和数据截图交给 TraeWork，让它找出本季度最关键的问题、分析原因，并生成可直接汇报的复盘报告。这类任务可能持续几小时、反复修改、调用多个工具，因此引出四个模块：

Workspace：作者把它比作 “人和 agent 共用的项目书桌”。task 记录目标、计划和进度，session 保存交互历史和中断后继续的线索，files 放原始材料，分析结果也留在桌上。代码场景有代码仓库天然充当工作现场，办公场景的 PDF、表格、图片关系松散，所以必须把 workspace 做成显性产品对象。
Workspace Search 与 Context Resolver：前者负责 “找材料”，面向整个项目做混合检索（文档解析、切分、向量、索引合并与重排）；后者负责 “选材料”，结合当前问题、task、session、memory 和上一轮工具结果，组织成本轮真正给模型的 working context。每次模型请求由 instruction、tool definition、working context 三类信息构成。
工具执行与权限治理：简单统计直接调工具读表；反馈、竞品、版本完成情况这类可拆分的活，可派 sub agent 并行处理再汇总。动作执行前要过权限层，决定自动放行、询问用户还是拒绝；工具返回的 observation 回流到下一轮。
Artifacts：最终产出 HTML 报告、图表或 PPT。作者强调它不是一种文件格式，而是被产品持续管理、可预览、审阅、反馈和二次编辑的交付对象，还会存回 workspace 成为下一项任务的材料。

作者最后判断：Trae 从 coding 走向 work，真正的野心是 “把代码仓库天然提供的秩序重新造给每一种知识工作”；能否成立不只看模型聪明程度，更看 workspace 能不能接住材料、状态、规则和成果，让 agent 下次回来不用一切重来。评论区有观众问视频里用的模型是不是 GML，作者回复是 “GPT5.6”，这属于评论区的补充说法，视频正文未涉及。
