核心主线：从 "会说话" 到 "能办事"

大模型（底座）：像读过海量书的聪明人，能理解问题、用自然语言回答。但直接拿来做客服会 "人格漂移"—— 问 "订单为什么没发货"，它可能讲物流发展史、可能安慰你、甚至编出不存在的赔付规则。原因是纯大模型的目标是生成 "最通顺合理" 的话，不是 "最业务正确" 的答案。
Prompt（岗位说明书）：告诉它扮演电商客服、遵守哪些公司政策、按什么规则回答，把天马行空的通用模型 "驯化" 成懂规矩的业务能手。
RAG（外挂硬盘 / 图书管理员）：模型知识固定、业务天天变、数据塞不进提示词。RAG 分三步 —— 检索（定位退货细则文档）、增强（把文档交给模型）、生成（按文档作答）。带来三点：知识容量不受限、规则更新只需换文档、回答有据可查。作者的原话是 "大模型负责会说话，RAG 负责说真话"。
上下文（Context）：模型本身没有记忆，每次对话都是 "初次见面"。要记录上下文，更要学会 "修剪"—— 记事本长度有限，怎么在有限字数里留住关键信息，就是上下文工程。
工具调用（Function Calling）：这是大模型和 Agent 的分水岭—— 能不能替你把事办了。查订单、退款、改地址各是一个可执行功能，模型判断该调哪个，系统调接口、返回结果。
编排（Orchestration）：协调大脑和双手。业界六种主流模式，从最可控到最灵活依次是顺序、条件、路由、Planner 计划、ReAct、多 Agent 协作。作者最推崇 ReAct（Reason 分析拆解 → Act 调工具执行 → Observe 看结果再调整），以 "用户要退款" 为例：第一轮查订单状态确认可退，第二轮创建退货单并调接口，最后同步结论。
Memory（记忆）：短期记忆即上下文，管这一轮不断片；长期记忆跨会话记住偏好、性格，本质是 "AI 时代的用户画像"，让 Agent 从工具变成数字伙伴。
全景图：顶层大脑（大模型，负责理解推理决策）+ 底层双手（工具）+ 中间编排层（Planning 拆任务、Memory 记你是谁、上下文工程动态组装信息喂给模型）。

作者的核心观点：产品经理不用卷底层算法，真正的战场在架构的编排与设计上；很多人说 "Agent 产品经理其实就是上下文产品经理"—— 技术负责怎么存，产品负责决定什么时间、把什么信息、以什么顺序喂给智能体。
