这条视频是 AI 产品千媚 对 Anthropic 发布的《The AI-Native SDLC Playbook》（AI 原生软件开发生命周期手册）的解读，核心观点是：AI 写代码变快后，瓶颈从 “写代码” 转移到了需求评审、代码审查和上线部署，所以企业不能只给旧流程打 AI 补丁，而要把整个开发流程重构成一个循环。

问题起点 视频开头用一张 “流水线” 图说明：AI 把开发环节从几周压到几小时，但需求提出到上线仍要两三周。传统线性流程（产品写需求→设计→工程写代码→测试→运维上线）是为 “人写代码慢、工程化贵” 设计的，现在中间快了，两头没跟上。

为什么必须是循环 作者认为 Agent 开发和传统开发有根本区别：传统开发里 PRD 和原型确认后功能基本就定了；但 Agent 的模型效果和边界是黑盒，不试不知道行不行。所以必须更早进入真实环境，用真实数据和场景验证、暴露问题、快速迭代。画面里用 “传统：先定后做” 和 “Agent：黑盒” 两条路径做了对比。

六个阶段与关键文档

规划：产出 intent.md，不是正式 PRD，任何人用大白话和 AI 聊，AI 追问影响谁、边界在哪、成功标准、约束，产品负责人审批。
设计：产出 spec.md，AI 结合团队安全策略、品牌规范、UX 标准生成，相当于高保真 PRD，仍由产品负责人审 “做什么”。
构建：产出 plan.md + 代码 + 测试。作者强调 AI 写第一行代码前至少要有三份文档，把返工成本从改代码提前到改文档；plan.md 由工程师反复拷问改动影响、顺序和风险。
测试：不是一次性报告，而是持续运行的评估体系 —— 收集 20–50 个真实任务挂到 CI，claude.md、Skill、Hook 配置一变动就自动跑，通过率掉了不能合并。
部署：AI 按审查策略审每个 PR 并标记问题，人做最终审批；生产部署必须人工授权，系统层面限制 AI 的网络访问和密钥读取。
维护：用确定性脚本（不是 AI）盯线上关键指标，异常时 AI 写新的 intent 文档回到起点，修复后把问题加进 Evals。

两层规则 + 一层护栏 claude.md 是项目须知（代码规范、架构约定、AI 常犯错误），AI 每次开工自动读；Skill 是沉淀的经验，属软约束、不保证 100% 遵守；Hooks 是硬护栏，比如禁止改数据库迁移文件、修 bug 时禁止改测试文件，不符合条件直接拦截。另外还讲了并行会话跑独立 Git 分支、用子 Agent 审查主 Agent 避免 “灯下黑”、AI 写完必须自己跑测试和构建。

作者的核心判断 对个人开发者，价值在于用文档流转规范流程；对企业，过去十年管理逻辑是 “管人”，现在 AI 接管执行，人要从执行者变成审计者、决策者和制度设计者—— 人写规则 AI 执行，人定标准 AI 验证，人审批产物 AI 生产产物。

评论区基本认可 “仍需人工 Review 和测试” 这一点，也有人提醒 token 成本和需求梳理成本可能更高，不宜盲目照搬。另外有观众问录屏工具，作者回复用的是 ScreenStudio。
