这条视频是 AI 产品博主「AI 产品千媚」拆解 Claude Code 的 memory 机制，核心观点是：Claude 的记忆设计非常克制，目标不是 “越来越懂你”，而是 “把下一个任务做得更好”。

三种常被混淆的长期状态

CLAUDE.md：明确写下的长期规则，如项目规范、技术栈、行为要求，相当于员工入职手册。
session / plan / task：当前任务做到哪、改过哪些文件、还剩哪些步骤，相当于桌上摊开的资料，任务结束大多不必长期保留。
Auto Memory：跨会话仍可能影响下次协作的经验，视频主要讲这一层。它不会记 “爱看科幻电影”，但会记 “是资深开发者，不需要基础科普”。

值得跨会话保存的四类内容：用户信息（角色、目标、知识背景）、反馈（纠正过什么、哪些做法被确认过）、项目背景（代码和 Git 里看不出的信息，如合规原因、负责人、截止时间）、reference（外部资料放在哪，如 Linear 项目、Grafana 面板）。代码结构、文件路径、Git 历史、已写进 CLAUDE.md 的规则则明确不存，因为这些能从更可靠的来源读取。

写入有两条路径：用户明确说 “记住 / 忘记”，主 agent 立即执行；否则每轮对话结束后，系统启动专门的提取 agent 回看新增消息，靠游标只处理上次提取后的新内容。这个后台 agent 权限卡得很紧：读写限制在记忆目录、不能调 MCP、不能派子 agent、最多跑 5 轮，失败也不提示。

存储与召回：每个项目一个 memory 目录，memory.md 当目录用，只留标题、链接和一句描述，正文按主题拆成详情文件，索引硬限制最多加载前 200 行。不用向量索引，是因为 Markdown 省掉了切片、embedding 和数据库维护，用户还能直接打开改。召回时先取最近更新的最多 200 份记忆的标题和简介，交给另一个 Sonnet 模型筛出最多 5 份最相关的，再给主 agent。

演化与 Autodream：相似内容合并进已有主题文件；新旧冲突时优先信当前可验证的项目状态或用户最新确认；超过两天的记忆召回时附带新鲜度提醒。但整套机制没有版本记录、没有信度评分，合并删除全靠模型判断，所以重复、误改、旧信息残留都可能发生。Autodream 是定期整理：距上次整理至少 24 小时、期间至少 5 个对话更新才会启动，派独立 agent 合并相似内容、修正被推翻的信息、清理索引。作者认为它最有价值的地方是把 “写入” 和 “维护” 拆成两个生命周期，但整理仍由模型完成，给不了数据库那种确定性。

评论区也印证了这一点：不少从业者认为记忆越多输出越不稳定，工程实现门槛高；也有人提到 Claude 记忆出过 bug、不如 OpenAI 的分层记忆。作者认可 “记得多了确实是负担”“行业现在没有标准答案”。

一句话总结：这套设计轻量、透明、可人工修改，适合当可靠的工作助手；但如果你期待它像熟悉你生活的私人助理，就会觉得它很弱。
