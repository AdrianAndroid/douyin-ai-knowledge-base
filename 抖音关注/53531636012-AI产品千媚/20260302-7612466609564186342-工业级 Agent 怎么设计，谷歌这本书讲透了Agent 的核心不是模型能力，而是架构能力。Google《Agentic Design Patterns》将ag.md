这条视频是 AI 产品博主「AI 产品千媚」对 Google《Agentic Design Patterns》的解读，核心观点是：工业级 Agent 的差距不在模型能力，而在架构能力。她把书里的 21 种设计模式按用途重组成六大类，讲清 “能跑 Demo” 和 “能上线” 之间差什么。

为什么 Demo 好做、上线难 视频开头点出痛点：有了 Vibe coding，选模型、写提示词、接工具、交给 AI 写代码，一个 Demo 很快就能跑起来。但接入真实业务、任务从单轮问答变成多步决策、系统需要长期运营后，问题就冒出来了 —— 多步任务无法稳定复现，长期运行后状态逐渐失控。作者认为这正是需要架构设计的原因。

六大类模式（作者自己的归类，非书中原分类）

流程编排：提示链（像流水线，把任务拆成顺序步骤，如先提取关键信息、再情感分析、最后出摘要）、路由（加条件判断，按上下文选路径和工具）、并行化（独立子任务同时跑）、规划（前三种是人预先定好路径，规划是 Agent 自己分析目标、制定计划再执行，典型场景是 deep research）。
推理提升：思维链是单条路径的显式推理；思维树是多分支评估后选最优；ReAct 是推理与行动交替、边想边做边观察；Reflection 是生成后自省，可自己反思，也可另设独立 “批评者” 按特定标准严格挑错。作者按时机归纳为：思维链 / 思维树是前置思考，ReAct 是过程中思考，Reflection 是后置思考。
外部交互：工具调用给 Agent 装上 “手和脚”；MCP 是标准化协议，作者比喻成 USB 接口，统一接入外部数据源，不用为每个源单独写适配器；RAG 解决知识时效性。她还打了个对照：工具像扳手，拿来即用；MCP 像插座，不直接给工具，但允许各种工具接入。
记忆管理：短期记忆是会话内的上下文（消息、回复、工具结果、思考过程），会话结束就丢；长期记忆像外部知识库，需要时检索出来再整合进当前上下文。
系统协作：单 Agent 面对多领域复杂任务能力受限，于是拆成多 Agent 团队，形式有顺序交接、并行处理、辩论与共识、层级结构、专家团队、批评 — 审查者对抗等，彼此通过 A2A 通信协议协作。
可靠性治理：评估与监控（评估 Agent 轨迹，监控准确率、延迟、资源消耗）、护栏与安全、异常处理与恢复（日志、重试、降级、恢复）、Human in the Loop（在需要细致判断、伦理推理或模糊语境时引入人类监督）。

组合才是重点 作者强调不能孤立看单个模式：智能客服是提示链拆解意图识别→需求澄清→Query 改写，再路由到 RAG 或工具路径，并加护栏；研究助手是 planning 定框架 + ReAct 边检索边分析 + 并行检索多源；AI Coding 是多 Agent 分工做需求分析、架构设计、测试。结尾给出 5 条实践建议：从简单开始、根据场景选择、持续迭代、重视可靠性、拥抱开源生态。
