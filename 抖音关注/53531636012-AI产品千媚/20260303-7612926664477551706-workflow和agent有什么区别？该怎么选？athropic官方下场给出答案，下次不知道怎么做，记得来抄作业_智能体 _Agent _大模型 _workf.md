这条视频是博主「AI 产品千媚」讲 Workflow 与 Agent 的区别和选型，核心依据是 Anthropic 的《Building effective agents》。她反对 “复杂度崇拜”，认为 Agent 不是越复杂越高级，两者真正的分界线是决策权归谁。

区别在哪

Workflow：路径由人写死，步骤提前规划好，模型只负责执行。决策权在人手里，所以可控、可复现、好调试。
Agent：路径由模型决定，会规划、会选择，工具结果还能改变策略。决策权在模型手里，更灵活，但不确定性也上来了 —— 同样的问题今天一个答案、明天一个逻辑，企业验收会很难。

三个判断标准（三条都不满足才轮到 Agent）

路径是否明确：路径明确、步骤固定，就是流程问题。
目标是否稳定清晰：可复现，还是流程问题。
是否需要动态策略选择：不需要，就不必引入 planning。

她的原话是 “不要把流程问题做成模型问题”。

推荐路径：增强型 LLM → Workflow → Agent

增强型 LLM：提示词写清楚，能检索、能调基础工具、能记上下文，很多场景到这一步就够了。
Workflow 五种模式：提示链（如写营销方案先大纲后正文）、路由（智能客服按售前 / 售后分流）、并行化（子任务独立或要多视角分析）、指挥官 Orchestrator-workers（无法预先写全子步骤时，由中央模型动态拆解分配，如 AI coding 要改哪些文件需现场决定）、评估优化器（一个模型生成、一个模型评估，如 deep research 判断信息够不够）。
Agent：只用于探索型任务、路径无法硬编码或需多轮操作的情况，且要满足三条：有环境数据反馈推动执行、敏感节点引入人类检查、设置最大迭代次数防死循环。

结尾她的观点是：复杂系统是迭代出来的，不是设计出来的；真正拉开差距的不是做了多少个智能体，而是能不能定好决策权的边界。
