了解Podman主要特性
Podman 由 RedHat 主导开发，是一款开源免费的容器管理工具。它完全遵循 OCI 标准，能够无缝运行 Docker 镜像，且命令行与 Docker 高度一致，大幅降低了学习和迁移成本。

01:32
对比Docker与Podman架构
Docker 依赖于 root 权限启动的守护进程，而 Podman 采用无守护进程的轻量化架构。它直接调用 runc 与操作系统内核交互，支持以普通用户权限运行容器，有效提升了安全性并降低了系统复杂度。

02:40
演示Linux安装与使用
在 Ubuntu 系统上，可以通过 apt 包管理器直接安装 Podman。通过与 Docker 的命令对比，可以直观地验证 Podman 无需 root 权限和无守护进程的特性。

03:38
科普K8s与Docker关系
视频简要梳理了 Kubernetes 与 Docker 的演进关系。随着 CRI 标准的建立，高版本的 K8s 可以绕过 Docker 守护进程，直接调用 containerd 等符合标准的容器运行时进行操作。

04:35
演示Windows安装与使用
在 Windows 系统上，Podman 与 WSL2（适用于 Linux 的 Windows 子系统）配合默契。只需在启用相关 Windows 功能后，通过 CMD 命令安装 WSL，即可在 Linux 子系统中正常运行 Podman。

演示拉取镜像与运行容器
通过配置国内镜像站解决网络问题后，使用 Podman 拉取 MongoDB 镜像并运行容器。演示了端口映射、绑定挂载卷以及传递环境变量等与 Docker 兼容的常用参数。

演示创建Pod管理容器
Podman 原生支持 Kubernetes 的 Pod 概念，可将多个紧密耦合的容器加入同一 Pod 中共享网络和存储。通过创建包含 MongoDB 和其网页客户端的 Pod，展示了 Podman 批量管理容器的便捷性。

演示导出K8s配置文件
Podman 可以将本地运行的 Pod 直接导出为 Kubernetes 兼容的 YAML 配置文件。同时，也能通过该配置文件在 Podman 中重新创建 Pod，实现了与 K8s 生态的无缝对接。

演示配置开机自启动
借助 Linux 系统的 systemd 守护进程，可以为无守护进程架构的 Podman 生成自启动配置。通过将配置文件部署到系统中，实现了服务器重启后 Pod 及容器的自动运行。
