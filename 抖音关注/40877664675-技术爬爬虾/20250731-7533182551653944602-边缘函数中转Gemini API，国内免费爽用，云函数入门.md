这是「技术爬爬虾」的一期编程教程，核心是讲边缘云函数：他写了一个小项目 gemini-balance-lite，用边缘函数把 Gemini 的免费 API 中转到国内使用，并支持多个 Key 轮询做负载均衡，把免费额度成倍放大。

项目怎么用

支持 Cloudflare Worker、Vercel、Deno、Netlify 四种免费部署方式，代码逻辑统一放在 handleRequest 里，各平台只是入口写法不同。
部署后平台分配的默认域名在国内打不开，需要绑定自己的域名（演示里用托管在 Cloudflare 的免费域名，配 A 记录 + TXT 记录完成验证）。
客户端用 Cherry Studio 接入，提供商选 Gemini 或 OpenAI 格式都行，API 地址填自己的域名，密钥填 Google AI Studio 申请的 Key，多个 Key 用逗号分隔，项目会随机挑一个用，从而增加每天的免费请求次数。实测 gemini-2.5-pro、2.5-flash 都能正常出结果，思维链和联网搜索也正常。
作者特别提醒：广东地区不建议用 Cloudflare Worker，因为可能被分到香港节点，而香港用不了 Gemini。

云函数知识部分

云函数就是开发者上传一段代码，有请求或事件触发时才运行，不用买服务器，底层环境由厂商维护，所以也叫 “无服务器部署”。
传统云函数 vs 边缘函数：边缘函数跑在全球边缘节点，就近响应、延迟低；运行在 V8 Isolates 轻量沙箱里，只有少量 Node.js 标准库加部分 Web API，且必须 return 一个 Response。传统云函数多在 Node.js 环境，能用文件处理、系统交互等大部分标准库。两者都是按请求启动、空闲回收，新请求会有冷启动；服务器部署则是进程常驻。
他用 Vercel 现场演示：先写一个返回字符串的传统函数，再引入 fs、path 读目录成功；改成边缘函数后同样代码直接报错，说明边缘环境不支持文件操作，改成读取远程数据再放进 Response 才跑通。

评论区补充的实用信息：429 报错多与额度、并发有关，多 Key 轮询能明显缓解；多账号自用一般问题不大，但别分享、别商用，也有人反馈自用仍被封，存在个体差异。
