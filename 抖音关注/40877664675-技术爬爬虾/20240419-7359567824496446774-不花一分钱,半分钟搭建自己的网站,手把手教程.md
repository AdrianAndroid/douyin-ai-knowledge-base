这是「技术爬爬虾」的 GitHub Pages 建站教程，核心结论是：不用买服务器、不用买域名，靠 GitHub 的免费静态托管就能搭出个人博客和项目页面，全程在网页上点按钮完成。

视频讲了什么

作者先对比传统建站：租服务器、跑 Web 程序、买域名、配 SSL 证书、配 DNS 解析，一套下来小白基本劝退。而 GitHub Pages 把这些自动化，点几下就能上线，且完全免费。它分两类站点：

个人站点：每个账号只能有一个，仓库名必须严格写成「账号名.github.io」，访问地址就是这个名字。
项目站点：数量不限、仓库名随意，但网址会多出一段仓库路径，比较长，可用自定义域名解决。

两段实操

个人博客：以黄玄的博客框架为例，先 fork 到自己名下并把仓库改名为 tech-shrimp.github.io，在 Settings → Pages 里选 GitHub Actions 并配置 Jekyll（把 Markdown 笔记渲染成网页），提交后 Actions 跑完出现对勾即部署成功。之后改 config.yml 换标题、邮箱，在 post 目录新建 Markdown 文件写文章，提交后自动重新部署。
项目站点：fork 一个收录 50 多种编程语言「表白代码」的开源项目，直接在线编辑 web/032 的 index 文件，把「小孙同学」改成「爬爬虾」，在 Pages 里选分支根目录保存，约 1 分钟后上线。再用 Cloudflare 域名做 4 条 A 记录加 1 条 CNAME，在 Custom Domain 填入域名，验证通过后就能用干净域名访问；最后把页面复制到根目录命名为 index.html，连后面的路径也省掉。

评论区补充的几点

有人指出作者把「pages」读错了；关于同类服务，网友提到 Gitee Pages 曾提供免费托管但已停服；编辑站点时图片可走图床、传仓库或用对象存储；这类托管本质是静态的，要做动态功能得配合云函数。

想动手的话，最容易卡住的一步通常是 fork 后仓库名没改成「账号名.github.io」，导致个人站点发布不出来。
