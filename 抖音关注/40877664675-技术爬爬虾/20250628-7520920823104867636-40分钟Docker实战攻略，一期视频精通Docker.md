理解Docker核心概念
Docker 利用容器化技术为应用程序封装独立的运行环境，每个环境即为一个容器。与虚拟机相比，Docker 容器共享宿主机的系统内核，因此更加轻量、小巧且启动迅速。 镜像是容器的模板，类似于软件安装包或制作糕点的模具，而容器则是运行中的软件或糕点。Docker 仓库（如官方的 Docker Hub）则是用于存放和分享这些镜像的集中场所。

在Linux系统上安装Docker
在 Linux 系统（如 Ubuntu）上安装 Docker 最为直接。只需按照官方文档的步骤，在服务器上执行两条指定的 shell 命令即可完成安装。 需要注意的是，若当前登录的 Linux 用户不是 root 用户（如普通的 Ubuntu 用户），则需要在所有的 Docker 命令前加上sudo，以管理员权限来执行。

在Windows系统上安装Docker
在 Windows 上安装 Docker 需要先启用 “虚拟机平台” 和 “适用于 Linux 的 Windows 子系统（WSL）” 功能。重启电脑后，需在命令提示符中以管理员身份运行两条命令，将 WSL 默认版本设为 2 并进行更新。 随后从官网下载对应 CPU 架构（通常为 AMD64）的 Docker Desktop 安装包进行安装。安装完成后，务必保持 Docker Desktop 运行，并在新的终端中输入docker --version验证是否安装成功。

在Mac系统上安装Docker
在苹果电脑（macOS）上安装 Docker 过程最为简便。只需根据自己电脑的芯片类型（Intel 或 Apple Silicon）下载对应的 Docker Desktop 安装包，然后按照常规步骤进行安装即可。

使用Docker命令下载镜像
使用docker pull命令可以从仓库下载镜像。一个完整的镜像名称通常包含仓库地址、命名空间、镜像名和标签（版本号）。对于官方仓库的官方镜像，可以省略仓库地址和命名空间，例如直接使用docker pull nginx获取最新版的 Nginx。 若遇到国内网络环境导致下载失败的情况，可以通过修改 Docker 配置文件添加国内镜像加速器来解决。此外，还可以通过添加--platform参数来拉取特定 CPU 架构的镜像。

使用Docker命令运行容器
docker run是最重要的命令之一，它使用指定的镜像创建并启动一个全新的容器。添加-d参数可以让容器在后台（分离模式）运行，避免阻塞当前终端窗口。 通过docker ps命令可以查看正在运行的容器，获取其唯一的容器 ID 和系统分配的容器名称。如果只想对已有的容器进行启停操作，可以使用docker stop和docker start命令，它们会保留之前设置的所有运行参数。

配置端口映射与挂载卷
由于容器网络与宿主机默认隔离，-p参数用于将宿主机的端口与容器内的端口进行绑定映射，使得外部网络可以通过访问宿主机端口来访问容器内的服务。 -v参数则用于将宿主机与容器的文件目录进行绑定（挂载卷），实现双向的文件同步。这一机制最大的作用是实现数据的持久化保存，即使容器被删除，数据依然保留在宿主机中。除了直接指定宿主机目录的绑定挂载，还可以使用docker volume create命令让 Docker 自动创建命名卷进行管理。

传递环境变量与设置重启策略
使用-e参数可以在容器启动时向其传递环境变量，常用于配置数据库的账号密码等运行时参数。相关的环境变量通常可以在 Docker Hub 对应镜像的官方文档中查询。 通过--restart参数可以配置容器的重启策略。设置为always表示只要容器停止（如崩溃或宿主机断电）就会立即自动重启；而设置为on-failure则在手动停止容器后不会再尝试重启，这在生产环境中非常实用。

进入容器内部进行调试
利用docker exec命令可以在运行中的容器内部执行 Linux 命令。常用的组合是docker exec -it <容器ID> /bin/sh，这会为用户提供一个交互式的命令行环境，直接进入容器内部。 由于 Docker 镜像追求精简，很多基础系统工具可能缺失。在进入容器后，可以先通过cat /etc/os-release查看 Linux 发行版，再使用对应的包管理器（如 apt）安装所需的调试工具（如 vim 编辑器），从而进行更深入的排错和配置修改。

使用Dockerfile构建镜像
Dockerfile 是用于制作自定义镜像的 “图纸”，它以文本文件的形式详细描述了镜像的构建步骤。典型的 Dockerfile 包含以下指令：

FROM：选择一个已有的基础镜像（如内置 Python 的 slim 镜像）。
WORKDIR：设置镜像内的工作目录。
COPY：将本地代码文件拷贝到镜像内。
RUN：在镜像内执行命令（如安装依赖包）。
EXPOSE：声明容器运行时提供服务的端口。
CMD：设定容器启动时默认执行的命令。 编写好 Dockerfile 后，使用docker build -t <镜像名>:<版本> .命令在当前目录构建镜像。构建成功后，还可以通过docker login和docker push命令将自定义镜像推送到 Docker Hub 上进行分享。

配置Docker网络模式
Docker 默认使用 bridge（桥接）网络模式，同一子网内的容器可以通过内部 IP 或容器名（借助 Docker 内部 DNS 机制）互相通信，而跨子网则无法通信。

自定义桥接子网：通过docker network create命令创建新的子网，并在启动容器时使用--network参数指定加入，实现容器间的网络隔离与通信。
host 模式：容器直接共享宿主机的网络命名空间，使用宿主机的 IP 地址，无需进行端口映射，适用于需要解决特殊网络问题的场景。
none 模式：容器完全禁用网络连接，处于不联网的隔离状态。

使用Docker Compose编排容器
对于由前端、后端、数据库等多个模块组成的复杂应用，将每个模块打包成独立容器是最佳实践，但这会带来繁琐的网络和启动配置工作。 Docker Compose 是一个轻量级的容器编排工具，它使用 YAML 文件来定义多个容器的创建、网络协同和运行参数。通过简单的docker-compose up -d命令即可一键启动所有服务并自动创建子网，使用docker-compose down则能一键停止并清理容器。它极大地简化了多容器应用的部署与管理流程。
