在团队协作开发中，直接使用 git pull 拉取代码容易产生杂乱的合并提交记录，导致提交历史难以追溯。本视频分享了如何通过 git pull --rebase 保持提交历史的线性干净，并演示了相关的配置与操作方法。

00:00
了解代码提交冲突
当多人在同一分支并行开发时，后提交的人在推送代码时往往会被远端拒绝。虽然使用 git pull 可以简单解决问题，但它等同于 git fetch 加 git merge，会在提交历史中产生额外的合并记录，长期积累会让历史变得臃肿且难以查找。

01:19
使用rebase保持历史干净
为了保持提交历史的线性与整洁，可以使用 git pull --rebasebase 命令。该命令会先将本地提交暂时搁置，拉取远端的最新提交后，再将本地提交无缝衔接在其后，从而避免产生无用的合并节点。

01:34
演示命令行操作
通过实际的命令行操作演示可以看出，使用普通的 git pull 会在 Git 日志中多出一条 merge branch 的记录；而改用 git pull --rebase 后，提交历史则保持了干净的直线状态，没有任何多余的合并信息。

02:45
修改git默认pull配置
为了避免每次拉取代码时都手动输入 --rebase 参数，可以通过 git config pull.rebase true 命令修改 Git 的全局配置。设置完成后，直接使用 git pull 命令也会默认以 rebase 的方式进行操作。

03:05
在编辑器中设置pull方式
除了命令行，在常用的代码编辑器（如 JetBrains 系列 IDE）中同样可以进行设置。在更新项目的操作选项中，选择使用 rebase 的方式，并勾选 “不再显示”，即可让编辑器在后续遇到代码拉取时默认保持提交历史的线性干净。
