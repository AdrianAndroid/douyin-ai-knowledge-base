这是一份由技术爬爬虾带来的Windows 平台 WSL 保姆级全攻略，核心是解决 AI Agent 在 Windows 上运行表现不如 macOS 的痛点，帮你不用羡慕 Mac，在 Windows 上顺畅跑 AI Agent。

作者开篇点明问题根源：Windows 自带的 PowerShell 对 AI 不够友好，而 AI 大模型的训练语料大多是 Linux/macOS 风格的命令行操作，直接在 Windows 环境跑 AI Agent 很容易频繁报错、浪费 Token。而 Windows 自带的神器 WSL，只靠一行命令就能运行 Linux 子系统，同时兼顾两大系统的优势，在 WSL 里跑 AI Agent 有 3 个核心好处：

Agent 运行更稳、效率更高，AI 写出错概率明显更低
和线上生产环境更一致，后续代码部署到 Linux 服务器时环境差异小，流程更顺畅
环境隔离更安全，就算 Agent 误操作搞坏了子系统，也不会影响 Windows 主系统，删掉重建实例就能恢复

完整教程从前置准备到实战落地一步步讲透：

先确认 CPU 虚拟化：打开任务管理器 - 性能 - CPU，查看虚拟化是否启用，没开启就进 BIOS 打开 Intel 的 VMX 或 AMD 的 SVM Mode 开关
基础安装：国内网络环境下用命令 wsl --install -web-download 提速，默认安装 Ubuntu，安装时设置 Linux 子系统的用户名和密码，注意输入密码时屏幕不会显示内容
进阶玩法：可以用命令列出所有在线 Linux 发行版，自定义安装其他发行版，还能通过--location指定安装目录到非 C 盘，也能给同一个发行版创建多个互相隔离的独立实例
基础使用：升级 WSL 到最新版本，掌握多种启动、指定实例、设置默认子系统的方式，关闭命令行窗口就能自动关机 WSL 虚拟机
实战部署：以 Ubuntu 为例，配置好 Git、Python、Node.js 这开发三件套，最后安装极简 AI Agent 工具 PI，完成启动测试。

评论区的开发者也补充了不少实用经验：Windows 自带的 PowerShell 5.x 容易出现中文乱码和编码错误，升级到 PowerShell 7.x 并设置 UTF-8 能大幅改善；也有用户分享让 Codex 改用 Python 执行命令，稳定性比直接跑命令行更好。
