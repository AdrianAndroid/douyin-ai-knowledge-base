这是「技术爬爬虾」对 TRAE SOLO 正式版的实测视频：作者用 SOLO Coder 二次开发一个 82 万行代码的开源项目 cal.com，验证它能不能扛住中大型代码库的改造。

三大核心更新

实时有感知：SOLO 会自主总结进度、列任务清单，关键步骤自动折叠成摘要；新增 Diff View 集中展示所有代码变更。
随时可掌控：新增 Plan 模式，先出开发计划、人工确认后再执行。
多任务并行：可同时开多个任务；进阶玩法是创建 Sub Agent（数据库大师、后端大师、前端大师、问答大师），上下文互相隔离，由主 Agent 调度汇总。

实测过程 作者给 cal.com 的预约列表加 "时间轴视图" 按钮。SOLO 先出计划书，作者发现它误把新增预约页 bookings-view.tsx 也列进修改范围，指出后重新生成计划。执行后交付 1 份文档 + 4 个文件修改，审核界面类似 GitHub Pull Request。随后作者又提两个 bug（时间块大小要按时长变化、部分文案缺中文翻译），并演示了一个技巧：修 bug 前手动压缩上下文，使用率从 45% 降到 1%，减少干扰也省 token。

进阶需求是给活动类型加 "优先级" 字段并落库、预约继承该优先级，涉及前后端加数据库共 14 个文件。SOLO 同时启动 4 个 Sub Agent 并行（前端量大时开了两个前端大师），期间作者另开任务问技术问题，不打断主流程。

评论区值得注意 主流反馈偏负面，集中在复杂项目里代码逻辑乱、报错多、调试成本高，常被拿来和 Cursor 对比；也有多条提到 "没有 Claude 模型加持体验明显下降"。高赞的 "三美金 Pro 会员一晚上不如 Cursor 一小时" 文案被认出是多人复制，有灌水嫌疑。正面评价多集中在小需求、简单应用场景。
