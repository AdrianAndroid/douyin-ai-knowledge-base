这是 UP 主「技术爬爬虾」的一期编程黑科技教程：他改造了一个 B 站评论爬虫，让程序自动给视频下的每条评论点赞，最后部署到 Linux 服务器上，每 3 小时定时跑一次。

视频主线

起因：他提到之前看过一位程序员 UP 主给自家视频每条留言都点赞，而他自己新视频发布前两天也会手动点赞，常被怀疑用了脚本。他顺势承认：手动点赞是真的，但 “爬爬虾” 这个脚本也是真的。
第一版思路：用 pyautogui 把单击、双击、滚轮等操作写进 Excel 配置，模拟鼠标点击；缺点是会占用电脑屏幕，只能放进虚拟机跑。
正式方案：改用 Python + Selenium 操作无头浏览器，在 Linux 上静默运行，资源占用小、更稳定。他在 ktop（开源项目平台）找了个现成的 B 站评论爬取项目，在代码里加了一个 click_like_icon 方法：先判断点赞按钮是否已点亮，未点亮就滚动到按钮位置点击，点完随机停零点几秒模拟真人；一级评论和二级评论两处都会调用。
配置与演示：关掉原爬虫功能、开启点赞功能，注释掉无头模式那一行以便肉眼观察，在 video list 里填三个视频链接，运行后手机扫码登录 B 站即可。
Linux 部署五步：配 Python 环境 → wget 下载并安装 Chrome → 解压 chromedriver 到 /usr/local/bin → pip install -r requirements.txt → 准备好扫码登录生成的 cookie 文件。
定时执行：写 start.sh 启动脚本后台静默运行，再用 crontab 设为每 3 小时的 18 分执行（0:18、3:18、6:18、9:18……），他自嘲这是 “冷酷无情的每三个小时自动给所有评论点赞”。

视频里调侃的 “点赞永动机” 是玩梗，实际就是自动化脚本；作者也明确说点赞功能做成了可配置、可关闭，不影响原程序。评论区问得最多的是 “已点赞的会不会被重复点成取消”“这样刷会不会封号”—— 按代码逻辑，脚本会先判断按钮状态，已点亮就跳过，但平台对自动化行为的态度属于账号风险，视频里没有涉及。
