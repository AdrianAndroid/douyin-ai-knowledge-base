视频先点明：HTTPS 虽然加密了传输流量，但DNS 查询和 SNI 字段仍以明文传输，会直接导致用户访问的网站信息被中间人监听、篡改，引发隐私泄露、DNS 污染、SNI 阻断等问题。

针对 DNS 明文漏洞，视频介绍了 DoT 和 DoH 两种加密 DNS 方案，其中主流的 DoH 复用 HTTPS 的 443 端口，让 DNS 查询和普通网页流量混在一起更难被识别攻击，还演示了在 Windows 11 和 Chrome 浏览器中配置阿里云 DoH 的完整操作步骤，配置后抓包就无法再从 DNS 请求里获取用户要访问的网站信息。
针对 SNI 明文漏洞，视频先解释了 SNI 在 TLS 握手阶段的作用和明文泄露风险，随后介绍了 ESNI 和更完善的 ECH 技术：ESNI 仅加密 SNI 字段但保护不全面、没有托底机制，而 ECH 可以加密整个 Client Hello 握手包，还支持解密失败后重试，解决了握手阶段的全部敏感数据泄露问题，目前主流浏览器已经默认支持 ECH，只需要提前配置好 DoH 完成密钥分发就能启用。

最后视频还提到谷歌研发的 QUIC 协议（HTTP/3 的底层），它从设计之初就自带 Client Hello 加密，还能大幅减少 TLS 握手流程降低延迟，等 HTTP/3 普及后，大部分网络隐私安全问题都会得到解决。视频中途还植入了博主个人主页专栏里的 Git 与 Github 精讲课程，说明前三节免费试看就能解决大部分日常使用问题。
