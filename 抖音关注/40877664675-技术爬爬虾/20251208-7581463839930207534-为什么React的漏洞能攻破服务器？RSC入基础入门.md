这个漏洞的 CVSS 评级达到满分 10.0，属于最高危险级别：攻击者不需要任何授权，仅通过网站公开地址发送特殊 POST 请求，就能在服务器上执行任意恶意代码，甚至直接打开本地计算器、窃取数据库数据、植入木马。视频里也完成了完整复现：使用存在漏洞的 Next.js 16.0.6 版本创建空白项目，运行 GitHub 上的 POC 脚本就成功触发攻击，哪怕是完全未修改代码的新项目也会中招。

作者解释了 “纯前端 React 框架能攻破服务器” 的核心原因：现在的 React 早已不是纯前端库，而是发展出了前后端一体的全栈架构。RSC 就是 React 生态近年最大的更新，它允许组件代码直接在服务器端运行，最终只把 HTML 结果返回给客户端，不再把全部逻辑打包到前端 JS 里。这次漏洞正是 RSC 的反序列化漏洞：攻击者利用 React 的 Flight 协议中对象的相互引用关系，顺着原型链找到 JavaScript 的 Function 构造器，最终构造出恶意函数完成远程代码执行。官方的修复方案也很直接：限制对象引用时只能读取自有属性，阻断对原型和构造器的访问。

视频还通过实战演示了 RSC 的特性：在 Next.js 13 之后默认所有组件都是服务器端组件，代码逻辑完全在服务端执行，甚至可以直接在组件里写数据库连接逻辑，浏览器端完全看不到敏感信息，最终直接返回拼接好的 HTML，省去了前后端接口交互的步骤，既节省带宽又大幅提升首屏加载速度。同时 Next.js 也支持通过'use client'标记声明客户端组件，二者可以嵌套使用，但要注意客户端组件里不能嵌套服务器组件。

最后作者也提醒开发者：Next.js 和 AI 编程适配性很强，能快速落地全栈应用，但这种前后端代码混写的模式很容易在 AI 辅助开发时出现逻辑混淆，把敏感 API 写到客户端代码里，开发者需要更深入理解框架的运行边界，避免引入安全隐患。
