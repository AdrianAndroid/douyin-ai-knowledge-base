这是「技术爬爬虾」的一期 Cloudflare 配置教程，核心是用两个域名加 CNAME 分线路解析，绕开国内访问 Cloudflare 免费 CDN 反而变慢的问题。开头那张 “赛博活佛” 图，是网友对 Cloudflare 免费服务的调侃。

问题背景 Cloudflare 免费提供 CDN、DDoS 防护、隐藏源站 IP 等服务，但国内用户常吐槽它 “越加速越慢”—— 因为默认分配的节点未必适合国内线路。

原理与配置思路 作者用自己两个域名演示：主力域名 txtreme.com、辅助域名 txtreme.top，服务器上用 nginx 挂了个简单网站。四步走：

把 origin.txtreme.top 解析到服务器，打开小黄云，开启 CDN 并隐藏真实 IP；
用 Cloudflare 的 SaaS（自定义主机名） 服务，让 CDN 节点收到 Host 为 txtreme.com 的请求时回源到 origin.txtreme.top；
新增子域名 cdn.txtreme.top，CNAME 到社区已配置好线路分流的公共优选地址，实现联通、电信、境外各走最优节点（作者自嘲这是 “抄袭业” 做法，但简单好用）；
把主力域名 txtreme.com CNAME 到 cdn.txtreme.top，这一步必须关掉小黄云。

实测效果 直连平均约 191ms 且有响应超时；优选后降到 127ms、无超时。未做优选的子域名测试出现 22 个访问失败，出口节点只有 104、172 两个；优选后出口节点明显增多，失败只剩福建泉州一处（作者提到当地在推进 IP 白名单）。

评论区值得注意的 高赞反馈称视频发布前后 Cloudflare 出现过约 3 小时故障，有人调侃 “赛博活佛归西”，也有人补充 IPv6 可绕开部分连不上的情况；另有用户提醒中文域名在 CF 里用不了（需转码），以及家庭宽带封 80/443 端口可考虑联通商务宽带。这些属于网友经验，不是作者原话。
