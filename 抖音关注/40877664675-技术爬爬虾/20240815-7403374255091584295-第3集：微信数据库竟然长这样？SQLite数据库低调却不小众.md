这条视频来自「技术爬爬虾」，核心是纠正一个常见误解：SQLite 并不小众，反而是世界上装机量最大的数据库，作者还以微信为例，拆解了它的原理和表结构。

主要脉络

为什么说 “人人都在用”：SQLite 是轻量级嵌入式关系型数据库，用 C 语言开发，不需要服务器，随 App 一起打包进手机、家电、路由器、汽车。官方统计在用的实例超过 1 万亿个。
轻到什么程度：安卓版仅 3.44MB，Windows 的 DLL 约 1MB，下载一个 exe 打开就能建库，作者现场演示了建表、插入 “汤姆”、查询。
“lite” 不等于功能弱：支持表、索引、视图、多列 / 倒序 / 部分索引、ACID 事务（Begin/Commit/Rollback），SQL 能力甚至比 MySQL 更早支持 WITH 语句。
微信怎么用它：微信团队极限优化了 SQLite 的 FTS5 全文搜索，把几百 GB 聊天记录的搜索压到毫秒级；作者推荐去微信 “搜一搜” 看腾讯官方文章《微信全文搜索技术优化》。
局限：单用户模式，多客户端高并发读写不如 MySQL、PostgreSQL 这类服务器数据库。
动手部分：用开源工具 DB Browser for SQLite 图形化查看数据库；再用开源项目 pywxdump 导出 PC 端微信数据库，得到 merge_all.db，逐一看表 ——contact（所有可见的人，含群里的陌生人）、msg（聊天核心表，is_sender 区分谁说的，type 1 文本 / 3 图片 / 34 语音 / 43 视频 / 47 表情）、chatroom（群与群昵称）、emotion、SNS、favorite 等。最后提到开源项目「留痕」可把聊天记录导出成 HTML/PDF 文档。

评论区讨论最多的也是这条主线：SQLite 适合本地低并发，MySQL 适合服务器高并发；以及断电崩溃时事务回滚能否保证一致性、数据库加密、远程访问等延伸问题。

需要提醒的是，导出和查看微信数据库涉及个人隐私数据，自己动手时注意只在本人设备、本人账号上操作，别把导出的库文件外传。
