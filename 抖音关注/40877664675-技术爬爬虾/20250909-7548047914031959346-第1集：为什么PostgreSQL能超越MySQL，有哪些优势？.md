本期视频深入探讨了 PostgreSQL 超越 MySQL 的核心优势，从底层索引机制、数据一致性保障、性能表现、系统扩展性以及开源社区活力等多个维度进行了全面对比。

对比底层索引机制
MySQL 采用聚集索引，数据按主键顺序存放在 B + 树的叶子节点上，非主键字段查询需要进行回表操作。而 PostgreSQL 将数据与索引分离，数据存放在 “堆表” 中，所有索引均为二级索引，这有效避免了随机写入带来的数据页分裂，使索引扩展具备更大的灵活性。

01:52
支持GIN倒排索引
PostgreSQL 支持 GIN（通用倒排索引），它建立了从 “值” 到 “行” 的反向映射。这使得针对 JSON 数据的键值对查找以及文本的全文检索变得极其高效，而 MySQL 并不支持此类索引。

03:07
支持GIST通用搜索树
GIST 是一个通用的索引框架，非常适合处理几何图形、地理位置、IP 地址及时间范围等非线性数据。其内部节点存储的是范围而非具体值，能够通过快速剪枝高效查找数据重叠或距离相近的元素，这也是 MySQL 所不具备的能力。

04:37
支持部分索引
在逻辑删除等场景中，PostgreSQL 可以通过添加条件创建部分索引，仅对满足条件的记录生效。这种设计不仅完美解决了唯一索引被已逻辑删除数据占用的问题，还能有效减小索引物理体积，提升查询速度并减少磁盘占用。

05:36
支持表达式索引
PostgreSQL 原生支持表达式索引，允许直接对列的计算结果建立索引（如将邮箱转为小写后建索引）。相比之下，MySQL 的表达式索引本质上是通过生成隐藏的虚拟列来实现的。

06:14
事务管理DDL语句
PostgreSQL 将表、索引等结构信息存储在系统表中，因此支持将 DDL（数据定义语言）语句直接纳入事务管理。这意味着表结构的修改可以进行整体回滚，有效保证了数据的一致性，避免了脏数据的产生。

08:28
支持可延迟约束
通过可延迟约束，PostgreSQL 将唯一性等约束的检查延迟到事务提交时执行。这解决了复杂业务场景中 “先有鸡还是先有蛋” 的死锁问题，允许在一个事务内安全地完成数据对调或批量更新。

09:28
事务隔离级别对比
PostgreSQL 默认采用 “读已提交” 隔离级别，而 MySQL 默认为 “可重复读”。在实际运行中，MySQL 的可重复读在读写操作上存在区别对待快照的逻辑，可能带来潜在的数据不一致风险，且在高并发场景下容易因间隙锁导致性能退化。

12:14
数据库性能对比
在高并发写入和关联查询场景下，权威测试表明 PostgreSQL 展现出了显著的性能优势。不仅如此，PostgreSQL 新版本的性能持续优化，而 MySQL 的最新版本在性能上反而出现了逐版递减的趋势。

13:38
数据库扩展性对比
PostgreSQL 秉持 “万物皆可扩展” 的设计理念，支持自定义数据类型、函数、操作符和索引类型。通过成功的第三方插件（如 PostGIS），可以直接在数据库层面构建企业级的地理信息系统等复杂能力。

16:59
开源许可证与社区
PostgreSQL 采用了极为宽松的开源许可证，由全球性的开发者社区共同管理，不受单一商业公司控制。这种模式吸引了大量企业共同参与贡献，形成了一个不断拓展能力边界的良性生态系统。
