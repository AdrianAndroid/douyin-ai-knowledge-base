这是「技术爬爬虾」发布的一期 TRAE 实战教程：用 TRAE 的 SOLO 模式，把 Figma 设计稿、Supabase 后端和 Stripe 支付串起来，从零做出一个热气球旅游预订网站，完整跑通注册、登录、下单、付款全流程。

视频主线

作者先介绍两个工具：Supabase 是开源后端平台，在 Postgres 基础上封装了用户鉴权、文件存储和可视化运维面板；Figma 则是浏览器里协作的网页与 App 设计工具。随后他演示了完整开发过程：

配置：在 Supabase 建项目拿数据库密码，在 TRAE 里连接；到 Stripe 取 API 密钥（用沙箱环境），建了三个热气球套餐商品，其中一个是 “浪漫落日” 一次性商品。
取设计稿：在 Figma 模板库的登录页分类里找到热气球主题设计，改造成登录、注册两个页面，再通过 TRAE 的 Figma 集成把两个 frame 加入对话。
SOLO 生成：输入提示词（销售网站、注册登录、Stripe 沙箱下单、三个套餐、用户与订单存 Supabase、只做三个页面），SOLO Builder 自动初始化项目、拆任务清单并逐项勾选完成，还生成了含 Mermaid 架构图的技术文档。
修 Bug：注册后用户没写进业务 users 表，作者切到 IDE 模式，用内嵌对话生成注释、靠写注释触发补全，按 Tab 接受建议；又修了支付 API 路径错误、付款成功但订单未创建两个问题。
验证：邮箱确认后登录成功，沙箱卡付款成功、页面跳转，数据库里能看到订单记录。

两个值得知道的知识点

前端直接调 Supabase 并不等于 “裸奔”，靠的是 RLS 行级安全策略：登录用户只能操作与自己相关的数据行。
架构上前端有两条数据通路：注册登录走 Supabase SDK，订单创建走自己的后端 API，Stripe 支付必须由后端调用以保证安全。
