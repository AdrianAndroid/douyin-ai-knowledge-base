介绍Caddy服务器
Caddy 是一个用 Go 语言编写的现代化 Web 服务器，在 GitHub 上斩获了 6 万星。对比传统的 Nginx，Caddy 最大的优势在于大幅简化了配置流程，并能自动申请和续签 TLS 加密证书。在低负载的日常使用中两者性能没有明显差距，因此 Caddy 非常适合个人博客、小型企业和家庭 NAS 服务等场景。

云服务器部署网站
在 Ubuntu 系统的云服务器上，可以通过复制官网文档中的对应命令快速安装 Caddy。安装成功后，将准备好的域名通过 A 记录指向服务器的公网 IP，并将网站文件放置在指定目录。随后只需修改 Caddyfile 配置文件，将地址改为自己的域名并指定网站文件路径，重新加载配置即可完成 HTTPS 网站的部署。此时访问域名，浏览器会显示由 Let's Encrypt 颁发的安全证书，且 Caddy 会自动进行续签。

讲解证书申请原理
Caddy 主要通过实现 ACME 协议来完成证书申请，其中关键一环是验证域名所有权。常见的验证方式有两种：服务器文件验证和 DNS 解析验证。服务器文件验证需要在网站目录下放置特殊文件，让认证服务器在公网通过域名访问到该文件，但这种方式要求服务器必须暴露公网的 80 端口。如果处于无法暴露 80 端口的家庭宽带环境，则需要使用 DNS 验证的方式。

04:29
配置多域名与重定向
若想让网站同时支持带 www 的子域名访问，只需在 DNS 记录中添加对应的 A 记录，并在 Caddy 配置中加入该子域名后重新加载即可。此外，为了防止配置 HTTPS 后用户直接通过 IP 地址访问网站，可以在 Caddyfile 中简单增加重定向规则。将访问 IP 地址的 80 和 443 端口的请求，重定向至目标域名并保留请求路径，从而使网站访问更加符合直觉和安全规范。

05:42
配置反向代理服务
反向代理主要为服务器端提供服务，可用于将家庭内网的服务安全地暴露在外网。在家庭服务器上安装 Caddy 后，由于家庭宽带通常无法使用 80 和 443 端口，需要在配置中自定义端口（如 5000），并将域名认证方式切换为 DNS。通过在配置中指定 DNS 提供商（如 Cloudflare）并填入对应的 API 密钥，再加上反向代理的内网服务地址，即可实现安全代理。同时，需安装相应的 DNS 插件、配置公网 IP 的 DNS 记录，并在路由器上进行端口转发，最终实现外网通过子域名加自定义端口安全访问内网服务。
