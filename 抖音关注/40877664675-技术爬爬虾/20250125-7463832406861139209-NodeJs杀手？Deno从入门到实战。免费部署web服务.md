Deno 是什么

安全的 JavaScript 运行时，能在浏览器之外（服务器端）跑 JS，这部分功能类似 Node.js。
底层用 Rust 编写，负责与操作系统相关的底层操作，带来更高的内存安全；执行 JS 的部分复用 Chrome 的 V8 引擎。
内置格式化、单元测试、打包等开发工具，包管理用 JSR（有核心开发者维护的标准库）。
提供类似 Vercel 的 Deno Deploy，可免费部署代码并分配域名，变成随时可访问的 Web 服务。

实操流程

官网按系统复制安装命令（Windows 用 PowerShell 执行），deno -V 验证版本。
新建文件夹后 deno init 生成三个文件：deno.json（主配置）、main.ts（入口）、main_test.ts（单元测试）。
VSCode 装官方 Deno 插件，deno run main.ts 直接跑 TS—— 不用额外装编译工具和配置；deno run dev 带 --watch 监控改动自动重启，可替代 nodemon。
实战小工具：读取 CSV → 解析成 JSON → 写入 MySQL。读文件需显式授权（--allow-read 或配置文件里声明），这是 Deno 权限系统的特色；CSV 解析用 JSR 上的 @std/csv 标准库，skipFirstRow 把首行当表头。
deno fmt 一条命令格式化代码，省掉 Prettier 和配置文件。
连 MySQL 时 JSR 上没找到高评分库，于是用 Deno 2.0 的新能力直接引入 NPM 包（deno add npm:mysql），改写成 ES 模块引用、补上环境变量和网络权限后连接成功，再把查询换成 insert，数据成功入库。
最后计划把项目改造成网页上传文件、解析入库的 Web 应用，并部署到 Deno Deploy（片尾展示了免费版与 20 美元 / 月付费版的额度对比）。

评论区在聊什么 讨论集中在 Deno、Bun 能否取代 Node.js：一派认为新运行时发展快、功能强；另一派认为 Node.js 生态和稳定性仍难撼动。也有不少人感慨前端技术迭代太快、积累容易过时，顺带调侃 Java 后端更省心。另有观众问 Deno 是否直接支持 TS 不用编译，回复是运行时内置了 TS 编译器、开发者无需手动配置，但底层仍会编译成 JS 再执行。
