画面里在演示什么

开头画面是 PyCharm 里的 main.py，作者先写了一个最简单的函数：

python
def do_this():     print("do this")


下方运行窗口的输出是：

plaintext

也就是说，原本只会打印 do this 的函数，被 “包” 了一层：调用前先打印 before fun do_this，执行完再打印 after fun。这正是装饰器最典型的效果 ——原函数一行没改，行为却多出了前后两段逻辑。

为什么需要它

如果很多函数都要加同样的 “前置 / 后置” 处理（日志、计时、权限校验、缓存等），逐个函数里复制代码既啰嗦又难维护。装饰器把这段公共逻辑抽出来，用 @装饰器名 挂在函数上方，就相当于 “把函数交给装饰器加工后再返回”。

理解的关键点

装饰器的本质是函数接收函数、返回函数，Python 里函数是一等对象，可以像变量一样传递。
@deco 写在 def f() 上方，等价于 f = deco(f)，所以被装饰后名字指向的其实是包装后的新函数。
通常配合 functools.wraps 保留原函数的名字和文档，避免调试时信息被覆盖。
