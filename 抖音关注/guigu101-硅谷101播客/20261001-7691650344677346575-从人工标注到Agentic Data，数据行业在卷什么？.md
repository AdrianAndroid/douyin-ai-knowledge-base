这是「硅谷 101」的一期圆桌对谈，主题是 AI 数据行业从人工标注转向 Agentic Data（智能体数据）。三位嘉宾（允中、一轴等）围绕 “数据行业在卷什么” 梳理了这条技术路线，最后在 “rubric 是否已经做到头” 上出现了分歧。

主线：数据需求的三级跳

预训练时代（2024 年前）：主流是人工标注的基础数据，靠海量数据做 pre-training。允中强调预训练依然重要，只是 “调数据配比” 这件事让人觉得无聊了。
推理与 RL 时代：o 系列模型出来后，大家发现 RL（强化学习）跑通了，兴趣迅速转向。RL 的关键是可验证信号—— 数学、代码最容易，选择题对错、算出数字就能判分。
Rubric 时代：医疗、金融、指令遵循这类领域有客观标答，但答案 “不结构化”，像历史论述题，人人写法不同，没法用 ABC 模式匹配。于是用 Rubric 评分细则：专家先把打分规则写下来，再让一个 “不太聪明的助教” 照着改卷。这就是核心概念 Weak-to-strong supervision（弱模型监督强模型）—— 成立条件是专家已把知识显式写出来。Mercor、Surge AI 的崛起就与专家 rubric 数据有关。
Agentic Data 时代：光验证聊天输出不够了，要在 Agent 环境里给工具、给沙盒，检查变量是否执行、数据库是否写入或删除、生成的文档图表是否合格。验证方式变得多样：程序化检查、rubric、人类偏好，目前尚无行业共识，各家流派不同（如 Terminal-Bench 走纯程序化路线）。

两位嘉宾的分歧

允中认为专家领域的 rubric 已被收集得比较干净，重心该转向 “环境”。
一轴看法相反：ALE 基准的初衷是把 vibe coding 的成功复制到 “vibe everything”——coding 发展快，正因为基准多且容易确定性验证，大家刷榜刷出了实打实的进步。所以要在更多工程领域建可客观打分的评测体系，最终做成真正的 “LAST EXAM”。他也承认各领域训练远未到头，很多东西还没被 rubric 表征出来。

一句话总结：数据行业从 “标答案” 卷到 “写评分规则”，再卷到 “造环境 + 造验证器”，而 rubric 的边界在哪，正是这期最有意思的争论点。想听哪一段的完整展开，比如 ALE 具体怎么设计题目和验证？
