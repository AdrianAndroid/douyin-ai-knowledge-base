这是「硅谷 101」在 2026 外滩大会现场录的一场圆桌讨论，主题是 Agent 成本战：用最强模型，还是用开源模型搭 “Agent 群组”？核心结论是行业正从 “无脑堆最强模型” 的 Token Maxing 转向 Token Efficient—— 在效果基本不掉的前提下把成本压下来。

讨论主线

趋势变化：年初大家用 OpenClaw、Hermes 这类 Agent 时，逻辑是 “哪个模型强用哪个”，硅谷不少公司因此疯狂烧 Token。现在中国开源模型能力上来了，加上 Agent 形态进化，出现了 “多种开源模型搭群组 + 少量最强模型兜底” 的混合用法，主要目的就是省 Token。
嘉宾一（郭靖）：内部当前仍用强模型，因为时间成本最贵；但他相信未来模型间能力差距缩小后会出现混合使用。他做过实验：强模型配一个中等规模模型融合使用，效果只降一点，成本能省三分之一甚至更多。他还提到垂直领域 “参数越小质量越高” 的现象，比如音乐生成，因为选用的数据质量更高。
对 2023 年 “垂直大模型” 失败的复盘：当时法律、医疗、财务大模型纷纷出现，后来被认为不 work，被基础模型吃掉。他的解释是：2023 年模型只有 “小学生” 水平，先补通识教育比灌专业知识更重要；而今天顶尖通用模型已在解哥德巴赫猜想，所以要反问 “你的领域真的需要这么高的智能吗”。他的做法是从强模型蒸馏出几十 B 级别的专用模型，在自己的任务上效果接近甚至更好，成本低得多。
嘉宾二（家俊）：分两种场景 —— 自己用选最先进模型；但落到公司业务（如给 “阿福” 做 memory 相关支持）就不能无脑用最新模型。他刚看了团队报的 9 月预算，认为 “太贵得砍”，透露至少要砍半、目标砍到原来的百分之二三十，但要贴着业务结果逐步来，不是一夜之间砍。他对效果有信心：很多具体任务不需要那么强的模型，一百多 B 的模型也挺能打，配上自有数据做 SFT 就够。

一个概念补充：这里的 “省钱” 不是简单换便宜模型，而是任务分层—— 把简单、重复、格式化的活儿交给小模型或蒸馏模型，把真正需要推理的难题留给旗舰模型。所以 “效果不掉” 的前提是你对自己的任务有清晰拆分和评测，否则省下的钱会以返工的形式还回去。评论区也有人补了类似理解：预算充足选最优解，预算有限就选 “蒸馏过” 的产品。

想继续聊的话，可以展开说说 “蒸馏 + SFT” 这套做法具体怎么落地，或者混合模型群组一般怎么分工。
