这是「硅谷 101 播客」的一期对谈片段，主题是 Token Maxing 到底值不值。嘉宾东旭（做分布式数据库的创业者）和主持人复盘了硅谷过去 8 个月 “无脑用最强模型” 的风潮，以及现在开始转向 “省着用” 的转折。

核心观点：贵，但值

东旭自述从去年 11 月开始，用 Opus 从 0 到 1 构建一个自己认为最复杂的软件 —— 分布式数据库。他的逻辑是：在任务极难、结果不确定时，无法精确评估最强模型和第二强模型的差距，benchmark 又容易刷榜，所以最优策略就是永远选最好的模型。代价是账单：一天烧掉四五百美金，而且这还是在已经买了 Claude Code Pro Max 订阅、额度用完后自掏腰包买超额用量的基础上。

但他认为 ROI 极高：那个软件公司销售期待已久，只要做到七八十分，一年可能多出 1000 万美金直接收入，而 “一个人三个月就做出来了”。

市场风向的转折

主持人提到两个信号：Uber 给员工发的 Token 额度后来因成本被收回，4 个月烧穿了全年预算；Stripe 内部大模型页面上直接弹提示，说 Opus 4.8 很贵，建议先用其他模型、不是所有任务都要用它。作者判断，现在讨论的重点已经从 “最大化用 Token” 变成 “更经济地用 Token”，背后还牵着一轮 Agent 形态的变革。

评论区有个补充视角：把这轮转变解释为从 token maxing 转向 token efficiency—— 前者想靠终端应用开发增量市场却没带来实际增量，后者转向优化中间路径、压缩成本。这属于网友的解读，不是视频原话。

值得注意的是，东旭的 “值” 有个前提：任务本身足够难、且产出能直接换成收入。对日常写脚本、改文案这类任务，同样的烧法未必划算 —— 这也是 “最强模型永远最优” 这个结论的边界。
