这是「硅谷 101 播客」的一段圆桌对谈剪辑，主题是 Computer Use 为什么又被带火、又卡在哪。标题里提到的 Astra 是引子，真正的落点是：身份验证成了这类产品商业化的瓶颈。

Computer Use 是什么 嘉宾 Bill 用一句话解释：模型靠 “看屏幕” 判断下一步该点哪里、输入什么，连续串起几十个动作完成一个任务。它和调 API 的区别是 —— 不用对方开接口、不用给密码，像人一样用鼠标键盘操作电脑，看到的是人看到的界面。

为什么又火了一波 作者观察到，此前行业押注 “所有工具都会开 API、都做 Agent 原生接入”，但现实是大量第三方 App（购物、旅行、Amazon 这类）不愿开放 API。于是大家又回到浏览器操作这条路，类似当年 Manus 先做 browser use、后来大家发现效率不高转回 API，如今有些场景绕不开，只能再回来。

一个真实用例 做 AI for Science 的嘉宾说，生物医学领域有很多几十年前的老软件，界面差、术语多，跨领域的人上手成本极高。用 Astra 的 Computer Use，靠简单 prompt 就能操作，还能顺便 “看它怎么用” 来学习。他推测这类模型把网上的教程、用户日志、反馈都学进去了，所以真的懂这些软件。

卡点：商家认不出 “你是你” 云端 browser use 目前靠商用机器加代理 IP 伪装成普通消费者，绕过商家的 IP 检查 —— 奢侈品网站早就开始屏蔽这类流量。商家真正担心的是：原本一个用户，现在变成二十个 Agent 不停比价、刷流量，流量入口被剥夺，得不偿失。

作者的破局判断 一是本地部署：30B 左右的小模型能跑在 AI Box、AI PC 上，浏览器操作发生在用户自己机器上，用的是本人 IP，就不必再 “伪装”。二是软硬件结合的身份确认：硬件属于这个用户，就能证明 Agent 是这个人的代表行为，商家才愿意开放 access。作者认为，这甚至可能倒逼 App 厂商改造 browser sandbox 的机制。

需要说明的是，以上都是嘉宾基于行业观察的判断和推测，不是已落地的结论；标题里的 GPT-6、Muse 属于话题标签，视频里并未展开技术细节。
