这是「硅谷 101」在外滩大会现场录的一场圆桌讨论，主题是 Token 经济学：智能、成本与算力的取舍。核心问题只有一个：Agent 用电脑，到底该走 API，还是直接操作图形界面？几位嘉宾给出的答案并不一致，但都指向同一个判断：这不是二选一，而是阶段问题。

讨论的起点 标题说 “有了 Astra，Token 又有新烧法”。Astra 指让 Agent 直接操作电脑、看屏幕点按钮的路线。用户反馈是 Token 成本太高，直接调 API 便宜得多；但让 Agent 操作电脑更省事，有时效果还更好。

三位嘉宾的观点

第一位（偏工程与商业视角）：看两件事。一是软件本身是否 AI native，旧软件不可能一夜全换，翻新要时间和成本，新技术替代旧技术历来是渐进过渡。二是 Token 效率分场景：个人使用容忍度高；但嵌进具体产品（他举了 “蚂蚁阿福”）时，每次回答都是商业决定，单次能带来的商业价值可能只有几分钱，成本敏感度和个人场景差三个数量级甚至更多。
亚峰：认为人机交互会大变，人和人最自然的交互就是对话加视觉，未来和 AI 也一样，对着界面 “点点点” 的方式短期有价值但长期偏落后。关于成本，他觉得当下更该突破智能上限—— 能做多难的事。Coding 之所以成立，是因为花的 Token 钱能和替代人力、提升效率的成本相比；如果模型能推进到科学发现、新材料新药，那时没人会在意 Token 多贵，衡量方式也该从 “花了多少 Token” 变成 “创造了多少价值”。
郭靖：用 API 还是 GUI 不是选择问题，是阶段问题，范式已定，剩下的是应用方怎么适配。他打了个比方：人眼有模式识别，看到的不是一堆 RGB 而是按钮、滚动条，因为大脑自动做了抽象；AI 没这个能力，让它看 GUI 等于让盲人看图。所以应该按 AI 的抽象方式设计应用，而不是让它模拟人类旧界面。

一个容易误解的点 “Agent 操作电脑” 并不等于更先进的形态。它更像是过渡期的兼容方案 —— 在软件还没为 AI 重做之前，用视觉模拟人类操作来兜底；真正的方向是软件原生暴露结构化接口。这也解释了为什么嘉宾们一边承认它短期有用，一边不认为它是终点。
