这是一节 Harness Engineering（驾驭工程） 的公开课导学，主讲人是九天 Hector。核心观点一句话：Agent = Model + Harness，模型负责生成，Harness 负责把生成过程约束成稳定结果。

为什么 Agent 一到真实任务就跑偏 作者认为问题不在模型强弱，而在缺少运行时约束。他用比喻说明：模型是发动机，Harness 是底盘、刹车和方向盘，没有后者，引擎越强越容易冲出赛道。他还梳理了三个阶段：提示工程（问好问题）→ 上下文工程（Agent Skills 按需加载）→ Harness Engineering（为多 Agent 营造带约束的环境）。

四大基础理论

文档即真相源：把技术栈、命令、规范、禁区写进 Agent 每次启动自动读取的文档（Claude 体系是 CLAUDE.md，OpenAI 体系是 AGENTS.md）。关键提醒是别写成几百行百科，主文件只留约百行目录，细则下沉到子文档按需跳转。
机械化结构约束：文档只是建议，Agent 会忽略。已知风险用 Hooks、脚本做确定性拦截；语义风险（如 “这行日志会泄露密钥”）交给另一个模型审查，形成双层防线。
反馈闭环：让每一步都有 “做对没做对” 的信号，覆盖工具调用、提交、上线、独立评审。核心原则是评估与生成分离—— 模型给自己打分总是过于宽容，所以把评审权交给独立 Agent。
系统熵减：AI 协作不会突然崩溃，而是缓慢腐烂：文档与实现脱节、绕过规范的捷径越积越多。要像垃圾回收一样常态化清理、压缩、强化高频错误。

落地案例：AI 内容审美对齐 作者团队把四条原则拧成一台机器：偏好单独存进 global learning.md（不与 Claude 自带记忆混放，一个管 “怎么干完”，一个管 “怎么干漂亮”）；用 Hooks 在真实场景中自动记录违规（伪造页面、要点不成段、乱用间隔号、术语不解释）；开工前按任务类型注入相关教训；每轮统计违反次数；最后做熵检，把不再犯的删掉、偶尔犯的压缩成一句、反复犯的加重语气。
