这是一场约 2 小时 22 分的技术公开课直播回放，主讲人带开发者从零上手 Kimi K3 模型和它自家的编程 Agent Kimi Code，最后用约 700 行提示、二十多轮迭代，做出一个工业级的多模态 PDF 检索问答系统。

上半场：K3 与 Kimi Code 入门

作者对 K3 的定位是：2.8 万亿参数的稀疏 MoE 开源模型，单次推理只激活约 104B，部署门槛不高；官方称其综合性能基本追平上一代顶尖闭源旗舰，视觉与前端能力是强项。API 兼容 OpenAI/Anthropic 格式，可直接接入 Claude Code、Codex 等主流 Agent。

两个他重点讲的能力：

12 项内置工具：单位换算、联网检索、记忆存取、base64 编解码、fetch、code runner 等，与模型绑定而非与某个 Agent 绑定，在线调用即可用。
动态工具筛选：工具多到几十上百个时，先由 searchtools 从海量工具里挑出相关的一小组再执行，代价是每次调用变成两轮。

Kimi Code 部分讲了安装登录、/init 生成项目级 AGENTS.md、斜杠命令、goals 长目标、子 Agent、MCP、Skills / 插件、-p 后台一次性任务等，并现场用它搭了一个简易聊天页面做演示。

下半场：多模态 PDF 检索项目

技术选型是：PaddleOCR 做版面分析与元素识别 → K3 做图片 / 表格 / 公式的语义增强与问答 → 向量检索 + BM25 关键词匹配 + LLM Wiki 知识库 + RRF 融合重排 → Deep Agents 作为运行时框架。作者解释了两个痛点：BM25 补 "细节信息"（如某个邮箱），LLM Wiki 补 "分散在多篇文档里的综合信息"，RRF 负责把多路结果合并排序。成品支持图文并茂回答、一键回溯引用片段、知识图谱展示和任务中心。

值得单独拎出的观点：作者反复强调，真正决定成败的不是那几百行提示词，而是开发者自己先想清楚架构、选型和验收标准；设置页、任务中心这类周边功能可以放手让模型 "自然生长"，而核心检索链路必须自己把关。评论区也有开发者呼应：卡住 AI 团队的不是模型能力，而是让 Agent 真正调通工具、接进业务流程。
