这是一场 LangChain 1.x 实战公开课的直播录屏，讲师用约 112 分钟把「从零搭一个企业级 Agent」的完整链路走了一遍，核心落点是那个最关键的 API：create_agent。

课程主线

讲师先交代背景：LangChain 仍是招聘要求里出现最多的 Agent 框架，过去九个月变化很大 —— 新增了开源可观测组件 LangFuse（LangSmith 的开源版）、把 deep agents 封装成 LangChain harness。技术栈分四层：底层 LangGraph（图计算）、中层 LangChain（最稳定、用得最多）、上层 deep agents（开箱即用的 harness）、旁挂 LangSmith / LangFuse 做监控。

四个实操模块

create_agent 与 Agent Loop：模型、tools 列表、system prompt 三个参数就构成一个 Agent。底层是「推理 — 调工具 — 回填结果 — 再判断」的循环，多步和并行调用都能自动处理（200 个工具以内基本没问题）。
记忆：模型本身没有对话记忆，靠挂载 InMemorySaver 这类 checkpointer 实现，用 thread_id 区分会话、做多用户隔离；也能换成 SQLite 持久化。历史记忆本质就是可读可改可删的文档列表，所以能实现「回滚」「时间旅行」。
Agentic RAG：传统 RAG 是固定流程检索；Agentic RAG 把 retriever 封装成一个 tool，靠 description 决定何时触发，检索后评估相关性、不达标就再检索，直到能回答原问题。作者认为这套流程简单但鲁棒性高，是当前最通用的方案。
LangFuse 可观测性：把 Agent 每次运行的调用链展开成树状 trace，定位失败节点、统计 token 消耗，支持本地 Docker 部署。

贯穿案例：团队用 LangChain 一比一复刻的「复反 OpenClaw」，演示了工具模块化、复杂 system prompt 组装、skill 加载和 markdown 长期记忆的实现方式。
