这条视频是博主「九天 Hector」的公开课上半场，主题是 Harness Engineering 最佳实践：Hermes Agent 快速入门实战。核心观点是：Hermes Agent 不是靠模型更聪明，而是靠一套工程约束，把每次干活的经验沉淀成记忆和 Skill，从而越用越顺手。

作者的核心判断

智能体 "难驾驭" 的根源：大模型输出本身有随机性、多步工具调用容易在某一步走偏、上下文有限导致 "遗忘" 和临近上限时的 "恐慌式收尾"、缺少人类审美对齐导致质量退化。所以作者认为关键不在模型，而在 "驾驭"。
作者把 Hermes Agent 定位为智能体本体（类似 OpenClaw、Claude Code），不是开发框架。它严格按 Harness Engineering 思路搭建，作者称其稳定性和迭代速度优于 OpenClaw，但上手门槛更高 —— 纯命令行交互，没有网页端。
作者也承认短板：生态不如 OpenClaw 丰富，多智能体（multi-agent）目前只有一个 sub agent 分发模式。

它凭什么 "越用越懂你"

四层记忆：memory.md（约 800 token 上限）、user.md（约 500 token，积累用户画像）、SQLite 全量历史对话检索、外部 provider 插件热插拔；外加一层记忆安全扫描（后门、不可见 Unicode 字符、凭证泄露检测）。记忆超限会自动摘要压缩。
Skill 自主进化：任务复杂、多次调用工具、遇报错或被用户纠正时，它会主动询问是否把这次流程固化成 Skill。作者演示了 "Python 项目安全审计"：首次跑约 6 分钟，生成 Skill 后第二次压到 300 秒内，还顺带完成了代码修复。
GEPA 进化引擎：把遗传算法与多目标优化用于提示词进化，每次只朝少数方向调整而非全量重写，最终合并仍需人工确认。

实操部分：Mac/Linux 用一行 curl 脚本安装（Windows 需先装 Linux 虚拟机），hermes doctor 自检，config set 配模型（演示用 DeepSeek），hermes chat -q 一次性下发任务、hermes chat 进交互模式；接飞书走 gateway + WebSocket，需在飞书开放平台建机器人、配 app id/secret、设 set home 频道；hermes cron create 做定时巡检。

评论区有个值得注意的分歧：一方认为经验沉淀成 Skill 后长期更省 token，另一方认为记忆系统要传完整上下文反而更耗 token。另外不少用户把 Hermes 和 Claude Code 定位成 "杂事与学习用 Hermes、写代码用 CC" 的组合，而非互相替代。
