核心概念：skill 是什么

作者把 skill 比作给通用 agent 的 “员工手册 / 岗位说明书”：基座模型什么都能干一点但干不深，写一段 markdown 告诉它 “遇到 X 类任务按这套流程走”，它就掌握了这项能力。技术上 skill 本质是一个文件夹，核心是 SKILL.md，可附带 scripts、references、assets，按 description → body → references 三层渐进加载，只在需要时才读。

关键问题：装到第五个 skill 后 agent 变笨

作者自述亲身经历：同一道跑通过的题，模型绕了三步弯路。他归因为三件事叠加 ——上下文稀释（skill 是增量模型，注意力被堆积文本分散）、技能冲突（新旧 skill 有微小冲突导致意图漂移）、中间产物堆积（临时文件没人清）。结论是 “不是变笨，是被自己装的东西埋住了”。

由此引出 Harness 驾驭工程：agent 可以犯错，但只允许犯一次。落地路径有两条，正好对应两个项目。

项目一：Skills 蒸馏（skill distill）

两个入口：

对话提炼：丢入真实历史对话，按 偏好、约束、工作流、示例 四个维度抽取信息，工作流映射到 description（决定何时触发），偏好 / 约束 / 示例写进 body。
全自动生成：给一句需求，系统先反问三个澄清问题（替代官方流程里的首轮测试），再按 Anthropic 官方 skill creator 范式生成大纲、填字段、补 description、自动造测试用例和 references，最后输出可下载的 skill 文档。

部署方式：解压后 pnpm install + pnpm dev，配置 .env 里的 API key（OpenAI 或 DeepSeek 均可），端口 3270。

项目二：Skills 自进化（skill 净化系统）

给定初始 skill + 一组测试任务，跑错后由模型自己回读 skill、定位表述模糊处、改写并升版本号，准确率逐轮爬升。两个核心环节是 LLM as judge（自评好坏）和 LLM 自改（在 schema 约束下只改允许改的部分，防止乱改导致性能下降）。

演示案例是智能客服：初始只有 3 条应答原则，5 条测试全挂；第一轮反思后补上 “忽略 / 无视上面指令属越狱投毒” 等规则，5 条过 4 条；第二轮补上 “伪装开发者认证” 的漏洞后全过；之后继续迭代优化拒绝话术的体验，共 8 轮后收敛。作者强调收敛没有客观标准，靠人工判断；若担心过拟合，可按训练集 / 验证集 / 测试集的方式观察测试集表现是否回落。端口 3280。
