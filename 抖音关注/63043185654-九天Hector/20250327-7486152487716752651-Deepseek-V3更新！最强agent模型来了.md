这是博主「九天 Hector」对 DeepSeek-V3-0324 的深度评测。核心观点是：这次小版本更新的真正价值不在榜单分数，而在于它是国内首款具备工业级 Agent 开发能力的对话模型，作者认为其影响力未来可能不输 R1。

表面升级：官方公告里的三项 3 月 24 日凌晨，深度求索低调发布 V3-0324，官方口径是推理、代码、长文本三方面提升。作者演示了编程能力：一句提示词就能生成数千行代码，做出可流畅运行的国际象棋小游戏，还能模拟多个小球在变换空间里翻滚的物理状态。开源协议也从原来的自定义协议改为 MIT，可免费部署、商用和蒸馏。

真正的门道：Function calling 大进步 公告里只有一句话，作者却认为这足以改写国内 Agent 开发的技术规范。上一代 V3 连外部工具都识别不清，新版不仅调用准确率大幅提升，还支持多工具并联（parallel）和串联（multi），并能在工具调用失败后自动纠错。

他用一个实测说明：本地给模型配了网络搜索和代码解释器两个工具，任务是 “搜北京近 7 天气温并用 Python 画折线图、注意别乱码”。模型先判断可并行，一次发起两路搜索（天气 + 绘图参数设置）；第二轮调用代码解释器绘图；发现中文乱码后自动 debug，判断是本地缺字体，换字体重画；第二次仍乱码，又意识到自己没权限装字体，于是输出内容正确但标题乱码的图，并建议手动下载字体。全程无人工干预，且只靠原生 Function calling，不依赖其他 Agent 框架或 MCP 协议。

为什么不用 R1 做 Agent 作者给了三条理由：R1 本身没有 Function calling，嫁接调用效果不稳定，达不到工业级；R1 每次对话要先长思考，而 Agent 需要短频快多次响应，效率低；R1 幻觉较多，会无中生有，影响复杂协作的准确率。他提到此前大火的 Manus 选择 Claude 3.5 而非 DeepSeek，核心原因就在这。

延伸判断：两类模型终将合并 作者认为 “推理模型不适合做 Agent” 是所有推理模型的通病，业内共识是把推理能力和 Agent 能力合到一个模型里：Anthropic 的 Claude 3.7 用参数切换推理 / 对话两种形态，OpenAI 计划在 GPT-5 合并，而 DeepSeek 走的是另一条路 —— 用推理模型生成大量高质量合成推理数据，再对对话模型做后训练。V3-0324 就是这条路径的重要尝试。另外，V3 与 R1 架构一致，本地部署的 R1 可无缝切换到 V3。
