这是一节近两小时的 MCP 实操公开课，主讲人九天 Hector 的核心主张是：不用写代码，靠复制配置文件就能把外部工具接进大模型，快速拼出智能体。视频按 “先认识工具、再逐个客户端上手” 的顺序展开，五个部分分别对应五类落地场景。

MCP（Model Context Protocol）本质是一套统一协议，解决的是 “大模型怎么调外部工具” 这件事。作者回顾：MCP 出现前，每个工具都要单独写函数、调 API、反复测试，复杂项目工作量极大；有了协议后，所有工具按同一套流程接入，像 “一把钥匙开所有锁”。体系里两个核心概念是客户端（Cursor、Cherry Studio 等运行环境）和服务器（一个个外部工具，可跑在云端或本地）。

五个部分的主线

工具从哪找：MCP 官方服务器合集、GitHub 上的 MCP 导航、Smithery、MCP 导航站等平台。作者特别推荐 Smithery 和官方合集，理由是维护好、接入文档详细；同时提醒 MCP 存在数据泄露风险，尽量从可信来源获取，别随便装来路不明的服务器。
Cursor：最早支持 MCP 的 AI 编程 IDE，0.48 版引入 Agent 模式，能自己编排多个 MCP 的调用顺序。演示了三个工具联动 ——Sequential Thinking 负责拆解和推理、Playwright 自动开浏览器抓信息、FileSystem 把结果写成 Markdown 存到本地，组合起来就是一个 “迷你版调研助手”。作者也点明前提：要用 Agent 模式顺畅调工具，得开 Pro 付费版，且模型本身能力要够强，弱模型接再多工具也调不明白。
Cherry Studio：轻量、面向个人的对话前端，内置 MCP 超市。加高德地图 MCP 变行程规划助手，加 Fetch MCP 变网页爬虫，加 GitHub MCP 变项目管理助手，是作者日常最常用的三个。演示中还遇到新版客户端缺依赖库的小 bug，需要手动把文件放进指定目录解决。
阿里云百炼：面向企业 / 开发者的在线平台，模型和 MCP 工具都是点选组装，不用碰配置文件。演示用千问 Max + 高德 MCP 做 “玉渊潭一日游” 规划，模型会先追问出发地、口味、预算再给方案；再接 Firecrawl 做网页信息提取。搭好后可一键发布成网页或 API，在代码里继续二次开发。
Open WebUI：开源、可完全离线部署的企业级对话终端，支持多用户和权限管理。它提出 MCPO 方案，把 MCP 通信封装成 OpenAPI 接口，用一行命令启动服务后在设置里挂载即可。作者还提到它内置的提示词模板能让本身没有 function calling 能力的模型（如 DeepSeek R1）也能调工具。

一个值得记住的机制：Cursor 里那段 JSON 配置看着像 “设置”，实际是一条下载并运行命令（npx 拉取指定包）。首次运行会自动把工具装到本地，之后直接用。不同客户端的 JSON 写法不一样，因为各家解析方式不同 —— 这也是 Smithery 要让你先选客户端和操作系统的原因。

评论区里，最高赞的观点是 “企业级方案不能本地部署就很难被接受”，这正好呼应视频里 Open WebUI 的定位；也有人追问 MCP 能否连线上数据库、Dify 是否支持，作者都给了肯定答复，但属于评论区的口头回应，视频正文没有展开演示。
