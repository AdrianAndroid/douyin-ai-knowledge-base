第一部分：架构长什么样

最小骨架：一个能调用工具的大模型 + 命令行（CMD/Bash）工具 + 一个 Agent Loop（调用工具→判断成败→成功退出、失败继续循环）。
五层架构：入口层（CLI、IDE、SDK）、运行时层（Agent Loop、REPL、Hook、状态管理）、引擎层（Query Engine、Compact 压缩）、工具能力层（内置工具、插件、MCP、Skill、多 Agent）、基础设施层（存储、缓存）。
代码分布：模型 API 交互约 8000 行、推理引擎约 4.6 万行、40 多个工具模块约 3 万行、终端 UI 约 2.5 万行，其余约 36 万行是工程基础设施。

第二部分：四个约束怎么落地

上下文管理：三层压缩 ——Micro Compact（几轮后删掉旧工具返回结果）、Auto Compact（接近阈值自动摘要，约 80%~92% 触发）、Manual Compact（斜杠命令手动触发）；再加四层防御，包括摘要 API 失败或 “压不下去” 时用 Snip 粗暴删减的 Reactive Compact。作者强调压缩必然有损、不可逆。
记忆管理：三层 ——Memory.md（永久记忆，用户不可改，内部自动维护）、Topic Files（按需索引加载）、Transcripts（历史会话只检索不加载）；另有 Auto Dream：空闲时 fork 一个 Agent 审查、巩固、删除记忆。用户自己写的 CLAUDE.md 最多只读前 500 行。
安全约束：五层管线 —— 字符串黑名单 → 正则匹配 → 白名单分类 → 独立大模型审查（不带上下文）→ 人类兜底；另有沙箱、断路器（连续 3 次或累计 20 次被拒即降权）、反蒸馏（识别机器人调用后注入假工具、造 “有毒” 训练数据）、双 AI 对抗审查。
成本约束：Sub Agents（子 Agent 当工具用，不共享上下文）与 Agent Teams（一主多队员、队员间不通信）两种多 Agent 模式；核心是共享 Token 经济学—— 把基础指令、工具定义等 “稳定区” 做成全局缓存，各 Agent 只叠加自己的 “动态区”，作者称额外加 5 个子 Agent 成本约等于 1 个 Agent、可降约 80%。

结尾是课程推广：三门付费课（Agent 开发实战、OpenClaw 实战、AI 编程实战），并提到源码里已埋了 “主动式 Agent”“Skill 渐进显示”“赛博宠物” 等未来功能。
