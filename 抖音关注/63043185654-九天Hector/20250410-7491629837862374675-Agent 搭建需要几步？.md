这条视频是博主九天 Hector讲 Agent 搭建的入门科普，以 “智能数据分析 Agent” 为例，把搭建拆成 Memory、Tools、Planning、Action 四个模块，最后还比较了单 Agent 与多 Agent 的取舍。

四个模块各自负责什么：

Memory（记忆）：不只是记住对话历史，还要关联本地知识库。比如你说 “统计某指标并和上个月对比”，模型本身不知道 “这个月” 是哪个月、指标对应哪些底层表，必须靠知识库把它翻译成 “查哪些表、做什么查找、输出什么结果”。作者认为 memory 实际是在引导模型完成复杂工作。
Tools（工具）：让模型能连 MySQL 取数，最好再配 Python 环境，方便取数后做清洗和可视化。简单 Agent 可能只有几个工具，复杂的会有几十个细分工具 —— 作者形容工具是 Agent 的 “手和脚”。
Planning（规划）：负责规划行动路径。作者拿 Manus 出圈举例，说它给了大家 “给个任务就能自己拆解、一步步完成” 的想象。比如做缺失值分析，要先想清楚在什么环境分析、现有哪些工具、怎么串成工作流，这很吃模型的推理能力，推理越强规划路径越优。
Action（执行 / 交互）：统一管理 Agent 与人、以及与其他 Agent 的交互。

关于多 Agent，作者提到可追溯到 2023 年底微软开源的对话式代理框架 AutoGen：创建多个 Agent 组成团队共同完成任务。但他强调，多 Agent 和 “单 Agent 调多个工具” 差别很大；拆多个 Agent 的真正原因是单一 Agent 保持统一身份设定和行为逻辑时指令跟随更强。实际开发中大多数情况仍以单 Agent 为主，底层模型不够稳定时，多 Agent 反而更不稳定。
