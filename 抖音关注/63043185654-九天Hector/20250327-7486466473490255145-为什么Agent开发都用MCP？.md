# 为什么Agent开发都用MCP？

核心结论：作者「九天 Hector」认为，大家用 MCP 主要看重的是它的生态，并不只是因为它能大幅减少自己的开发量。

视频从 Agent 开发的实际痛点讲起：大模型要干活，核心一步是连接外部工具。早期靠 OpenAI 提出的 function calling，它相当于一个 “中介”，一边接收大模型的请求，一边调用外部工具，再把结果返回给模型，由模型回答用户。OpenAI 当时举的例子包括查天气 API、发邮件、操作本地 MySQL 数据库。作者说，正是这个功能出现后，Agent 智能体的概念才逐渐兴起，如今它已是顶尖大模型普遍支持的基本范式。

但 function calling 的问题也很明显：代码量大，各家流程不统一。作者把 Agent 开发拆成 Tools、Planning、Action 等模块，其中 Planning 和 Tools 最费工，而且外部函数要支撑企业级运行和并发需求，本身就不容易设计。

MCP 的价值在于统一这套开发环节，作者概括为三层：底层统一协议，让大家按同一套规范协作；中间提供整套 SDK，把原来十几个手写步骤封装成几行代码；上层靠共享生态，一个人写好服务器，其他人直接复用，避免重复开发。

所以作者的判断是：MCP 确实能省一些开发量，但不会 “迅速减少多少”，真正吸引人的是拿来就能用的工具生态。这也是对 “MCP 是不是开发效率神器” 这一常见误解的修正。
