这是九天 Hector 的LangChain RAG 系统开发基础公开课，属于企业级智能体开发系列的第二阶段。整节课的主线是：先用一个能跑起来的极简 RAG 应用建立直观感受，再逐个拆解 LangChain 中 RAG 各环节的底层 API。

先看效果，再讲原理

作者开场演示了一个基于 LangChain + Streamlit 的完整前端：上传 PDF → 自动解析并提示切成几个片段 → 直接提问 “这个文档主要讲了哪些内容”，模型能准确总结出 LangChain 工具生态、功能与争议、现状与未来等章节。他特别说明，这个案例在早前的 LangChain 公开课里是 “终极案例”，放到 RAG 课里只能算入门小 demo。

核心流程只有四步

读取文档 → 切分 → 存储 → 封装成 Agent 问答。作者用 PyPDFLoader（底层是 PyPDF 库）读 PDF，用 RecursiveCharacterTextSplitter 按 chunk_size 递归切分，用 FAISS 存向量，再用 create_tool_calling_agent 把检索封装成工具。本地运行只需 streamlit run，端口 8501。

LangChain 把 RAG 拆成六个环节

source（数据源）、load（加载）、transform（切分）、embed（向量化）、store（存储）、retrieve（检索）。作者强调两个关键点：

load 环节要同时保留文本内容和结构信息。PDF 里的图片、公式、表格、标题层级都属于结构信息，否则无法判断 “图片和它下面的说明文字该不该放进同一个片段”。
切分环节能决定 RAG 效果的三四成。切得好后面还有救，切不好后面很难挽回。

五种切分方法

按句子 / 段落切、按固定长度切、滑动窗口切（相邻片段重叠若干字符保证语义完整）、递归切（在 chunk_size 阈值内不断拼接完整段落，超了就另起一段）、语义切（用模型判断边界）。作者认为递归法综合性能最好，也是 LangChain 的默认方法；语义切需要额外部署模型，速度慢，属于进阶内容。CharacterTextSplitter 靠 separator、chunk_size、chunk_overlap 三个参数就能组合出前三种切法，且 chunk_size 优先级弱于 separator。另有 MarkdownHeaderTextSplitter、CodeTextSplitter 按文档特有标识符切分。

Embedding 与向量库

在线可选 OpenAI text-embedding-3（small 1536 维、large 3072 维）和阿里百炼的 text-embedding-v4；开源推荐 BGE、MOSS、Nomic 三选一，中文多语言场景用 BGE-M3（约 1.2G，2G 显存即可跑）。作者用 t-SNE 降维把 “早睡早起是否健康” 的问题和若干句子画在二维平面上，直观展示语义相近的文本点会聚在一起。向量库部分讲了 Chroma 的 from_documents、similarity_search、similarity_search_with_score，以及用 k-means 聚类加速检索的原理 —— 先判断新向量属于哪个簇，再在簇内比对，避免和上万个向量逐一算余弦相似度。
