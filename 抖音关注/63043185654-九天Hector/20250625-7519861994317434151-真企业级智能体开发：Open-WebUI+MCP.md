这是「九天 Hector」公开课第五部分，主题是用 Open-WebUI + MCP 搭建企业级智能体。作者的核心观点是：相比主要面向个人的 Cherry Studio、偏编程的 Cursor 类工具，Open-WebUI 是真正面向企业的大模型对话前端，支持多用户管理、并发调度，还能完全离线部署，是快速把 MCP 工具组装成内部可用产品的最短路径。

作者讲的关键逻辑

MCPO 方案：Open-WebUI 在 4 月上旬官宣支持 MCP 调用，但没有直接裸连，而是提出 MCPO，把 MCP 的通信流程封装成 OpenAPI 接口，再通过 SSE 传输，目的是更稳定、更安全，降低原协议在信息传输上的漏洞风险。作者提到，Open-WebUI 团队最初对 MCP 是持反对态度的，认为当时过于狂热、底层有漏洞，后来在社区讨论后才接纳。
提示词模板兜底：Open-WebUI 内置一套提示词模板，能让本身没有 Function Calling 能力的模型（如 DeepSeek-R1）也完成结构化的工具调用。作者解释，Function Calling 是训练数据赋予的能力，没训过的模型只能靠提示词模板逼出结构化输出。
实操流程：用 Ollama 拉模型（推荐 Qwen3-32B 或 Gemma 3 27B，后者 4bit 量化约需 17G 显存、Function Calling 准确率高）→ pip 安装 Open-WebUI，设 HF_HUB_OFFLINE=1 后 open-webui serve，8080 端口访问、注册管理员 → 安装 uv 和 MCPO，用一行命令把某个 MCP 服务（演示的是查询时间的 server-time）跑在指定端口 → 在设置 - 工具里添加该端口地址并保存 → 对话页小扳手图标出现工具数，提问 “北京现在几点” 即自动触发调用，还能点开查看调用参数和返回结果。
远程部署：在服务器上跑时需用 SSH 隧道把 8080 和 MCP 服务端口都映射到本地。

评论区补充：有开发者表示自己团队此前的 Web 项目已用类似方式调用 MCP，作者点赞回应，属于经验分享而非官方确认；也有人吐槽演示界面 “挺丑”，还有人质疑是否在卖课、询问部署门槛和其他模型支持情况。

需要提醒的是，视频里 “4 月上旬官宣支持 MCP”“近 80k star” 等说法是作者当时的表述，版本迭代较快，实际部署前建议对照官方文档确认当前配置方式。
