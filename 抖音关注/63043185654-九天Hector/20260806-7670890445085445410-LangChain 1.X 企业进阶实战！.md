这是一场 LangChain 1.X 智能体开发实战公开课的直播录屏，讲师 “九天” 用近两小时，从底层 API 讲到企业级项目，核心是讲清 LangChain 1.x 这套技术体系怎么用、各层组件分别解决什么问题。

技术生态的四层结构

作者把 LangChain 体系分成四层：最底层是 LangGraph，负责图计算调度，日常开发很少直接碰；中间是 LangChain，也就是 create_agent 这一层，最稳定、使用面最广；上层是 Deep Agents，官方定位为 “开箱即用的 harness”，自带 to-do 拆解、虚拟文件系统、上下文自动压缩、bash 与文件操作等约束能力，作者形容它像可定制的 Claude Code；旁边还有观测平台 LangSmith，以及今年开源的本地版 LangFuse。作者特别提到，1.x 相比 0.x 的最大改动就是 create_agent 把模型、工具、system prompt 三要素封装进一个 API。

四个实操环节

Agent Loop：create_agent 的本质是 “推理→调工具→回传结果→再判断” 的循环，直到能回答用户问题为止。作者用订单查询、运费计算演示了单次和并行多工具调用，并说 200 个工具以内都能稳定识别。
记忆：大模型本身没有对话记忆，靠 InMemorySaver 挂载，再用 thread_id 区分会话，实现多轮对话和多用户隔离；换成 SQLite 就能持久化。作者还演示了查看、篡改、回滚历史快照。
Agentic RAG：关键做法是把检索器封装成一个带 description 的 tool，交给 agent 按需触发；检索结果不相关就再检索，直到能回答为止。作者认为这套流程简单但鲁棒性高，比堆复杂策略更实用。
LangFuse 可观测性：把每次运行的调用链路展开成树状结构，能看到每个节点的成功 / 失败、token 消耗和报错位置，解决 “agent 报错了却不知道错在哪” 的问题。
