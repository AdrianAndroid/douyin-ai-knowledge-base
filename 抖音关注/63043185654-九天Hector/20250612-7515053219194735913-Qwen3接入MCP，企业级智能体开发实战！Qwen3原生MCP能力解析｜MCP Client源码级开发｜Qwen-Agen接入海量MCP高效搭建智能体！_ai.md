这是一场由九天 Hector主讲的公开课录播，主题是把 Qwen3 接入 MCP 工具做智能体开发。核心观点很明确：所谓 Qwen3 的 “原生 MCP 能力”，底层其实就是它较强的 Function Calling 能力，MCP 只是更高层的封装协议。

内容主线

概念澄清：MCP 服务器约等于原来的 “外部函数”，客户端则是能调用这些工具的运行环境（如 Cherry Studio、Qwen-Agent）。MCP 的价值不在缩短单个工具开发时间，而在协议统一、能复用别人写好的工具。
能力边界：作者实测，0.6B/4B 这类小模型顶多撑 5—8 步工具调用；要跑十几到几十步的复杂流程，得用 32B 甚至 235B。官方演示用的正是 32B。
桌面端快速接入：以 Cherry Studio 为例，选 Ollama（11434 端口）或 vLLM（8000 端口）→ 加载本地 Qwen3 → 把模型类型勾成 “推理 + 工具” → 配置 get_weather 这类 MCP 服务器 → 对话即可。
手写 MCP 客户端：用 uv 建项目，装 httpx、openai、mcp 三个库，写 .env 存模型地址和 Key，再写几百行 main.py：读配置 → 启动各 MCP 服务器子进程 → 汇总所有工具成列表 → 转成 Qwen3 能识别的格式 → 循环执行 Function Calling，直到模型给出最终结果。
Qwen-Agent 框架版：用官方框架把同样的流程压缩成 “定义模型 → 定义 Agent → 挂工具 → 运行”。作者演示了接 SQLite MCP 写 SQL、加 code_interpreter 做数据分析、再叠加高德地图和 Firecrawl 爬虫，最后开 WebUI，复现了官方那段 “爬 GitHub 星标数据并画图” 的演示。
