这是博主九天 Hector的一期技术科普，主题是讲清 Function Calling（函数调用）—— 也就是让大模型能 “调用外部工具” 的那套机制，为什么它是做 Agent 的必修课。

核心观点 作者认为，Agent 之所以能查天气、订票、搜资料，关键不在于模型自己会做这些事，而在于它能把用户的自然语言翻译成一次工具调用请求。真正干活的是外部函数和工具 API，模型只负责 “判断该不该调、调哪个、传什么参数”。

视频里讲到的关键逻辑

难点一：意图触发，不是规则触发。画面里明确写了 “调用外部工具的行为是根据用户意图触发的，而不是根据规则触发的”。意思是不能靠关键词匹配，比如三个看起来相似的问题，模型要能分辨哪个需要调工具、哪个直接回答。
第二步：模型做意图识别。流程是：用户输入 → 大模型判断 → 若无关问题就直接回复；若需要工具，就输出对外部函数的调用请求 → 外部函数再去请求工具 API → 结果回传给模型组织成回答。
隐藏的特殊标记：模型看到的输入输出里其实带着 <begin_of_sentence>、<user>、<assistant> 这类特殊 token，它们帮模型区分 “谁在说话”，也是它能稳定输出结构化调用格式的基础。

一个容易误解的点 Function Calling 并不是模型真的执行了代码，它输出的只是一段结构化的调用意图（函数名 + 参数），执行权在应用侧。所以工具安不安全、参数可不可信，要靠开发者自己校验，这也是实际落地时最容易出问题的地方。

视频最后作者说，讲完这些就对 Function Calling 了解得比较深入了。想继续的话，可以聊聊实际写一个 Function Calling 时，函数描述（schema）该怎么写才不容易被模型误判。
