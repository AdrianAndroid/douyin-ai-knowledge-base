这是一场近 3 小时的技术公开课直播回放，主讲人 “九天” 围绕 Harness Engineering（驾驭工程） 展开，从理论讲到两个开源项目的实操。核心观点一句话：决定 Agent 好不好用的往往不是模型，而是模型外面那套约束与反馈机制，即 “Agent = Model + Harness”。

理论部分：四大基础原则

作者用 “马” 的比喻串起三代 AI 交互方式：提示词工程是 “跟马喊话”，上下文工程是 “给马看地图”，驾驭工程则是 “配好马鞍、缰绳和护栏”。他总结的四大原则是：

代码库即真相源：把项目信息写进 Agent 每次启动必读的文档（Claude 体系叫 CLAUDE.md，OpenAI 体系叫 AGENTS.md），但要做成 “地图” 而非 “百科”，主文件控制在百行左右，细则下沉到子目录按需加载。
机械化架构约束：文档只是建议，关键约束要升级为规则 —— 用钩子、脚本做确定性拦截，再用 “一个大模型审查另一个大模型” 兜住语义层面的风险，形成双层防线。
反馈闭环：让 Agent 每一步都拿到 “做对没做对” 的信号；关键原则是评估与生成分离，因为模型给自己打分总是过度宽容。
熵管理：代码和文档不会突然崩溃，而是缓慢腐烂（注释与实现脱节、无用功能堆积）。要像垃圾回收一样常态化扫描、压缩、清理。

实操部分：两个项目

Hermes Agent（Nous Research 开源）：作者称其为 “更工业化的 OpenClaw 版本”。亮点是四层记忆系统（memory.md、user.md、SQLite 全量检索、外部 provider 插件）和 Skill 自主生成与进化。演示中让它对自身项目做安全审计，首次跑了约 6 分钟，事后自动提议创建 python-project-security 技能；第二次同类任务时间压缩到 300 秒内，还顺带完成了部分修复。背后是名为 EGPA 的提示词进化引擎（遗传算法 + 多目标优化）。
GStack（YC 现任 CEO 陈嘉欣开源）：基于多个 Claude Code 实例组成的 agent swarm，内置 28 个 Skill、7 类角色（CEO 办公室、工程部、设计部、QA、安全官等），全部由 Markdown 文档定义。作者强调 “纯 Markdown 项目” 并不名不副实 —— 在 Agent 时代，一套好的身份提示和 Skill 本身就是值钱的数字资产。
