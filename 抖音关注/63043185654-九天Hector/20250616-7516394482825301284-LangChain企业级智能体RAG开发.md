这是一场关于 LangChain 家族 的公开课直播，主讲人先花约半小时讲清生态背景，再进入 Jupyter 实操，带大家用 DeepSeek 模型跑通 LangChain 的 Chain 搭建。核心观点是：LangChain 不是 "过时框架"，而是定位为 "模型能力增强器"—— 通过把提示词模板、模型、解析器等组件拼成一条条 Chain，来补强大模型本身做不好的事。

一、家族全景与历史脉络

作者梳理了 LangChain 生态：LangChain（基础）、LangGraph（把 Chain 拼成图结构，做 Multi-Agent）、LangSmith（运行监控与 Debug，需联网）、LangFlow（拖拽式低代码版，GitHub 约 72k stars，作者称是 Dify 的免费平替）、LangGraph Studio（图结构可视化前端）。他强调 LangGraph 是建立在 LangChain 之上的更高层封装，所以学习顺序应先 LangChain 后 LangGraph。

关于争议，作者的解释是：LangChain 诞生于 2022 年底 GPT-3.5 之前，当时模型是 "补全模型"，只会成语接龙式续写，所以需要大量工程化手段（few-shot、结构化输出、工具调用封装）来 "扶着" 模型干活。GPT-3.5/4 之后，function calling、JSON 输出等能力被模型原生集成，LangChain 一度显得臃肿冗余，招来 "太抽象、依赖多、文档跟不上" 的批评。0.3 版本后大幅精简，砍掉了为弱模型准备的旧功能，转向封装 RAG、Memory、Tools 等高频场景。

二、与其他框架的路线差异

作者认为 OpenAI Agents SDK 与谷歌 ADK 属于一派：尽量少写代码、两三行起一个 Agent，模型统一走 LiteLLM 接入；LangChain 则自成一派，为每个模型单独封装库（如 langchain-deepseek、langchain-google-genai），代价是要装一堆包，好处是接口统一、减少兼容性 bug、后期运行更稳。对 AutoGen（微软实验项目）和 CrewAI，作者评价不高，认为离生产落地有距离。

三、实操部分

环境为 Python 3.11+、langchain 0.3+、langchain-deepseek 0.13+。API Key 写入 .env，用 init_chat_model 创建模型对象，invoke 后返回 AIMessage（含 content 与 additional_kwargs）。随后演示了 Chain 的经典三段式：提示词模板 → 模型 → 输出解析器，用竖线 | 串联。示例包括 StrOutputParser 提取纯文本、BooleanOutputParser 把 yes/no 转成 true/false、结构化解析器抽取姓名年龄为 JSON；还演示了链嵌套（先写新闻稿、再抽时间地点事件）、用 RunnableLambda 插入自定义 debug 节点打印中间结果，最后用 Gradio 搭出流式对话前端（默认端口 7860）。
