先讲清 LLM Wiki 是什么

作者把传统 RAG 的三个短板说得很直白：固定长度切块会把句子、表格、操作步骤拦腰截断；语义相似不等于内容重要，容易捞回噪声；最关键的是 RAG “从不积累”，每次提问都从零开始，文档越多代价越高。

LLM Wiki 的思路正相反：平时就把资料持续整理成结构化 Wiki，提问时读的是已经消化好的词条，而不是原始材料。骨架分三层 ——raw（只读原始素材）、wiki（由模型逐句写成的互联词条）、stem（规定词条怎么组织、引用怎么建的操作手册）。日常只有三个动作：ingest 吸收、query 提问并回填新结论、audit 定期体检矛盾与孤立词条。作者强调它的精髓是 “复利”：新文档进来不是简单加一条，而是整合进已有网络、补交叉引用、标出冲突。

GBrain 做了什么

GBrain 是 YC 现任总裁 Garry Tan 开源的实现，作者称其为 LLM Wiki 目前最成熟的落地项目。核心能力包括：多渠道内容（会议转录、邮件、日程、通话记录）自动归集清洗成 Markdown；按人物、公司、事件三类固定实体建联成知识图谱；夜间 Dream Cycle 自动整理、标记过时信息、重算重要度；SkillFire 把出错经历沉淀成技能，让系统越用越准。作者提到官方数据：1.7 万多页文档、4000 多个人物档案，前五条召回率接近 100%。

实操与原理

部署依赖 Bun 和 pg_lite，需配置 OpenAI 或 OpenRouter 的 API Key 做 Embedding，流程是 clone 仓库、bun install、init 初始化、写.env.local，然后 import 入库、state 查看、search 检索，可用deps2这类参数向外扩散两层实体查询。检索侧是12 步混合检索：多路问题改写、向量 + 关键词双路召回、RRF 融合排序、图谱扩展、冲突校验、重排取 Top5 再拼接回答。入库侧则是四步 enrichment 流水线，做格式化、实体标注、时间线断言，再经 compare-choose 合并冲突信息。
