这是博主「卡尔的 AI 沃茨」对 AWS 纽约峰会 的解读，核心是两款产品：企业级 Agent 底座 Amazon Bedrock AgentCore，以及 AI 编程 IDE Kiro。作者的观点是：AI 编程正在从 “提示词 + 代码” 变成一套标准、可靠的生产系统。

AgentCore：给 Agent 配齐 “上岗装备”

作者把 AgentCore 比作 Agent 的 “肌肉骨架”，让 AI 从只能聊天变成能自动干活的员工，并逐个拆了 7 个模块：

Runtime：Agent 的操作系统，虚拟机加云计算内核，每个 Agent 有独立隔离环境，任务互不干扰，能扛 8 小时级的长任务。
Memory：短期对话记忆和长期任务记忆都能管，Agent 之间还能共享上下文。
Identity：给每个 Agent 发 “小工牌”，按最小权限规定它能访问哪些服务，降低幻觉带来的风险。
Code Interpreter：相当于给 Agent 配电脑，支持 Python、JS 等语言，运行在安全沙箱里，执行环境可自定义。
Browser Tool：充当 Agent 的 “眼睛 + 键鼠”，能自己填网页、抓信息，且不挑模型。
Gateway：把现有 API、Lambda、工具打包成 Agent 能调用的组件，由它自动挑选。
可观测性：全程记录 Agent 行为，出问题能溯源。作者那句 “不是怕出错，而是怕找不到错” 是这段的点睛。

Kiro：产品经理的 “梦中场景”

打开 Kiro 先看到的是 AI 对话框，而不是代码。Vibe code 模式是随口说一句 “做个评论系统” 就开写，文件前后对比的体验接近 Cursor；真正被作者看重的是 Spec 模式——AI 自动生成结构化需求文档、技术图纸和任务列表，等于用 AI 规范了整个开发流程。他的总结是：Kiro 负责 “写得快”，AgentCore 负责 “跑得稳”。

评论区补充了一个值得注意的点：不少人反馈 Cursor 频繁 retry、用不了，作者回复说 Cursor 会继承大模型 API 供应商的地区限制，所以问题未必出在 Cursor 本身；Kiro 的体验则褒贬不一，有人说停不下来，也有人说一个文档跑了三天。
