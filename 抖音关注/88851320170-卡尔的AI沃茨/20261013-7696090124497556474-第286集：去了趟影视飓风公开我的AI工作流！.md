这是博主「卡尔的 AI 沃茨」在影视飓风分享后，迭代了九个版本的 Agent + Skill 工作流教程，核心观点是：Skill 的价值在于把一类操作流程固定成一个动作，不用每次重新向模型解释，直接让模型执行就行。

四个阶段

找合适的 Skill：作者认为遇到问题先假设 “已经有人做出来了”。他以影视飓风 “一百台 Pocket、上百小时素材” 为例，先搜 “本地视频” 没结果，扩大搜 “视频” 也不满足，最后用 Agent 提示的 ffmpeg 关键词搜出 25 个结果。说明书看不懂时，就把下载量前五的 Skill 全丢给 Agent，让它对比优缺点、给出主选和辅助方案。
把经验打包成 Skill：没有现成方案时，先向 Agent 描述需求，让它结合本机环境给出低成本路线，再打包成 Skill。他的例子是本地剪辑：用 ffmpeg 定位裁剪、Whisper 本地转写带时间轴的文字稿，据此判断静音、重复和画面信息量，生成剪辑决策表，并分保守、平衡、激进三种模式。
组合成工作流：让 Agent 理解什么时候用哪个 Skill、按什么顺序串起来。
批量化、定时化：把稳定工作流跑成 “数字同事”。

实测结果：二十分钟素材按每 15 秒切帧、找 “画面出现三人及以上” 的片段，前后各留 15 秒输出，命中画面用蓝框标出；口播素材原片 176 秒，自动粗剪后剩 95 秒、24 段保留区间，每段都附了剪辑原因和时间点。

几个概念他讲得很直白：Agent 负责拆任务、派活，背后接大模型理解意图；MCP 负责连接本地 Agent 和外部工具；Skill 像手机 App，你只需知道拍照用相机，不用懂底层怎么写。他还纠正了一个误区：Skill 不是技术部门专属，内容、视觉、产品、运营、HR 都能用。

评论区里，有人问为什么在终端操作，作者回复主要是兼容性更高；也有人问 Skill 在哪封装、怎么用，他说可以在本机 Agent 打包后发到 GitHub。另有高赞评论认为难点在把 Skill 从 60 分打磨到 90 分，这属于个人经验，不是定论。
