核心思路

作者先吐槽：很多教程都教人 “二选一”，他自己也给 Codex 装了一堆前端 UI 设计的 skill，想追平 Claude 的效果，结果 “纯笑话”。他判断问题出在来回传递的上下文太多，人工拿不准该给对面发多少东西，于是换了个思路 —— 把两个 agent 放进同一个项目，让它们看到的信息完全一致，从根上消除信息损耗。

具体做法

在 Claude Code 3.0 新版本的项目里，先让云端 agent 写一份约 5000 字的执行计划；
再让 Claude 和 Codex 各自负责擅长的部分，比如 Codex 做大纲和演讲模式的 HTML PPT，Claude 负责设计；
用云端 agent 替代 “24 小时在线的机器”，没有 Mac mini 也能远程用上习惯的 agent；
手机、云端、电脑可以反复迭代开发计划，再和本地 agent 分工开发；
同一项目支持团队成员把各自电脑上的多个 agent 拉进来一起干活。

作者的观点

他认为 AI 编程的下一阶段不是比 “哪个 AI 更强”，而是把不同 agent 当同一个团队用，靠更好的工作流把它们串起来。他还提到，做设计的朋友自己养的 agent 做前端 “嘎嘎强”，用同样的 skill 自己的 agent 却没做出那个效果 —— 说明 agent 的调教积累也有差别。
