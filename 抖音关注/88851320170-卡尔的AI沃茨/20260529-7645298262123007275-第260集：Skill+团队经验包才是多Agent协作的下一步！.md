这条视频是博主「卡尔的 AI 沃茨」分享的一个观点：多 Agent 协作里，比共享 Skill 更重要的是共享项目经验。他一个月内跟十多个 AI 团队交流过工作流，发现大家囤了很多写文章、做 PPT、剪视频、写代码的 Skill，但真正能沉淀下来的项目并不多。

核心对比：Skill 与项目仓

Skill 回答的是 “我想让 Agent 会什么”，比如能力、工具、方法。
项目仓（他提到的是清华和面壁合作的 PilotDeck）回答的是 “我们已经做到哪一步”，包括对象、偏好、进度。

他用自己做的 HTML PPT 演讲模式举例：自己用着顺手，但新人用同一个 Skill 却做不出同样质量。原因是新人的 Agent 不知道这个 Skill 日常面对什么人、团队不喜欢什么排版和颜色、哪些术语要保留。

PilotDeck 的 Workspace 机制 一个项目一个仓，仓里装着团队协作所需的项目经验：项目文件、项目整体记忆、用到的所有 Skill、每天要跑的定时任务，以及通过 dream 提取的每次对话结构化信息。以前是 Agent 带着自己的记忆帮你干活，没法把 Agent 复制给别人；现在是项目自己带着完整上下文，新 Agent 打开就能一秒追上进度。

记忆与项目仓的区别 记忆解决的是 “下次对话还认不认识你这个人”；项目仓解决的是 “项目能不能从一个人迁移到另一个人、从一个 Agent 迁移到全新 Agent”。

成本考量 他提到团队跑 Agent 最怕大家都直接用最强模型，而项目仓的计费围绕项目来算，会按任务复杂度分派给不同模型。

最后他的结论是：更愿意把开发项目的过程沉淀下来，留下一个能被新人、新 Agent、新设备接手的项目经验，结尾还调侃了一句 “大宝，你学会了吗”。
