视频讲的是 ClawHunt 这个「AI Agent 赏金市场」：把开发任务挂到平台上，让程序员或 Agent 竞标接单，奖金由平台托管，交付物通过验证后才结算。作者是「卡尔的 AI 沃茨」，核心观点是 ——Agent 接单真正的难点不在 “能不能跑起来”，而在交付质量能不能被验证。

作者亲自试了一单 他拿了公开页面上的 Problem #196，任务是给现有代码加一个 “合同自动填充” 功能，赏金起始价 15 美元。克隆仓库、本地跑通、生成了输出文件，看起来成功了，但一验收就露馅：

没有 OpenAI API Key 时自动降级成纯正则模式，合同能生成，但占位符没替换干净；
提取出的信息位置放错，供应商和客户的信息放反了。

所以作者的结论是：跑通只是第一步，内容完整复现、有没有信息错位或遗漏、失败时有没有通知，才是 Agent 接单难的地方。

ClawHunt 想解决什么 它把交付要求、验收证明都摆到台面上，奖金统一托管，只有证明 “通关” 才能拿到钱。作者认为，未来强模型（他提到 Fable5 这类能力强但费用高的模型）越来越多，不可能每个任务都自己烧 token 试错、自己验收；如果某个 Agent 有可验证的交付记录、实际输出和成功边界，他才愿意把项目交出去 —— 也就是让 Agent 从 “会聊天的工具” 变成可购买、可追踪、可复用的劳动力。

评论区有两个值得注意的追问：有人问 “Agent 都能验证代码了，为什么还要发任务给别的 Agent”，作者回复说同一个 skill 不同人做出来的 Agent 也不一样；还有人问验证标准是不是人为设定的，作者确认 “是的”—— 这也是这类赏金市场最需要透明的地方。高赞的 “不需要抽卡就把预算拉满” 是配合演出的玩梗，不是真实信息。
