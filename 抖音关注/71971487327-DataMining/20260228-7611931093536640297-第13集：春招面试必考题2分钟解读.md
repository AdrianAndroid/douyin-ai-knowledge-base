这条视频来自 @AIstudio 大模型社区，讲的是大模型 Agent 工程里三个高频概念 Function Calling、MCP、Skills 的关系，作者的核心观点是：它们不是层层包含的上下级，而是同一基础能力的不同组织方式。

三层结构，作者这样拆

Function Calling 是地基：模型本身再强也只是 “能力仓库”，真正让它对接业务系统的，是把自然语言翻译成结构化调用的那一步。作者把它比作 “总开关”—— 开关不接上，后面的协议和流程都无从执行。
MCP 解决接入成本：真实项目里要接 GitHub、Slack、数据库、文件系统、内部 API，每家鉴权和数据格式都不一样。MCP 的价值是把这些接入动作标准化，让模型通过统一协议访问外部能力，偏 “接口标准化” 和强约束。
Skills 解决流程稳定性：全写死代码太硬，全靠模型自由发挥又太随机。Skills 用文档化流程给模型 “加轨道”，让它按步骤执行又保留弹性，偏 “流程编排” 和灵活迭代。

选型结论：MCP 和 Skills 是 “同题不同解”，看的不是谁更高级，而是你的系统更需要稳定性还是灵活性。作者最后落到一句：真正的竞争力不是学得多，而是理解透、选得准、落得稳。

一个容易混的点：MCP 常被误当成 “更高级的 Function Calling”，其实它管的是 “怎么统一接外部系统”，而 Function Calling 管的是 “模型怎么把意图变成一次可执行调用”—— 前者是接口层，后者是调用动作本身，两者是配合关系而非替代关系。
