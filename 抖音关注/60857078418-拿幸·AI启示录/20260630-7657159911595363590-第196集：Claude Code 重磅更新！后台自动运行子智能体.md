视频讲了什么

作者引用 Claude Code 创造者 Boris Cherny 的说法：下一版里子智能体默认后台跑。以前你盯着它读文件、跑测试、等输出，像陪一个能干但需要照看的实习生加班；以后你在前台聊方案，后台已经有一批智能体在查代码、改文件、跑测试、合并结果。

支撑这个变化的是三块已有能力：

Routines：把 prompt、代码仓库和连接器打包成自动化任务，按计划、API 调用或 GitHub 事件触发，跑在 Anthropic 云端，不用自己电脑一直开着 —— 相当于让 Claude Code 半夜自己看 backlog、审 PR。
子智能体：拥有独立上下文、独立权限和独立任务，适合处理会污染主对话的搜索日志、代码分析和实现工作；文档已区分前台（阻塞主对话）和后台（并发运行）。
动态工作流：根据任务动态写编排脚本，把工作拆给几十到上百个并行子智能体，交付前先自检。

作者的观点

作者认为，代码生成成本下降后，稀缺资源换了位置。他引用 Cursor 2026 春季开发者习惯报告：AI 生成改动不经单独手动 diff 就进入提交流程的比例，从年初约 7% 升到 5 月约 38%。他的结论不是 “程序员要没了”，而是岗位被拆开 —— 原型师、构建者、清理者、增长者、维护者，其中 清理者 最关键：删掉没用的东西、降复杂度、修性能、补安全洞。因为 AI 越能堆代码，系统复杂度累积越快，没人把关，效率提升就会变成 “技术债加速器”。
