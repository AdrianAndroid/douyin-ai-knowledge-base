为什么不能只靠 base model

作者把提升 LLM 能力分成两条路：横轴是换更强的底座模型（如 GPT-4 到 GPT-5），那是 OpenAI、Anthropic 这类公司的事，普通人既没算力也没钱；纵轴是在现有模型上叠加工程技术，也就是 augmenting LLM，这才是这堂课和这支视频讲的内容。教授列了四个底座模型的硬伤：

缺领域知识：公司内部资料、产品规格、农业病害这类小众数据集，模型根本不知道。
信息滞后：新词、新事件、新公司它都不认识。
难以控制：输出是概率性的，同一个 prompt 跑两次结果可能不同；客服场景里一会儿说能退费、一会儿说不能，公司就麻烦了。

前半段：强化单个模型的三个工具

Prompt engineering：教授认为它不会成为一个职业，而是像九九乘法表一样的基本功。好 prompt 要有角色、产出格式、重点三要素。他引用 BCG 的实验讲了三个现象：锯齿边界（AI 有些任务加分、有些拖后腿）、在方向盘前打瞌睡（不知道 AI 弱项还盲信它，结果比不用更差）、以及两种用法 ——Centaur（半人马式，整包委派）和 Cyborg（生化人式，高频来回协作）。重复性任务适合委派，需要判断和创意的任务适合来回磨。最关键的技巧是 prompt chaining：把复杂任务拆成多个 prompt，前一个的输出喂给下一个，比如投诉回信拆成 “抽问题→起草大纲→写完整回信”，每步可独立测试，也获得了可观测性。注意它和 chain of thought（让模型一步步想）不是一回事。

Fine-tuning：教授的态度是 “能不做就不做”，理由有四 —— 需要大量高质量标注数据、容易过拟合丢掉通用能力、时效性差（训两个月上线，下月新模型就把你打平）、而且多数场景用 prompt 就能达到类似效果，且 prompt 换模型后还能迁移。
