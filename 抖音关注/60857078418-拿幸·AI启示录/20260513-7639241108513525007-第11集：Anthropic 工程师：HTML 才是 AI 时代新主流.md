视频主旨：博主「AI 启示录」解读了 Anthropic Claude Code 团队工程师 塔里克・希帕尔（Thariq Shihipar）的观点：“HTML 是新的 Markdown”。他主张 AI 生成文档时改用 HTML，因为 HTML 能呈现布局、颜色和交互，而 Markdown 只能呈现纯文本。

事件起因 塔里克在 X 平台发表文章《HTML 的不合理有效性》，48 小时内获得 780 万阅读、1.2 万次转发、2 万多次收藏。他是 MIT 媒体实验室硕士、YC 创业者，加入 Anthropic 后设计了 Claude Code “信息不足时主动提问而非瞎猜” 的功能。他还开源了团队日常使用的 20 个 HTML 文件，按用途分为 9 类，浏览器打开即可使用。

三个代表性案例

代码审查：HTML 页面渲染完整 DIFF，每段改动旁有内联注释，并按严重程度着色（红 = 必须改、黄 = 建议、绿 = 写得好）；顶部有 “风险地图”，标出 6 个被改文件的风险等级；底部自动生成修复清单。作者的解释是：DIFF 本质是空间信息，Markdown 把它压成一维文字，HTML 能还原二维结构。
交互式教程：讲一致性哈希时，页面直接画出可交互的哈希环（4 个节点、32 个 key），点击增删节点就能实时看到 key 重新分配，旁边配迁移量对比表和悬停术语表。
用完即弃的编辑器：比如给 24 个工单排序，Claude 生成一个四列看板（现在 / 下一步 / 稍后 / 砍掉），卡片可拖拽，Claude 先预排序，人只做微调，最后点 “复制为 Markdown” 导出。微调提示词时也有左右对照编辑器，带变量高亮、样例实时渲染和 token 计数器。

核心机制：双向交互 HTML 文档从 “只读” 变成 “可操作”，滑块、旋钮、拖拽区都是活的，调完参数导出成文本再粘回 Claude Code，形成闭环：人下指令 → AI 生成 HTML 工具 → 人在工具里调整 → 结果导回 AI。作者强调，AI 生成的不再是文档，而是工具。

为什么 Markdown 不够用了 塔里克给出两个变化：一是 AI 输出越来越长，超过 100 行的 Markdown 他自己都读不下去；二是人越来越少亲手编辑文件，改内容靠对 Claude 说 “这里改一下”，Markdown 赖以立足的 “方便手打” 优势被架空。对 AI 来说，写 HTML 和写 Markdown 没本质区别，但人读 HTML 的体验好得多。他也承认 HTML 的代价：生成慢 2—4 倍、版本控制 diff 难看、更费 token，但反问 “你根本不会读的文档，省那点 token 有什么意义”。

争议与作者判断 网上分成 Markdown 党和 HTML 党。博主认为两边说的不是一回事：Markdown 党回答 “我们用什么写”，HTML 党回答 “我们给人看什么”。他列举 Markdown 阵营的论据：AGENTS.md 被 6 万多个开源项目采用、Linux 基金会成立 Agentic AI 基金会做开放标准、卡帕西的 LLM Wiki 靠一个 markdown 文件涨到近 5 万 star，以及同一篇博客 HTML 需 16180 token、Markdown 仅 3150 token（省 80%）。
