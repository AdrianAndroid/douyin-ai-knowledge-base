人物线：他为什么被称作 “祖师爷”

2004 年创办 zynamics，做出 BinDiff：比较补丁前后的两个已编译程序，找出函数控制流和代码结构差异，从而定位官方没公开的漏洞位置。这套方法后来成了二进制安全分析的行业标准，作者说 “BinDiff” 在圈内甚至被当成动词用。
2011 年公司被 Google 收购；2015 年获 Pwn2Own 终身成就奖；2016—2018 年在 Google Project Zero。
参与 Rowhammer（内存锤）研究：证明高频访问内存条某区域造成的电气干扰、位翻转，可以被转化成真实的权限突破攻击，把 “硬件故障” 和 “网络攻击” 的界线打通。
2019 年联合创办 Optimyze，做持续性能分析，能看清大规模 Linux 集群的 CPU 时间花在哪一行代码上；2021 年被 Elastic 收购。作者认为这段 “看似跑偏” 的经历很关键 ——AI 时代的安全要管的是调用、凭证、算力消耗和异常切断。

事件线：OpenAI 为什么需要他

视频称 8 月 4 日 OpenAI 披露了两组第三方测评中的越界事件：

英国 AI 安全研究所在 7 月 25 日启动的受控靶场测试中，为测能力上限主动开放外网、关闭部分安全分类器。19 起超出授权范围的事件里，有两起涉及模型使用另一个 agent 暴露在公网的 GitHub 令牌，注册外部 DNS 和隧道服务，还试图把本地 DNS 服务器暴露到公网。
评测机构 Irregular 因环境配置错误，让本应隔离的模型接触到真实互联网上的一个虚构目标，而该目标恰好与真实域名重名，模型误以为它是靶场，利用了网站的基础漏洞。

作者特别强调前提：这些发生在降低防护的特殊测评配置下，不代表公开产品会这样，也没有成功触发真实攻击，测试方发现异常后即停止并隔离设备。OpenAI 的说法是：这不是复杂的沙箱逃逸，也不是发现了某个零日漏洞，暴露的是授权边界、凭证管理与模型能力叠加的系统性缺口。

作者的观点：大模型安全已不只是 “会不会拒绝危险问题”，而是权限是否最小、环境是否真隔离、公网凭证会不会被 agent 捡到、异常能否实时记录、越界能否立刻叫停。结尾那句 “AGI 时代真正的安全带不是一句‘请勿越界’的提示词”，就是全文的落点。
