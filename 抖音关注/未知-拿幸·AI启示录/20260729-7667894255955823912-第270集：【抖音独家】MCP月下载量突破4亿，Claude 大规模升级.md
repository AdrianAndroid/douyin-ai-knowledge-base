这条视频讲的是 MCP 2026-07-28 这次协议大改：作者认为，AI 智能体的竞争重点正从 “模型有多强” 转向 “能不能稳定接入现实系统”，而 MCP 正在成为工具调用层的通用接口。

MCP 是什么、为什么重要 MCP（Model Context Protocol）不是新模型，也不是某个智能体产品，而是让 AI 应用访问文件、数据库、搜索引擎、企业系统的一套统一通信方式。作者用 “AI 时代的 USB-C” 来比喻它，解决的是 “N 个模型 × N 个工具” 的适配困境 —— 过去每接一个新模型或新软件，开发者都要重写一套连接层。视频提到，MCP 月度 SDK 下载量已破 4 亿次、年内增长约 4 倍，Claude 连接器目录里的 MCP 服务器超过 950 个。

这次更新的核心：无状态 旧版远程 MCP 采用带会话状态的双向通信，客户端要先握手，服务器要记住会话 ID 和连接状态。用户一多，扩容就麻烦：新请求可能落到没保存状态的机器上，开发者只能自己搞共享状态存储或维持长连接。新规范取消了初始化握手和 session id，每个请求自带协议版本、客户端身份和能力信息，可被任意实例独立处理，因此能自然跑在 Serverless 和边缘环境里。作者强调：状态没消失，只是从传输层挪到了明面上，用任务句柄显式传递，模型看得见、开发者能追踪、系统好审计。

三项配套能力

扩展框架：扩展以可选模块形式加能力，不改核心协议。首批包括 MCP Apps（在对话界面里直接渲染图表、表单、播放器、操作面板）和 Tasks（为几十分钟甚至几小时的长任务提供持久任务句柄、进度查询和中途输入）。
企业托管授权：管理员通过现有身份提供商统一部署连接器，员工按群组继承权限、首次登录自动完成连接。作者认为这对企业甚至比模型能力更重要 —— 企业真正担心的是 AI 能看见什么、能执行什么、出问题能否追责。
底层加固：多轮往返请求（高风险操作可返回 “需要输入” 再重新发起）、基于请求头的路由（网关、限流器、防火墙可直接按 MCP-method、MCP-name 路由计费）、缓存有效期与确定性排序、OAuth 授权加固。

作者特意保留的克制 他明确说，把 MCP 直接叫 “AI 时代的 HTTP” 要谨慎：HTTP 连接浏览器和服务器，MCP 连接模型、数据与工具，层级不同。更准确的说法是，它在竞争 “智能体工具调用层的事实标准”。另外，2025 年 12 月 Anthropic 已把 MCP 捐给 Linux 基金会旗下的 Agentic AI Foundation，转为厂商中立的开放治理，这也是这次重构能被称为 “行业基础设施” 的前提。

风险提醒 协议统一了调用方式，但保证不了每个工具都安全。当一个系统同时具备访问私密数据、接触不可信内容、向外发送信息三种能力时，模型可能被邮件或网页里的恶意指令诱导去泄露数据。作者的态度很清醒：MCP 不是让 AI 自动获得所有权限的通行证，协议越统一、工具越容易组合，最小权限、人工确认、网络隔离、沙盒和审计就越重要。

评论区里，不少人认可 Claude 在编码和工具调用上的表现，也觉得 MCP 让智能体接入工具省心了不少；也有人提到多平台 API 和 Key 管理依然繁琐。这些属于网友经验，不是作者原话。
