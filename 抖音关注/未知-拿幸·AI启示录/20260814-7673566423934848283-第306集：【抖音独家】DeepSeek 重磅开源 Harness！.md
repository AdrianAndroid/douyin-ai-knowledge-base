视频讲了什么

作者把 2026 年 8 月 13 日 DeepSeek 的两件事放在一起看：

V4 Pro 正式版上线 APP、Web 和 API，官方公布的 Terminal Bench 2.1 成绩为 87.9，并强化了 Codex 场景适配。
开源 Harness：官方没有把它定义成新模型，也不是简单的 API 客户端，而是 “智能体运行框架”。装好依赖后一条命令就能在本地启动 Web UI，采用开源许可证，目前处于开发者预览阶段，官方也提醒快速迭代中可能出现破坏兼容性的改动。

为什么 “大脑强” 不等于 “会干活”

作者用修 Bug 举例：模型要先理解需求、找文件、读代码、判断依赖、改文件、跑测试；测试失败还得看报错、重新定位、再改再跑。任务持续一小时，还要决定哪些历史信息保留、哪些压缩、何时搜索、何时申请权限、何时拆子 Agent、失败后是重规划还是沿原路修正。到这一步，决定结果的已经不只是模型智商，而是工具、上下文、状态、权限、执行和反馈循环这一整套系统 —— 也就是 Harness。作者引用 OpenAI 拆解 Codex 架构时的说法，指出 Harness 负责组织模型与工具之间的循环，这个循环可能持续几十甚至上百次。

“一切皆插件” 是什么意思

Harness 的核心理念是 everything is a plugin。作者强调这不是营销口号：模型适配器、工具注册系统、Session Log，甚至 Harness 本身都是插件。传统软件是 “固定核心 + 外围插件”，而它更像把整个 Agent 拆成可重组的零件 —— 模型、工具、文件系统、存储、子 Agent、上下文策略、运行循环都能换。作者打了个比方：大模型是大脑，工具是软件和设备，Harness 更接近一个 “完整岗位”，同一套系统里可以让不同 Agent 分别写代码、做研究、写作，改变的是模型被组织起来工作的方式。

另外，Harness 要求模型能看到的内容必须能从 Session Log 重建，用户消息、模型请求、工具调用与结果都进入可持久记录的事件流，因此任务可以恢复、分叉、回放和调试 —— 它留下的是完整工作轨迹，而不只是一段答案。

作者提醒的风险

作者明确说这是开发者预览版，极致开放也把风险推到前台：Agent 能自由调用 shell、读写文件、发网络请求和调子 Agent 时，权限隔离与审批就是底线，一次误删目录或向生产环境发请求可能不可逆。Session Log 只是事后审计，不能运行时阻断；预览版尚未提供细粒度沙箱、熔断和人工干预接口，落地前得自己搭安全护栏。长任务还有幻觉、工具超时、状态漂移、API 限流等暗礁，恢复粒度、回滚策略、上下文压缩是否鲁棒，文档里都还没有明确答案。

评论区补充

评论整体偏技术理性，主要分歧在 “自定义加载所有插件” 是否利好：一方认为这是厂商功能不完善、把体验压力推给用户，另一方认为这正是从拼参数转向拼系统、帮模型落地业务流程。也有人指出 harness 概念并非 DeepSeek 首创，很早就有；还有评论称 V4 Pro 正式版在 API 和客户端上出现了能力回退，这属于网友反馈，视频里没有涉及。

作者最后落到一句判断：模型决定智能的上限，Harness 决定这份智能有多少能真正被兑现，而安全边界和长任务鲁棒性是必须跨过的两道沟。
