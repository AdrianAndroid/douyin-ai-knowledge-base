这条视频是科技博主「拿幸・AI 启示录」对 DeepSeek 八天内两次更新的拆解，核心观点是：DeepSeek 真正在做的不是 “补一个多模态模型”，而是把 Agent 走向现实世界所需的感知、行动、记忆三块基建拼齐。

视频讲了什么

8 月 21 日：DeepSeek 上线首个面向 API 的视觉理解模型 V4-Flash-Vision-Exp。它并非另起炉灶的独立视觉模型，而是在原本擅长推理、写代码、跑 Agent 的 V4-Flash 上加了 “眼睛”，能直接读截图、图表、网页和现实画面。
8 月 13 日：先开放并开源了 Harness 开发者预览版，提供文件、Shell、搜索、沙箱、工作流等执行环境。官方定义是 “Agent = Model + Harness”，模型是大脑，Harness 是身体。
同期开放 Files API：图片先上传，再用 file_id 反复引用同一张设计稿或截图，支持 JPEG/PNG/GIF/WebP，单文件最高 64MiB。

作者的关键判断

作者认为，Agent 时代需要的视觉能力是 “看见之后能继续干活”，并非 “看懂一张猫的照片”。他举了两个例子：给一张网站截图，模型要拆出结构、字体层级、色值、间距和响应式布局，再自己写代码复刻；给一段 “浅烘单品豆、5 公斤起订、不要行业黑话” 的模糊需求，输出一份 11 页 B 端合作方案。

成本是重点。按一张图最高约 384 Token、V4-Flash 缓存未命中输入 1 元 / 百万 Token 粗略计算，1000 张图的纯图片输入约 0.384 元，闲时约 0.192 元。作者也明确提醒：这只是理论下限，实际还要加文字、Prompt、历史上下文、输出 Token 和存储开销，不能理解成 “1000 张图全处理完只要两毛”。真正的变化是设计逻辑：以前开发者要反复问 “这里真有必要让 AI 看一眼吗”，成本降下来后问题变成 “为什么不让它一直看”，视觉于是从高级能力变成 Agent 的常驻传感器。

需要留意的两点

一是视频里的跑分（Terminal Bench 2.1 得 83.9、DeepSWE 59.3、DSBench-Hard 63.6，多模态 Agent 能力接近 Opus-4.8）是作者引述的官方数据，属于厂商自测口径，不等同于第三方独立评测。二是评论区的主流讨论其实跑偏到了另一个话题：不少技术用户认为某大模型产品用户流失的主因是涨价太狠、编码场景竞争力不足，而非缺视觉模型；“没人用着急了才赶紧上线视觉模型” 这类说法被认为是想太多，不是共识。

作者最后落到一句话：竞争的问题从 “谁回答得更聪明”，变成 “谁能让模型看得见、记得住、用得起、真能把事做完”。
