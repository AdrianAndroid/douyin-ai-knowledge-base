这次更新到底改了什么

9 月 18 日，Claude Code 开始原生支持 AGENTS.md。这个文件可以理解成 “写给 AI 看的项目工作手册”，里面写明项目怎么编译、测试怎么跑、哪些代码别乱动、团队命名规范等。AI 进入陌生仓库时先读它，就不用从零摸索。

过去各家工具各用一套：Claude Code 认 CLAUDE.md，Codex 推 AGENTS.md，Cursor、GitHub Copilot、Gemini CLI 陆续跟进后者。同一个团队里有人用 Claude Code、有人用 Codex，就得维护两份内容相近的规则文件，改一处忘一处，几个 AI 各按各的版本干活。开发者此前只能靠软链接或 “导入” 语句绕路，现在这条路通了。

几个容易误解的细节：Claude Code 没有放弃 CLAUDE.md，也不是默认两份一起加载 —— 项目里有 CLAUDE.md 就优先用它；想两个都加载，需要在设置里改。另外官方说明该功能暂不覆盖 Bedrock、Vertex、Foundry 环境。所以严格说，这是一次兼容性更新。

为什么作者说 “不简单”

关键在于它基于一个叫 mods 的新机制实现，AGENTS.md 是第一个内置的 mod，源码已放进官方仓库。要理解 mods，得先懂 Harness（运行框架）：如果大模型是大脑，Harness 就是让大脑在真实环境里持续干活的那套东西 —— 管上下文、调工具、执行任务、协调模型与外部世界。以前能调的只是给 AI 什么指令、开放哪些工具；mods 往前走一步，让开发者能在框架允许的环节改变 AI 的工作方式，这次改的就是项目说明文件如何被发现、选择、加载。

作者还对比了 DeepSeek 的 Harness 开发者预览版：理念是 “一切皆插件”，模型、工具、技能、会话、沙箱、存储甚至界面都可组合替换，由 Cordis 内核管理挂载和依赖，GitHub 上约 22.9 万 Star，还提供了把 Claude Code 和 Codex 当子智能体调用的实现。两者路线不同：DeepSeek 从底层做开放模块化框架，胜在自由；Claude Code 在成熟产品里逐环节开放定制，胜在现成好用。

三层地基

作者把智能体时代的基础设施归为三层：AGENTS.md 解决 AI 怎么理解项目；MCP 解决 AI 怎么连接外部工具和数据；Harness 决定 AI 怎么把能力组织起来把事干完。2025 年 8 月 OpenAI 推出 AGENTS.md，同年 12 月 OpenAI、Anthropic 和 Block 共同发起 Linux 基金会旗下的 Agentic AI Foundation，分别贡献了 AGENTS.md、MCP 和 goose。
