这条视频是博主小哲讲 Agent 开发的一道面试题：Agent 长任务跑飞了怎么处理。核心结论是：光调大最大轮次没用，得把 “规划” 和 “执行” 拆成两个循环，再加漂移诊断。

问题场景 开头举例：一个引擎用 ReAct 跑 12 个接口的聚合任务，第 7 步发现第 3 步数据有误，回溯重做，结果越绕越远直至失控。作者认为这不是加轮次能救的。

ReAct 单循环为什么撑不住长任务 作者给出的经验区间是 8—12 步，超过后三个问题同时爆发：

规划专注度被稀释：每步都要重新理解状态、判断前几步数据对不对，注意力被实时推理吃掉（画面字幕：“规划能力就被实时推理耗尽了”）；
错误传导没有恢复机制：ReAct 里没有 “回退到规划层” 这个概念，只能硬着头皮走，或错几步才发现；
资源消耗无法预估：跑完 15 步才知道花了多少，生产环境里这本身就是风险。

解法：规划与执行分离 规划循环生成完整计划，执行循环逐步推进，每步结果回传给规划层验证；发现偏差就重规划，且重规划基于原始目标，而不是已经跑偏的上下文，形成 “规划 — 执行 — 验证 — 重规划” 的闭环。

漂移的量化诊断 作者提到五个轻量指标（状态一致性、目标持续得分、行动波动率、早期约束是否被静默丢弃、轨迹与初始计划的结构兼容性），只用规则和嵌入相似度就能算，不用额外训练。配套原则是 “除非有明确改进依据，否则保持当前方向”，避免在两个差不多的方案间反复摇摆。

两个常见坑

阈值设太松：漂移已发生却不告警，可能第 4 步就偏了，后面十几步全白跑；
震荡抑制太激进：该调整时死守旧计划，环境一变又重蹈覆辙。

最后作者给了面试答法：先分情况（单循环超 8—12 步会失效；引入 Plan-and-Execute 加五维诊断可保持对齐），再点出判断标准 —— 规划与执行之间有没有接口、有没有可量化指标、重规划是否基于原始目标。视频为 AIGC 内容，结尾有橱窗课程引导。
