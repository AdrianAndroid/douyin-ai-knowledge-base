这条视频是博主小哲（账号「小哲大模型 AI」）讲 AI 应用开发里的经典选型问题：Agent 和 Workflow 怎么选。他的核心观点是：不要只看 “灵活还是固定”，而要问一句 ——下一步由谁决定。

两者的本质区别在决策权

Workflow：节点、分支条件、流转顺序都提前定义好，由流程引擎按规则调度。大模型也能放进去，但只负责某个节点的具体活儿（比如提取信息、生成文本），整体怎么走仍由预设规则控制。
Agent：只给一个目标，由模型结合当前信息判断下一步要不要调工具、调哪个、要不要调整顺序、继续试还是提前结束。执行路径是运行时逐步长出来的。

作者特意纠正一个常见误解：Workflow 不是只能走直线，它同样能做 if-else 分支和条件判断，区别只在于分支规则是提前写死的，还是模型在执行中现场决定的。

各自适合什么

	优先用 Workflow	重点考虑 Agent
任务特征	步骤明确、规则稳定、变量少、看重结果一致性	目标清楚，但中间路径难以预知
典型例子	固定格式文档提取、结构化信息校验、固定模板通知、按序批量数据处理	开放式问题检索、多轮查询与交叉验证
好处	链路可复现、出错易定位到具体节点、消耗通常更低	能适应 “上一步结果改变下一步方向” 的不确定路径
代价	新情况出现就得加分支改配置，流程写太死一个节点卡住会拖累整条链路	模型可能判断错，多轮思考和工具调用增加耗时与 Token，输出有随机性

一半固定、一半要临时判断怎么办

作者的做法是拆开：外层用 Workflow 把控主流程（顺序明确、不能跳步、需要合规校验的部分），把中间需要根据已有信息深入查询、调整策略的子步骤交给 Agent，并给它划清任务边界。这样主流程可控，局部又有灵活空间。

选型时确认三件事：处理路径能不能提前列清楚；结果一致性要求有多高；执行中有多少判断必须依赖新信息。前两项强就选 Workflow，路径未知就选 Agent，两者并存就组合。

他最后强调的一句话挺关键：与其给整个系统贴一个 “Agent” 或 “Workflow” 的标签，不如想清楚每一部分的决策权该放在哪里—— 确定性流程牢牢管住，需要探索的范围划清楚。另外，视频里提到想系统学 Agent 开发可以看他的橱窗，属于作者自己的课程推广。

想接着聊的话，可以具体看看 “外层 Workflow + 内层 Agent” 这种混合架构在真实项目里怎么落地，比如 Agent 那一段的输入输出边界该怎么定。
