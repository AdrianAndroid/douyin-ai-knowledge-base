这是博主小哲讲 AI Agent 多轮对话上下文管理的技术解析视频，核心观点是：只把历史对话拼进 Prompt 解决不了问题，因为大模型 “懂了”，执行端（工具调用）没懂，真正需要的是同时管控生成端和执行端的整套体系。

作者先抛出的面试式追问 用户第一轮说 “查上海周三高铁票”，第二轮 “顺便订当天酒店”，第三轮 “到了后约客户会议”。如果每轮只拿当前这句话去提取工具参数，“到了之后” 就丢了时间、地点，直接变成无效调用。类似坑还有：说 “第二个帮我取消” 时补全参数容易搞错指代；说 “我改去广州了” 时系统还拿北京上下文去调机票酒店。

五类失效根源 工具调用指代丢失、参数补全错误、上下文冲突、状态信息冗余、性能成本失控（每轮完整补全 + 调用 + 重排，延迟和 Token 都涨）。

三层解法

状态管理层：维护结构化任务状态（任务域、关键实体、意图轨迹、已执行结果），而不是追加聊天文本。
工具调用层：调用前结合状态补全参数，再做可信度校验，低可信就向用户澄清，不硬调。
生成端上下文层：只放最近两三轮对话加执行结果，更早历史压缩成任务事实摘要写进系统提示词。
执行缓存层：同一任务域且实体未变，直接复用上轮结果；只有切换任务或实体变化才重新调用。

异常处理：任务切换用语义相似度检测并清空旧状态；用户说 “不是这个”“重新来” 就回退上一轮状态；设最大轮次和超时自动重置；监控多轮完成率、补全错误率、切换准确率、单轮调用成本。
