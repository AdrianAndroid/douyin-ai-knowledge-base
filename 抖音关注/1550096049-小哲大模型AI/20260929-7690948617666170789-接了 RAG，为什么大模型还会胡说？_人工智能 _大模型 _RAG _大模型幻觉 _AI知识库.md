这条视频是博主小哲讲的一个技术问题：为什么大模型接了 RAG 还是会胡说。他的核心观点是：RAG 只是缓解手段，不是根治方案，幻觉要按 “检索 —Prompt— 后校验” 全链路治理。

作者对幻觉的定性

作者认为幻觉的本质不是 “模型记错了”，而是大模型本质在做概率预测 —— 它只负责生成通顺的文本，不判断真假，只要概率上通顺，错的也照样自信输出。他把幻觉分成知识幻觉和推理幻觉两类。

为什么 RAG 治不全

作者举了企业客服的例子：知识库明明收录了最新规章制度，模型仍会篡改条款、编造不存在的流程，甚至新旧规则混着答。他列出四个 RAG 管不了的原因：召回片段冗余、冲突、老旧，模型会自己 “择优” 篡改；上下文过长导致注意力稀释，关键信息被淹没；模型推理能力有缺陷，拼接多条信息时逻辑错乱；Prompt 没有强制约束，模型自由发挥。

全链路治理三步

检索侧：多路召回加重排，过滤低分、无关、过期片段；清洗知识库脏数据、定时归档旧版本；精准分片避免语义断裂。
Prompt 强约束：强制只基于检索内容回答，无匹配资料就直接说 “无法解答”，并开启引用溯源、标注出处。
后校验：二次校验 Agent 核对答案与原文是否一致，关键数据、条款、编号用规则引擎校验，有错就拦截重生成。

落地避坑：别无脑堆知识库，冗余越多幻觉越重；超长文档必须分片过滤，禁止全文投喂；复杂业务开溯源方便人工校验；高精准场景禁止模型自由推理。

最后作者强调，幻觉无法 100% 根除，只能靠检索优化、Prompt 约束、事后校验和按需微调形成闭环 —— 这也是 “只会跑 Demo” 和 “真正落地 AI 项目” 的区别。视频开头提到橱窗有 Agent 开发系统课，属于作者的课程推广。

开场先问 “怎么彻底解决大模型幻觉”，指出很多人第一反应是上 RAG，但检索到正确内容后模型依然编造数据，引出底层成因和工程解法。

定义幻觉为无中生有、篡改事实、张冠李戴、编造数据，本质是模型按概率预测下一个字，只保证通顺不判断真假。

RAG 主要补真实私有知识、解决知识滞后和缺失，但召回冗余冲突、上下文过长、推理缺陷、Prompt 无约束这四类问题它管不了。

先做多路召回加重排、清洗脏数据、精准分片减少错误输入；再用 Prompt 锁死输出规则并强制溯源；最后用二次校验 Agent 加规则引擎拦截错误。

不堆知识库、不全文投喂、复杂业务开溯源、高精准场景禁自由推理；结论是幻觉无法根除，只能闭环持续降低。
