这是博主「小哲大模型 AI」讲的一道大模型面试题：Agent 和 Workflow 到底差在哪。他的核心观点是：判断标准不是 “有没有调用 API 或搜索工具”，而是谁握着方向盘—— 下一步行动的决定权在代码手里，就是 Workflow；在大模型手里，才是 Agent。

两种模式的差别

Workflow：像程序员提前画好的固定导航路线。比如 “调搜索接口→解析数据→丢给大模型生成回答”，第一步、第二步全在代码里写死。流程顺畅时没问题，一旦遇到预设外的情况（接口报错、数据格式变了），就会卡住报错。
Agent：只给大模型一个终极目标，让它自己边开边看、动态决策。

买咖啡的例子

Workflow 版：下楼→点冰美式→付钱拿走。结果咖啡店关门，系统直接卡在原地，因为预设步骤里没有 “关门了怎么办”。
Agent 版：目标只有 “老板必须喝到咖啡”。发现店关门后，它自己判断原计划行不通，掏出手机打开外卖软件，搜附近其他店、对比送达时间，挑一家半小时内能送到的下单。全程没人教过它 “关门该怎么处理”。

工程实践中的结论

作者认为大厂最成熟的做法不是二选一，而是 “混合双打”：用 Workflow 管住主流程的底线，保证可控和安全；在需要灵活探索的局部节点，放手让 Agent 发挥。

需要说明的是，这是作者为面试作答提炼的通俗框架，不是行业标准定义。严格来说，业界对 Agent 的界定还常涉及自主规划、记忆、多轮工具调用等特征，“决策权归属” 是其中最关键的一条，但并非唯一维度。视频结尾他留了个思考题：网购时遇到的自动回复机器人算 Workflow 还是 Agent？按他的标准，多数按固定话术树或关键词匹配的客服属于 Workflow，只有能自主判断该查订单、该转人工的才算 Agent。
