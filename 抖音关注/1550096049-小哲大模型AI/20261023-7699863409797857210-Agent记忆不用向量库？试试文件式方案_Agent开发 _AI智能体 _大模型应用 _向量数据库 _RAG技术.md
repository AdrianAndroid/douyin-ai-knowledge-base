视频主旨：博主「小哲」在讲一个反常识的 Agent 记忆方案：不一定要先上向量库、embedding 和 RAG，可以借鉴 Codex 的「文件式记忆」思路，用「摘要 + 文件检索」来管理 Agent 的长期记忆。

两种思路的对比

常见向量方案：把内容转成向量，查找时按语义相似度召回。
文件式记忆：像一本活页笔记本。每完成一段工作，就把重要内容提炼成摘要，按时间顺序整理；下次启动时先载入摘要，让 Agent 知道之前发生过什么，需要细节时再翻对应记录。核心是分层组织 + 按需读取。

作者拆的四步

决定记什么：技术栈规范、踩过的坑与修复办法、个人工作偏好。共同点是只需找回关键点，不必逐字复述整段对话。
两阶段异步处理：会话闲置一段时间后，先用轻量模型把对话提取成记忆片段，再用更强的模型把片段合并成规范记忆文件。整个过程在后台跑，不打断当前对话。
渐进式加载：高频摘要（约几千 Token）常驻上下文做概览；完整记忆靠关键词工具（视频里提到 grip）在 memory 文件里检索，返回较新的几个文件；更细的过程再调历史会话。高频常驻、低频按需，上下文不用塞全部历史。
动态记忆 + 静态指令：AGENTS.md 写开发者明确指定的项目规则，记忆文件存工作中整理出的信息，两者配合。

作者的判断与边界（这是他个人观点，不是行业定论）：先想清楚自己要召回什么，再选方案。要的是规范、修复要点、工作偏好这类关键要点，摘要式记忆加关键词检索更轻量，也更好控制上下文和 Token 用量；但它不能等同于逐字还原全部历史。向量库仍有用途，关键看任务是否真需要语义检索。

一个容易混淆的点：文件式方案靠关键词定位，向量方案靠语义相似度召回，前者对「说法不同但意思相近」的查询不敏感，这正是它适合「要点召回」而非「模糊语义搜索」的原因。
