这是博主小哲讲的一道 AI 面试题：多个 Agent 能否同时连接同一个 MCP Server 调用工具。他的核心结论是：不能简单回答 “能” 或 “不能”，答案取决于 MCP Server 的会话模式、有没有做连接池化、认证信息是否按 Agent 隔离。

默认情况：不行 Agent 调用 MCP 工具，本质是向 Server 发起一次会话连接，Server 会为这个会话维护工具列表、认证上下文和调用状态。默认是有状态单会话模式，一个会话正在执行工具调用时，另一个 Agent 再连进来会被拒绝或排队，提示 “会话正在使用中”，这就是典型的 MCP 会话冲突。

两种并发方案

无状态请求模式：每次工具调用独立处理，不依赖会话状态，适合高频调用，能避免状态互相污染，也避免长连接占满 Server 资源。
MCP 网关 + 连接池（作者认为更核心）：网关按会话 ID 或 Agent 身份，把请求路由到 Server 池里的不同实例，或给每个 Agent 分配独立会话，相当于在框架层做了连接隔离和负载均衡。新请求直接落到空闲实例，避免全部涌入单一 Server 排队。

最该警惕的隐患 如果没做会话隔离，却让多个 Agent 共用一个连接，认证信息就会串号：B 可能以 A 的身份调用只有 A 有权限的工具，越权了还不报错。这在多 Agent 共享工具池、统一 MCP 接入时特别容易出现。

面试怎么答 先分场景：默认单会话下，一个 Server 实例只服务一个 Agent 会话，其他连接排队；引入网关加连接池后，多 Agent 可并发调用，请求按会话 ID 或 Agent 身份精准分发。最后点出判断本质是三个条件：会话模式、连接池、认证隔离。
