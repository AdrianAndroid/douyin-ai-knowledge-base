这是博主「小哲」讲的一道大模型推理面试题：多 Agent 能不能共享 KV Cache。他的核心观点是，不能简单回答 “能” 或 “不能”，要分情况讨论 —— 默认独立推理时不能共享，但开启前缀缓存后可以共享相同前缀部分。

小哲把答案拆成三层：

1. 默认情况：不能 每个 Agent 推理时，都把完整上下文提交给推理引擎，引擎为这次请求单独分配 KV Cache 显存，记录每层 Attention 的 Key 和 Value。即使系统提示词一模一样，引擎也会分别算两遍，显存里存两份完全相同的缓存 —— 这就是最常见的浪费。

2. 开启前缀缓存：能共享相同前缀 框架提供前缀缓存开关，典型机制是 RadixAttention，用 Radix Tree 管理公共前缀，相同部分只算一次。前提是多个 Agent 共用同一套系统提示词和工具定义、Prompt 前缀对齐。这样新请求到达时直接命中缓存前缀，既不用重算系统提示词，也避免显存存多份副本。

3. 语义缓存：复用推理结果 这一层更进一步，把历史问答对按语义相似度索引，新请求先查缓存，命中就直接返回，不命中才走推理。作者说这相当于框架层面帮你做了一层结果复用。

最容易踩的坑：如果没做前缀对齐 —— 各 Agent 系统提示词顺序不同、工具定义格式不同 —— 缓存命中率会直接归零，甚至比不开缓存还慢。这类问题在 Multi-Agent 协作和批量任务里最常见。

所以面试的标准答法是：先讲默认独立推理下各自计算、各自存储，再讲开启前缀缓存后共享公共前缀，最后点出判断本质是看前缀是否对齐、框架有没有开前缀缓存、语义缓存有没有命中。
