这是博主小哲的一条 Agent 架构科普视频，主旨是：搭 Agent 系统没有唯一标准答案，选哪种架构取决于场景复杂度和需要的控制力。他先给出三个结论：架构没有统一标准；演进脉络大致是 Single-Agent → Multi-Agent 协作 → 基于图的 Workflow；做 AI Coding 或 Skill 系统方向，Router+Skill 目前是相对最佳实践。

七种架构逐个拆解

Single-Agent：一个大模型包揽全部，用户输入后由 LLM 思考、调工具、出结果，早期 ChatGPT 是代表。简单、便宜、延迟低，但任务一复杂就认知过载、上下文污染，只适合简单对话验证。
Reasoning（ReAct 类）：循环 “思考 — 行动 — 观察 — 再思考” 直到完成，链式推理完整、可解释性好；代价是 Token 消耗大、容易跑偏，不适合大规模工程化。
Plan-and-Execute：先规划再执行，Plan 阶段列出步骤一、二、三，Execute 阶段逐步落地。稳定性高，适合代码生成和长流程自动化，但计划一旦出错容易全盘崩溃，灵活性不如 ReAct。
Multi-Agent：顶层由协调分配系统统筹，下面 Planner、Executor 等角色 Agent 各司其职。任务拆解清晰、上下文污染低、可扩展，但成本高，适合流程一致性要求高的复杂行业场景。
Router+Skill：作者最推荐的一种，核心理念是 “不要让模型想，让模型选”—— 用户输入先经 IntentRouter 做意图识别，直接路由到对应 Skill 执行。稳定、可控、可缓存、易评估命中率；代价是 Skill 设计成本高，可能出现路由冲突。
Blackboard 黑板系统：多个 Agent 同时读写共享状态，由状态变化驱动执行，适合复杂协作，但状态管理重、出问题难追踪，LangGraph 这类工作流引擎和分布式系统常用。
Graph Workflow：基于有向无环图编排，支持条件分支、并行、回溯和重试，代表工具有 LangGraph、Temporal、n8n，是企业生产环境里最重也最稳妥的方案。

结尾他串起整条路径：Single-Agent 做简单验证、ReAct 做多步探索、Plan-and-Execute 做工程化、Multi-Agent 做协作、Router+Skill 做精准技能系统、Blackboard 做共享状态、Graph Workflow 用于生产，并强调 “不用一步到位，按业务复杂度选档位”。

一个值得补充的边界：视频里 “Router+Skill 是最佳实践” 是作者针对 AI Coding 场景的判断，不是通用结论。评论区就有从业者提到，制造业和跨境物流的流程自动化项目里，最稳定的往往不是最复杂的架构，而是工具调用加状态机这种务实方案 —— 这正好印证了作者自己说的 “没有最好的架构”。
