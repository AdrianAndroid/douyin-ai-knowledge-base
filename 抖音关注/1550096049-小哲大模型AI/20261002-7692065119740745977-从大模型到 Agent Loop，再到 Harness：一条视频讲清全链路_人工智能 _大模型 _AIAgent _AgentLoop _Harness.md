各环节怎么串起来

LLM：GPT、Claude、DeepSeek 都属于大语言模型，核心能力是 “接收输入、预测下一个内容”。关键限制是它只看这一次发给它的内容，所以不知道你的订单和退款规则，直接问 “能不能退款” 它答不了。
Token：模型读写文字的基本单位，由分词器切出来。作者强调1 个 Token 对应几个字没有固定数量——“退款” 可能是一个 Token，“2000” 可能被切成 “200” 和 “0”。粗略按 “一个汉字≈一个 Token” 估算可以，但算费用不能只数字数，要看分词器或直接读 API 返回的用量。它影响三件事：单次能读多少、一次调用花多少钱、对话太长时哪些内容要删或压缩。
Prompt 与 Context：Prompt 是主动交给模型的任务要求（比如 “你是售后助手，按公司规则判断，不要猜订单信息”）；Context 是这一次模型能看到的全部内容，包括系统提示词、历史消息、Tool 定义、临时加载的业务资料。所以 Prompt 只是 Context 的一部分：Prompt 说做什么，Context 决定能看到什么。
Tool 与 MCP：给模型一个 get_order 工具，传订单号返回商品类型、金额、签收信息。但模型不会真的进数据库，它只生成一个 ToolCall 表达意图，由应用去执行、再把结果塞回 Context。MCP 解决的是另一层问题：公司里客服 Agent、售后 Agent 都要查订单，不必每个项目重写一遍，MCP 提供统一的发现和调用方式。作者特意区分：Tool 是能力本身，MCP 是调用这套能力的标准。
Agent Loop：查完一次订单还不够，还要读退款规则、商品类型、签收时间、金额，信息不足就再调工具。这个 “判断 — 执行 — 拿结果 — 再判断” 的循环就是 Agent Loop，模型到这一步才从单次问答变成能持续完成任务的 Agent。
Skill：退款、退货、投诉规则全写进系统提示词会浪费 Context 也难维护，所以把退款审核单独做成一个 Skill，告诉 Agent 先查订单、再读规则、再按商品类型 / 签收时间 / 金额判断，金额超 2000 转人工。Tool 决定能做什么，Skill 决定这类任务该怎么做。

最后的结果演示：模型查到是普通手机、满足七天无理由，但金额超 3000，高于 2000 的免审核线，按 Skill 指引转人工处理，任务结束。
