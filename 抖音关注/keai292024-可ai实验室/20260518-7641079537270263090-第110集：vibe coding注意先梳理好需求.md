谁在说什么

画面是多人连麦的线上沙龙，主画面是一位戴粉色眼镜特效的女生。她提到自己已经走完 “上线自己的产品” 这条路，于是向另一位嘉宾提问：如果给刚接触 vibe coding、甚至没有技术背景的小伙伴一句建议或避坑指南，会说什么？

嘉宾的复盘（作者自述的教训）

他当初的做法是想起一个功能做一个功能，边做边加。
如果重做一遍，他会先把 “要做什么” 和整体架构跟 Claude Code 梳理清楚，再统一交给它执行，而不是中途今天想在这加一个、明天想在那加一个。
他踩过的具体坑：早期用 Cursor 加功能时，工具 “没那么聪明”，把本该共用一套代码的功能拆成了好几个页面，导致代码结构混乱。
后果是后期花了很多时间去审计特定功能、梳理逻辑、删掉冗余部分，相当于把数据重新汇总一遍。
结论：需求不提前想清楚、边做边加，特别容易堆出屎山代码。

怎么理解这条建议

它讲的不是工具技巧，而是 “需求先行” 的工程习惯：vibe coding 让写代码变快了，但需求含糊时，AI 会按每次的局部指令各自实现，重复逻辑和多余页面就越积越多，返工成本反而更高。所以先定架构和功能边界，再让 AI 批量落地，是这条视频真正想传达的方法。
