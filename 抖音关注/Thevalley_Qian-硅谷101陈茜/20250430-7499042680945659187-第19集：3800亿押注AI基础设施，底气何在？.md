这是「硅谷 101」陈茜对阿里云智能集团副总裁汪军华的专访，主题是阿里云宣布未来三年投入 3800 亿 押注 AI 基础设施，以及为什么敢在 “AI 应用元年” 下这么重的注。

核心判断：应用真的爆发了，但爆发点在推理侧

汪军华认为 2025 年与前两年明显不同：ToC 应用是病毒式爆发，ToB 是一单一单慢慢积累，但两边都在起量。他举的例子是千问 Qwen Chat 上线不到两个月，一个月流量涨了 3000%；同时训练客户在减少，绝大多数客户找阿里云是要做推理—— 跑通义千问、Qwen 32B、文生图模型，也包括 DeepSeek。他引用 Sam Altman “谁再有 10 万张卡我马上就买” 来说明 GPU 有多紧俏。

技术主线：范式从 “堆规模” 转向 “强化学习 + MoE”

训练时代：PAI 平台做了八九年，大模型起来后最大挑战是把万卡集群稳定高效地用起来，靠自动容错、自动容灾、高性能网络和存储，让用户一键拉起任务。
推理模型时代：不再靠堆数据堆参数，而是靠后训练强化学习把推理能力 “练” 出来。强化学习是 “训练 — 生成样本 — 打分 — 反馈更新权重” 的闭环，要把几个复杂系统连在一起，本身很脆弱，所以工程难度反而更高。
MoE 稀疏架构：初衷是每个 token 不必算全部 671B 参数，只激活三十几 B 就能保证效果。但要让硬件效率最大化，得做算子融合、计算与通信掩盖（通信时 GPU 仍在算）。

两个关键概念，视频专门做了解释

PD 分离：推理分 Prefill（并行处理输入 prompt）和 Decode（一个 token 一个 token 顺序生成）。推理模型的输出可能长达几万 token，按每秒 30 token 算要跑半小时，两者负载特性完全不同 ——P 是计算密集，D 是缓存密集，拆到不同硬件上跑才能提吞吐、降延迟。
KV Cache：注意力机制里每个词的 key（身份标签）和 value（内容）会被缓存下来，避免每生成一个新 token 都重算前文。过去是单请求内复用，现在做成全局共享，不同请求的相同前缀也能命中。汪军华给出的数字是：每天千万级请求下，KV Cache 利用率能提升约十倍，从百分之几到百分之几十，相当于 GPU 需求降一个数量级。
