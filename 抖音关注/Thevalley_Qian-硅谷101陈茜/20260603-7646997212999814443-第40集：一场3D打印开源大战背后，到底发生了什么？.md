这条视频来自 硅谷 101（陈茜），讲的是 拓竹科技（Bambu Lab） 在海外卷入的一场开源舆论风波：一件原本属于技术层面的分歧，最后演变成 “大厂霸凌独立开发者” 的全球舆论战。

事件经过

拓竹被称为 “3D 打印界苹果”，2022 年中才进入海外市场，2023 年就成为全球桌面级 3D 打印机出货量第一的品牌，靠的是稳定性和性价比。
3D 打印离不开切片软件，它决定每一层怎么走、打多快。拓竹有官方软件 Bambu Studio，但极客圈更常用 PrusaSlicer、OrcaSlicer 等第三方工具。
2025 年初，拓竹引入授权与认证机制：本地模式和开发者模式保留，但想通过云端控制打印机，必须走官方认证路径。
今年四月，波兰开发者 Pawel Jarczak 发布了一个 OrcaSlicer 分叉版本，试图绕过认证、继续使用部分云端功能。拓竹通过 Reddit 私信联系他，指出这可能涉及非授权使用其服务体系和认证机制，并提示法律与合规风险。
几番交涉后，开发者主动下架项目，但公开表示自己被当成 “罪犯” 审问。这句话点燃了海外社区：头部科技博主声援、捐款造势，被删代码被全网复刻，开源组织 SFC 介入并发起 25 万美元筹款，竞争对手 Prusa 顺势发声，媒体跟进。

争议根源

3D 打印行业本身是从开源文化里长出来的，圈内默认价值观是 “能改、能修、能自己控制设备”。而 Bambu Studio 是 PrusaSlicer 的分叉，PrusaSlicer 又源自 Slic3r，三者都采用 AGPL-3.0 协议。开发者因此认为：公开的 AGPL 源码，任何人都可以拿走修改和分发。

拓竹的回应是：交涉重点在于开发者冒充官方攻击私有云服务，并非反对开源；而且这次事件一度造成服务中断，影响大量用户日常使用。

关键判断

作者认为这不是简单的 “违规” 或 “没违规”。The Verge 采访的长期研究开源协议的律师 Kyle Mitchell 指出，AGPL 在云服务时代存在模糊地带 —— 云端服务、设备连接服务算不算必须公开的代码范围，本身就有争议。另外，公开 GitHub 仓库的 git 审计显示，拓竹在基于开源项目开发 Bambu Studio 之后，也向切片软件生态回馈了大量代码和功能，后来被多个第三方项目继承使用。

所以本质是开源边界该划在哪里的辩论：极客社区在意 “自由、控制”，普通用户关注 “稳定、简单”。拓竹越想把 3D 打印从极客工具推向大众消费电子（比如手机控机），就越要面对远程安全和服务稳定性问题，也就越容易和原有开源文化摩擦。目前各方都未真正提起诉讼，法律上尚无定论。

评论区也偏技术理性，主流观点认为云端服务是公司自己的服务器资源，本地或局域网使用不该被指责；也有人补充 AGPL 可以通过购买商业许可实现闭源商用；少数派则强调拓竹 FDM 机型的价格和性能贡献不该被开源道德一票否决。

视频最后落到一个更大的观察：公司出海规模小时，大家只看产品便不便宜、功能强不强；成为行业头部后，就会被放进社群文化、行业规则和舆论认知的复杂体系里审视，如何在技术、商业安全和舆论之间找平衡，是必修课。
