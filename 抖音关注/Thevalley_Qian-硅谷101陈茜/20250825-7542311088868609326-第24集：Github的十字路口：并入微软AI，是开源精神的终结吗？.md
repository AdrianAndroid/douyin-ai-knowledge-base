这是「硅谷 101」的 101Weekly 节目，特约研究员 Yiwen 讲的是 GitHub 并入微软 AI 体系这件事：CEO Thomas Dohmke 卸任后，微软不再任命新 CEO，而是让 GitHub 完全融入今年 1 月成立的 CoreAI 部门。作者的核心判断是：GitHub 的独立时代落幕，但它作为全球最大开发者社区的地位短期内难以被替代。

事件本身

8 月 11 日，Thomas Dohmke 用德语发博客告别，说 “创业初心始终牵动着我”，要再次创业 —— 和 2021 年前任 CEO Nat Friedman 离职时的说法几乎一样。
微软 CoreAI 主管 Jay Parikh 宣布两项调整：微软开发者部门主管 Julia Liuson 监督 GitHub 的营收、工程与支持；GitHub 首席产品官 Mario Rodriguez 向微软 AI 平台副总裁 Asha Sharma 汇报。
背景是 2018 年微软以 75 亿美元收购 GitHub，此后七年一直保持子公司独立运营，没出现强绑 Azure、激进收费或广告。

为什么走这步棋 作者梳理了 GitHub 的来路：2005 年 Linus 写 Git，2007 年 Chris Wanstrath 与 Tom Preston-Werner 在旧金山酒吧起意，2008 年推出 Beta 版，靠免费公共仓库＋社交化界面赢得开源社区。2021 年 GitHub 推出 Copilot，2022 年 6 月向个人用户开放，比 GPT-3.5 还早几个月，几个月破百万用户。但如今 Cursor、Windsurf、Trae 等产品抢走份额，Copilot 虽有 2000 万用户，优势已被稀释。所以微软的意图是把 GitHub 从 “代码托管平台” 转成 “AI 开发工具核心”，让 Copilot 直接对接 AI 负责人，统一资源投入；三个月前还宣布开源 VS Code 中的 Copilot 以抢回市场。

开发者的两层担忧 一是商业决策会更贴近 Azure 和微软 AI 战略，免费功能可能付费化；二是上传的代码是否会被用于训练微软的 AI。作者还举了 Reddit 的例子：AI 时代数据成了金矿，官方收紧 API，担心 GitHub 也走向 “代码不再能百分之百自由访问”。

评论区补充了几个角度：高赞观点认为开源项目实际成了大厂免费的 AI 训练数据源；也有人指出维基百科数据量只够做基础数据；还有人强调 Git 是工具、GitHub 是平台，两者别混；以及 “真惹众怒就另开项目” 的社区韧性论。

作者最后的态度比较克制：组织架构对用户和竞争对手意义有限，GitHub 的价值不在于属于谁，而在于能否继续做开发者的共同家园。
