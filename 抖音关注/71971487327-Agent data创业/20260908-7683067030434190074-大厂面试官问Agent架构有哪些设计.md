这条视频是 AgentAlpha 创客星球 讲的一道大厂面试题：被问 “你们 Agent 系统架构怎么设计的” 时，别只背 ReAct、多智能体、LangChain 这些名词，面试官真正想听的是你在延迟、成本、可靠性三个约束下做了什么取舍。作者把 Agent 架构分成五层，主线是 “把确定性从模型手里一步步抢回给工程”。

五层架构

单 Agent 循环（ReAct）：最小定义是 “模型看上下文→决定动作→执行工具→结果回填→再决策” 的循环，单次 API 调用不算 Agent。真正致命的是三个故障模式：上下文腐烂（工具返回几万 token 日志后忘了原始指令）、无界循环（两步之间反复横跳烧预算）、错误累积（第三步的幻觉变成第四步的输入事实）。对策是上下文压缩摘要、最大步数硬中断、工具返回结果结构化裁剪，做到这三点能覆盖六七成真实需求。
规划与执行分离：任务超过二十步，单循环的规划能力会崩塌。解法是 planner 产出显式计划对象、executor 逐步执行、每步后按观察结果重规划。作者强调没有 replan 机制的 Plan-and-Execute 是 “上个时代的古董”，因为计划是在信息最不充分的时刻做出的。瓶颈在规划器本身，业界妥协方案是分层规划：顶层粗粒度里程碑，子目标再展开。
Router + Skill 意图路由：业务是上百种明确需求时，用分类器、小模型甚至规则把输入路由到确定性技能函数。价值在于把系统切成可独立测试、评估、回滚的模块。但作者提醒面试时要主动说它的 “阿喀琉斯之踵”：路由错误是系统性故障第一大来源，分类准确率决定系统天花板，生产环境必须配置信度兜底，宁可转人工也不硬路由。
共享状态多智能体（黑板架构）：检索、写代码、审查等 Agent 围绕一个带 Schema 的共享状态对象协作，读状态干活、写回状态，由控制逻辑决定下一个激活谁。LangGraph 的 State Graph 本质就是一个类型化黑板。核心收益是上下文隔离 —— 审查 Agent 不用看两万字原始文档，只看提炼结论，直接解决第一层的上下文腐烂。代价是并发写冲突和状态溯源，所以 checkpoint 成了一等公民。
DAG 企业级终极形态：流程拓扑写死在代码里，模型只在节点内部有有限自主权，条件分支、并行、失败重试、超时降级、人工审批全由编排引擎保证。延迟和成本可控，因为每次模型调用次数可计算、可审计。作者引用 Anthropic 的原则 “能用 workflow 就别上 agent”，选型标准只有一条：路径是否可预测。

一句话总结：ReAct 是把一切交给模型，DAG 是把一切交给工程，中间三层是在两者之间找平衡点；架构选型的本质是 “这个业务里模型配拥有多少自由度”，自由度每多一分，可信度就少一分。
