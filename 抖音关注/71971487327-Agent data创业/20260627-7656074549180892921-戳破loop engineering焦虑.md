这条视频来自 AgentAlpha 创客星球，属于「LOOP」系列第 03 期。作者的核心观点是：Loop Engineering 并不是一项全新的技术，而是把 “让 Agent 持续干活” 这件事系统化，不必因为 FOMO（错失恐惧）而焦虑。

作者对 Loop Engineering 的定义 作者先讲了一个常见场景：让 Agent 干活，它经常干到一半就偷懒，测试没过也敢说完成。以前靠人像 “奴隶主拿鞭子” 一样盯着，Harness Engineering 解决的就是 “别让它跑偏”；而 Loop Engineering 想解决的是 “让马儿自己去干活”。

它和普通 Agent Engineering 的区别

普通 Agent Engineering：解决一轮任务里怎么想、怎么做、怎么调工具，属于模型内部怎么跑。
Loop Engineering：解决更宏大的一层—— 什么时候开始、谁判断这一轮过没过、没过要不要继续、继续几次、什么时候停、什么时候交还给人，属于系统整体怎么管。

三层工程的分工 作者用一句话区分：上下文工程决定 “这一轮看什么”，Harness 工程决定 “在什么环境干活”，Loop 决定 “一轮轮任务怎么串起来”。所以 Loop 不是替代前两者，而是把它们组织进一个能持续推进的闭环。

不是所有任务都值得做 Loop 作者给出五个前提：任务会反复发生、目标清楚、结果能验证、失败成本可控、你愿意持续 review。硬上 Loop 很可能 token 烧得更贵、错误更多。他认为真正值得学的不是 “循环” 这两个字，而是开始用长期运行的执行系统去思考。

需要说明的是，这些是作者对行业概念的梳理和判断，属于方法论层面的个人总结，不是有统一标准的官方定义。视频结尾预告下一条讲 Loop 和 Harness 怎么区分，这也是这套框架里最容易混淆的一处。
