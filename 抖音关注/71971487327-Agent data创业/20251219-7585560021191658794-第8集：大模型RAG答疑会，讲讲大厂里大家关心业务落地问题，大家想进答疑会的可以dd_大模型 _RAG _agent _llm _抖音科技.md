这段视频是「AIstudio 大模型社区」的大模型 RAG 答疑会片段，主题是多语言 RAG 系统怎么搭、文档图表怎么解析。作者给出的核心经验很直接：多语言 RAG 里，不管用户用什么语言提问，第一步先翻译成英语，让模型内部的数据流全程走英语，最后再把答案翻回用户的语言。

为什么先翻成英语 作者的理由是：大语言模型是整套系统的引擎，而同一个模型在不同语言上的能力并不一样。他举例说，同一道数学题，用英语解通常比用中文解更好；只有千问是例外 —— 中文做阅读理解这类任务表现不错，但做数学仍不如英语。所以如果底层用的是 ChatGPT 这类模型，中间数据流直接用英语就行；如果用千问，就得先看任务类型，再决定中间用中文还是英语，相关研究可以查论文。

另一个坑：别让原始语言在链路里流动 作者强调，输入统一之后，不要让印尼语之类的原文继续在模型架构里流转，否则性能会 “对半折”。也就是说，翻译不只是为了提问，检索、拼接、生成这些环节的中间文本也要统一成同一种语言。

文档解析：从 Docling 到 Infinity Parser 有观众问，PDF、Word 里 “图中有表” 的文档，用 Docling 解析出来效果一般，有没有更好的办法。作者推荐了近期开源的 Infinity Parser：它能把扫描版 PDF 直接解析成 Markdown，表格也变成 Markdown 表格，大模型读起来没有障碍；一个 7B 模型部署一下就能扫文档。

需要说明的是，以上都是作者在答疑中的个人经验和推荐，属于实践建议，不是经过统一评测的定论；具体效果还跟模型版本、语种和文档质量有关。

作者用一句话给出方案：进来先翻成英语，内部数据流全用英语，最后一步再翻回用户语言。

同一道数学题英语解得更好；千问中文做阅读理解不错，但数学仍不如英语，所以选中间语言要看任务范式。

输入统一后，不要让印尼语等原文继续在架构里流转，否则性能会大幅下降。

把扫描 PDF 直接转成 Markdown，表格也保留为 Markdown 表格，7B 模型部署即可使用。
