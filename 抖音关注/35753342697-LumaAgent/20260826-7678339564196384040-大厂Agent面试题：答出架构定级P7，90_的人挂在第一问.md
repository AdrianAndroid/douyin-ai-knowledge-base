这条视频是 LumaAgent 发布的一道大厂 AI 大模型面试真题讲解：设计一个能在电商售后场景中自主处理退款、物流查询、比价、优惠券核对的 Agent，并说清完整架构。作者的核心观点是：面试官想看的不是 “会不会调 GPT 的 API”，而是你有没有把大模型从聊天机器人做成能干活、能决策、能兜底的智能体系统的工程能力。

作者按六个得分点拆解了答题框架：

任务分解与规划：先引入 planner，把 “鞋小了想退款、顺便看大一号、再对比其他平台价格” 拆成查订单、确认退款期、生成退款申请、查库存、比价、汇总回复等子任务；加分点是提到任务依赖图 DAG—— 查库存和比价可并行，查订单和退款必须串行。
工具调用与接口设计：大模型本身操作不了外部系统，要定义标准工具接口，如 refund_tool(order_id, reason)、logistics_tool(tracking_num)、price_compare_tool(product_id)；用 function calling 或 JSON Schema 约束输出，避免自由生成文本导致幻觉和系统崩溃。
记忆系统：短期记忆存当前会话上下文和已完成步骤，长期记忆存历史订单、尺码偏好、退货记录，通常用向量数据库检索。比如记得用户买过这双鞋的尺码偏好，Agent 就能主动推荐换货而不是退款。
执行与反思（ReAct 模式）：按 “思考→行动→观察→再思考” 循环。退款工具返回 “订单已过退款期” 时，不能直接告诉用户失败，而要重新规划：检查是否在换货期，或转人工客服；同时设计失败重试、降级策略、人工兜底等错误恢复机制。
多 Agent 协作：任务更复杂时，用主控 Agent 调度售后、物流、价格等专家 Agent，通过消息传递或黑板模式共享信息。
安全、成本与可观测性：退款金额超过 500 元转人工审核，删除订单数据需二次确认，敏感操作记日志便于审计；简单任务用小模型、复杂任务用大模型做模型路由；每个决策和工具调用耗时都要有日志监控。

结尾作者总结：核心不是背架构图，而是把模糊业务需求拆成可执行、可观测、可兜底的系统，并留下一句 “大模型是大脑，Agent 是身体，只会调 API 只有大脑没有手”。
