五条要点

权限最小化：MCP Server 只提供 Agent 完成任务必需的 Tools 和 Resources，绝不开放 blanket permission（全权许可），作者称这是 “安全基石”。
工具设计清晰化：每个 Tool 单一职责，名称和描述要明确。作者给的对照例子是 read_file-读取指定路径的文件内容 优于 handle_file-操作文件，因为模糊说明会导致模型误用。
安全绝对优先：MCP 放大模型能力的同时也放大风险。不要运行未经审计的第三方 Server；对工具输入严格校验清理，防提示注入；高危操作（如 Shell）放进沙盒或容器。
提示词引导交互：系统提示词要重新设计，写清 Agent 角色、可用工具及使用场景（如 “若需查询数据，可调用 query_database 工具”），并写明安全准则（如 “执行删除前需用户确认”）。
全面测试与迭代：Agent 行为难以完全预测，需大量测试；通过查看 MCP 通信日志、分析模型的 “思考” 链，反过来优化工具定义和提示词。

一个关键背景：MCP（Model Context Protocol）是让模型以标准化方式调用外部工具和数据的协议，相当于给 Agent 接上 “插座”。也正因为工具是外部接入的，第 1、3 条才格外重要 —— 权限和输入校验的边界不在模型里，而在 Server 那一侧。
