数字游牧人 Samuel 用 1.5 小时，借助 TRAE 的 SOLO 模式从零做出一个带前后端和数据库的 AI 换装应用，并借此演示 SOLO 的完整工作流程。他提到，同类换装应用每月订阅收入约 10 万美元；这个数字是他引用的背景，并非他的实际收入。

演示主线（SOLO Builder）

打开 TRAE 选 SOLO 模式后，界面不是传统 IDE 布局，而是分成三栏：多任务对话流、工具面板、代码编辑器；代码编辑器只是工具面板里的一个子窗口，AI 被放在更高优先级。
支持同时创建多个任务并行执行，比如一个写测试、一个更新文档、一个修 bug、一个开发新功能。
输入简短需求后，AI 先写技术文档和需求文档（含架构、数据库设计），等人工确认，再列 todo list 逐步实现；生成过程中可开 “实时跟随”，看它在编辑器、文档、终端、浏览器之间跳转。
写完会自己运行，报错自己修，全部完成后有提示音和弹窗通知；另有页面汇总所有代码改动，方便审阅。
第一轮只做出 UI，数据是假的。接着让它接后端和数据库，它提示连接 Supabase，并通过内置的第三方工具集成完成注册登录、数据存储、部署、AI 服务调用和订阅付款，项目才真正跑通。

SOLO Coder 的三个卖点

先调研再动手：勾选 plan mode 后，它会调用子 agent 调研已有代码，先给方案、人工确认后再改，避免方向性错误浪费时间和 token。
主 agent + 子 agent 分工：解决 “一个 agent 挂太多 MCP 就变笨” 的问题，可一句话创建专查技术文档的子 agent 并配专属 MCP，各自在独立环境工作，减少上下文污染。
上下文压缩：显示已用上下文量，必要时自动压缩、去冗余，省 token 也让 AI 聚焦重点。

作者的核心判断是：SOLO 把 “写文档→定计划→开发→跑通前后端” 这套规范流程内置了，相当于自带最佳实践，不懂 Prompt engineering、context engineering 也能用；相比 Claude Code 这类 CLI 工具只能在命令窗口上下翻找，SOLO 的 UI 让人更容易知道 AI 在做什么、卡在哪、何时完成。他也提到 SOLO 正式版已发布、不再需要邀请码（此前有人二手卖几百元），11 月 12—15 日可免费使用，并预告本月在苏州办一场半天出作品的 SOLO 黑客松。
