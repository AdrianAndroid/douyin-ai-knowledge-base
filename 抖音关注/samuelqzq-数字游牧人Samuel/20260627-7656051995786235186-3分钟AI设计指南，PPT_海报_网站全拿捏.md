数字游牧人 Samuel 这条视频是在演示：用 TRAE WORK 的 Design 模式，把网上的高级设计审美 “搬” 到自己的 PPT、海报和软件界面里，核心卖点是 “需求→设计→开发” 在一个工具里跑完。

他讲的流程分三步

WORK 模式写需求：他举的例子是做一个 “AI 监控我工作” 的软件 —— 实时看屏幕，一分心就用弹幕喷他。让 AI 把一句话需求扩成详细 PRD。
DESIGN 模式做设计：把 PRD 加一张随手找的 UI 参考图丢进去，AI 先理解需求、规划页面结构，再从参考图提取视觉风格，一次生成多个页面的多个模块。他强调产出不是图片，而是可直接交互的原型，能选中组件改颜色、字号、拖位置，也能用自然语言让 AI 改某一块。
Code 模式开发：设计完直接跳 Code 模式写代码，省掉 “设计师交稿→程序员实现” 的断层。

他重点讲的设计系统：内置几套风格（TRAE 自己的黑绿风、Claude 风等），每套都带配色、字体组件和常用页面结构，相当于给 AI 一份详细设计规范，保证风格统一。不想用预设，可以自然语言描述或上传 Figma 文件，让 AI 提取颜色、组件、排版，变成自己的设计系统，后续新页面沿用同一套视觉语言。他现场用两套风格各做了一版 PPT / 海报，标题、正文、色块、图示、卡片、分隔线都统一，图示也按风格重绘。

他的观点：以前设计是专业活，要设计师加 Figma，还容易和代码实现有落差；现在 AI 够强，拼的是执行和反馈的速度—— 今天有想法，让 AI 展开需求、生成界面海报，第二天就能给客户看，有问题马上改。这是他基于自己团队经验的判断，不是行业定论。

评论区高赞 “你竟然尝试教会我” 是玩梗，不是差评；实际讨论集中在 Traework 国际版 / 中文版怎么选、内置模型、能不能替代 Trae IDE、会员收费，以及不少人担心这类工具看着高级、自己学不会。

想先搞清哪块？比如 Design 模式里 “参考图提取风格” 和 “上传 Figma 建自己的设计系统” 这两条路，实际用起来差别挺大。
