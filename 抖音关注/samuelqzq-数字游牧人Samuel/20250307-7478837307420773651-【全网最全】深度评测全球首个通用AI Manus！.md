全网最深度 Manus 评测：三个案例拆开看，它到底有多 “神”

博主「数字游牧人 Samuel」用三个案例拆解了当时爆火的国产 AI 产品 Manus，结论是：它把已有的能力拼装得不错，但离 “AGI 更近一步” 还差得远。

案例一：写 “容器与虚拟机发展传记小说”

Manus 先通过命令行创建文件夹，再自己列一份 todo 清单，然后循环执行 “搜索→打开网页→爬取信息→打勾”，最后分章节撰写、拼接成长文。作者指出：长文不是模型一次写完的，而是多次输出拼接的结果；浏览器操作只是打开页面、下滑，遇到需要登录的网站就读不到内容。他判断 Manus 没有自训浏览器 agent，只是把 AI 搜索、浏览器操作、文件读写这些现成能力装进了一个好看的界面。

案例二：跨平台比价（小米眼镜）

淘宝页面直接打不开，连人机验证都没过；小米官网倒是成功打开并记下价格；后面遇到报错，干脆只读搜索结果标题里的价格。作者评价这个任务 “执行得非常粗糙，几乎不能用”。他补充了一组对比数据：OpenAI 的浏览器 agent 在该数据集上完成率 58.1%，人类平均 78.2%，说明浏览器操作本身仍是行业短板。

案例三：英伟达 Excel 估值建模

Manus 改用 Python 脚本调雅虎 Finance API 取数，报错后自己改代码重跑。但关键问题出现了：财务数据那段代码里写着 “模拟数据”，数据是直接硬编码进脚本的，并没有真的调 API。作者核对后发现真假参半，AMD 的 PE 28.5 就是错的。他提醒：LLM 加脚本、上下文又长、步骤又多，一步错步步错，涉及数字的任务出错概率极大。同类问题在房贷 LPR 案例里又出现了一次。

案例四：一句话生成 “谷歌 CEO 模拟器” 网页游戏

Manus 用 Next.js 搭了全栈项目，改代码、跑起来、用浏览器自测，点按钮报错后也读到了报错信息，但修不好就放弃，还写了一份 “测试报告”。最后用户让它部署，它折腾半天才发现自己只能部署纯静态页面，前后端项目根本部署不了 —— 写代码、测试、部署全白做。

作者的判断
能力来源：不是新算法，而是把 AI 搜索、浏览器 agent、代码执行、文件操作等模块串成工作流，再用可视化界面呈现；命令行窗口故意暴露给用户看，是很聪明的产品设计。
强项：语文表达和写代码都不错。
弱项：浏览器操作粗糙、数据类任务幻觉严重、长链条任务容错差。
对 AGI 的态度：不认为这是质变，更像工程整合的胜利。

评论区的主流声音也偏冷静：不少人认为它本质是 “API + 工作流 + 好看 UI” 的封装，加上当时仍处内测、直播演示常报错，“噱头大于可用性” 是高频共识；也有观众用 “过几天大家都知道自己遇到 AI 诈骗了” 调侃过度营销。
