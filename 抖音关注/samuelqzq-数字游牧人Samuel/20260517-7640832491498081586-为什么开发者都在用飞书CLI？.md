这条视频是博主「数字游牧人 Samuel」对 飞书 CLI 的一次观察式解读：他先用自己的 HR Agent 做引子，再对比各家办公套件 CLI 的开源数据，最后判断飞书 CLI 可能成为未来 AI Agent 的默认基建。

开场的故事：一个没有人类 HR 的招聘 博主用第一人称演了一段 “投简历” 的经历：刷到月薪 3 万的招聘帖投了简历，对面不是人类 HR，而是一个 AI—— 它在飞书多维表格里给简历打分，发邮件约面试，还发来飞书会议链接，进去后 “面试官” 就是博主本人。他说明这是自己做的 HR Agent，两周处理了 56 封简历、约了 10 多场面试，做法是 “大模型 + 飞书 CLI”。

核心观点：CLI Everything 作者认为，这一波 “CLI Everything” 浪潮的本质是让软件对 Agent 友好。他提到 2026 年 3 月（他说是 “一个多月前”）Google Workspace、飞书、钉钉、企业微信都开源了各自的 CLI，并用 GitHub star 数当作 “开发者用脚投票” 的指标：飞书 CLI 刚突破 1 万 star，而 Jira、Slack、Linear 等明星产品的 CLI 都远低于这个数。npm 下载量上，他称飞书 CLI 反超 Google Workspace CLI 一倍。

他给的原因：社区活跃度 作者把 Google Workspace CLI 用量下滑归因于社区不活跃：它不是 Google 官方项目、依赖单一维护者、一个半月没有 PR 被合并、社区贡献因无人 review 被忽略。对比之下飞书 CLI 的 issue 和 PR 更多，外部贡献者也不少 —— 他举例一位河南科技大学的学生把贡献写进个人主页，还有一位土耳其的纳斯达克上市公司工程团队负责人。

开发者拿它做什么 他引用 AI coding 创业公司 Verdent 团队的文章观点：现在 Agent 能写代码、跑测试、提 PR，但之后更新任务状态、改文档、通知同事还得人工去办公软件里做，Agent 与办公环境的割裂成了工作流 AI 化的瓶颈，而 CLI 正好补上这一段。他还提到完全跑在飞书里的 Agent 产品 Pokoclaw，每个 subAgent 是一个单独的飞书群聊。

需要留意的两点 一是 star 数、下载量、时间点这些都是作者自述和画面里的图表，属于他的调研口径，不是官方统计；二是 “默认基建” 是他的判断和期待，不是已发生的事实。评论区则跑向了另一个方向：不少人感叹 “再也不敢投简历了”“HR 又迎来一波失业潮”，这些是反讽式焦虑表达；也有高赞观点认为 AI 没有欲望、不会取代人类。“万物可 CLI” 是评论里高频的技术口号，作者回复 “没毛病” 表示认可。
