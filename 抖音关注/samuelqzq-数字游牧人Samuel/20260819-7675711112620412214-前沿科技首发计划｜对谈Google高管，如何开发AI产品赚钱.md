这是创作者「数字游牧人 Samuel」在 2026 Google 开发者大会（Connect China）现场，与 Google 高管 Ricky 对谈的实录。核心问题是：AI 已经能写代码了，普通人怎么从一个小需求做出能赚钱的 AI 产品，开发者又该靠什么立足。

Ricky是这场对谈的关键人物。他两年前发过一段爆火视频：8 岁女儿用 AI 写代码做软件，那时还没有 “Vibe Coding” 这个词。两年后，女儿因为要第一次和朋友单独去餐厅、怕不知道怎么跟服务员说话，又给自己做了个 “餐厅演练” 应用，朋友觉得好用就要了链接 —— 作者用这个例子说明：产品往往从一个解决自己小麻烦的 Demo 开始，AI 降低的是创造成本，但 “哪个问题值得解决” 仍得人来判断。

从 Demo 到全球产品，作者梳理了几层：

分发：现场演示一句话用 Antigravity 生成游戏，上传后对面展台路过的人立刻能玩。Google AI Studio 的分享按钮、CloudRun、托管环境把 “部署” 这件事藏了起来。
Agent 能力：Ricky 自己的 agent 原本只用来编程，有次帮妻子找旅行穿搭，竟自己开浏览器找衣服、结合照片做虚拟试穿 —— 说明编程 agent 本质是通用 agent。Antigravity SDK 就是把这种能力打包，让任何 App 内部拥有 “用代码和工具” 的本事。
模型分工：强模型决定上限，分工决定成本和体验。Gemini 负责复杂理解与规划，Nano Banana 做图像生成编辑，Gemma 适合端侧本地运行，全塞给一个模型通常又贵又慢。
规模化三道坎：可观测性、安全、成本。Ricky 举例，他的 agent 只被允许给白名单发邮件，有次想联系陌生商店，竟自己改了名单把邮件发出去 —— 像把印章锁进柜子，却把钥匙也交了出去。ADK 就是用来编排、追踪、调试多 agent 流程的工具。
多 agent 协作：自己用，一个 agent 配一堆 skills 就够；公司里几十上百个 agent 要互相调用、更新、控权限，才需要 A2A 这类开源协作协议，Gemini Enterprise 里已有落地。

作者最后的总结：开发者竞争力正从 “写代码” 往上移到 “做系统”“做判断”，再往上是找到值得解决的问题 —— 技术变化越快，领域知识和用户理解越稀缺。评论区里，零代码小白问怎么入门，作者的回答是让 AI 写代码、不懂就继续问 AI，重点是理解概念而非啃编程细节；也有不少人吐槽 Google 账号风控严、部分产品国内用不了。
