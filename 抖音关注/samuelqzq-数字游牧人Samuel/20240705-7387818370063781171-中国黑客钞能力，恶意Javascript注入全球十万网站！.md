视频讲的是 “polyfill.io 供应链投毒” 事件：一个中国公司买下了开源项目 polyfill.io 的域名和 GitHub 账号，而这个脚本被全球大量网站通过 CDN 动态引用，等于拿到了向这些网站下发任意 JavaScript 的权限。作者用 “钞能力” 调侃这次收购，重点不在攻击技术本身，而在开源依赖的信任链条有多脆弱。

事件主线（按视频叙述）

起因：约 2024 年 2 月，一家中国公司买下 polyfill.io 的域名和 GitHub 账号。视频称全球超十万网站依赖它，页面打开时会去该域名下载并执行代码。
过程：早在植入恶意代码前，就有人在 GitHub 仓库留言质疑 “项目被卖了，别用了”，但这类质疑被刷屏、删除。作者评价 “真他喵的专业”。
结果：Google Ads 屏蔽了受影响网站，GitHub 也在仓库加上 “本仓库可能包含造成损害的恶意内容” 的警告。实际破坏被作者描述为 “不算太大”—— 点击广告时有 20%~30% 概率跳转到赌球网站。

作者提出的两个 “细思极恐”

一行 <script> 就是攻击面。画面里高亮的那行 cdn.polyfill.io 引用，是无数前端项目的常规写法：不打包进自己的代码，而是运行时从第三方 CDN 拉 JS 执行。CDN 或域名易主，下游所有网站一起中招，这就是供应链攻击。
开源维护者的处境是漏洞的温床。一个前端项目动辄依赖几十上百个第三方库，很多小项目作者辛苦几年 “赚不到一毛钱”，而收购报价据说是 “小几十万” 级别，很难不动心。

需要分清的一点：视频里 “十万网站”“二三十概率跳转”“小几十万报价” 都是作者口述，属于他的说法而非核实数据；而 GitHub 警告、Google 广告拦截是公开可查的事实。另外 “polyfill” 本身是给旧浏览器补新特性的兼容脚本，正因为几乎所有网站都需要它，才成了高价值目标 —— 这也是这类攻击难防的根本原因：不是代码写错了，而是信任被卖了。
