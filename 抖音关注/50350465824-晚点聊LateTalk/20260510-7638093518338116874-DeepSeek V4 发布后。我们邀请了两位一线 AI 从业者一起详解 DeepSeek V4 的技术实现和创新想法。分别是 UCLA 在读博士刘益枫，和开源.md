这是「晚点聊 LateTalk」的一期硬核技术播客，主播程曼祺邀请 UCLA 计算机博士生刘益枫（模型架构方向）和 SGLang 核心开发者、RadixArk 工程师赵晨阳（推理方向），逐章拆解 DeepSeek V4 技术报告。核心结论是：V4 不是新范式，它延续 R1 的 “测试时扩展” 路线，靠一堆组合创新和工程优化，把百万上下文从理论推到实用。

四个同时上线的新东西

注意力机制：放弃 V3 的 MLA，改用滑动窗口 + 长距注意力的混合稀疏方案（CSA 做 4:1 序列压缩再 top-k 选取，HCA 做 128:1 压缩保持稠密），每层预定义走哪条路。稀疏层锁定关键 token，稠密层提供语义概览。
优化器：从 AdamW 换成 Muon，把更新从逐元素提升到矩阵层面；DeepSeek 把 Kimi Moonlight 的 0.2 系数进一步调到 0.18，全模型一个默认值即可。
MHC 残差：在 Hyper-Connections 基础上加 Sinkhorn 归一化，把层间信息通道从 d 拓宽到 c×d，同时约束梯度尺度，解决原方案训练不稳的问题。
推理侧：用 TileLang 写 kernel（比 CUDA 门槛低、比 Triton 更底层），并把 FP4 训练做到生产级 —— 训练阶段伪量化、采样阶段真实量化，发布的 checkpoint 就是 FP4。

效率与代价：V4 推理 FLOPs 只有 V3.2 的 27%，KV cache 仅 10%；但两位都强调这优势只在长上下文才显著，几千 token 的短输入几乎看不出差别。另一面是用户反馈解决同一问题的 token 消耗反而变多，赵晨阳形容为 “拿着高压水枪浇花”，综合效率提升没那么夸张。激活比例压到约 3%（1.6T 总参数、约 49B 激活），是同期模型里最低的。

几处值得注意的判断：报告没再公布训练成本，刘益枫认为这是 “不再靠成本优势定义自己” 的信号；V4 没做多模态，是专注文本 + 国产芯片适配的取舍；报告里国产芯片只在推理并行方案处提到 “在华为昇腾上做了技术验证”，训练是否使用并无披露，外界猜测居多。评测上 V4 在 Arena 约排 23 位，落后于同期部分国产模型，但报告坦诚公布了内部工程师的采用意愿数据。
